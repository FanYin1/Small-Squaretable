## 本次开发后的实际效果

1. 管理员可以把一段已保存的新版故事迁到另一套同结构数据库和指定账户，继续原来的身份、处境、约定及表达偏好。恢复包含实际原文、状态、来源、记忆向量和本地附件，不由模型重新编造。
2. 04D的待确认行动与私下交谈一起迁移。候选仍待确认；私聊的听众重新映射到目标人物，私聊摘要和记忆仍不进入其他人物或公开生成。
3. 未完成的记忆批次和失败后的提取检查点可以接着处理。已完成的生成/创建请求回执保留，迁移不会把旧请求当成第一次执行，也不复制账户余额或支付账本。
4. 删除与生成提交、记忆提取/嵌入/保存同时发生时，统一先锁故事再锁子记录；已删除故事的迟到结果不能重新写回，其他故事保留。
5. 除原有可信源库重放外，恢复旧备份可使用独立保存的私密删除快照。恢复前核对摘要与现有凭据，恢复后重放删除，失败时保持目标离线。

## 迁移包及边界

格式为 `small-squaretable.admin-story`、版本1；入口为 `scripts/story-transfer.mjs`。这是管理员离线维护能力，工具随工作区交付，需安装项目开发依赖并通过`tsx`加载协议类型；不在普通用户接口接收完整包，也不把工具所在工作区冒充容器内运维环境。

| 数据 | 处理 |
|---|---|
| 身份、角色与世界书 | 保存冻结快照；身份名称/描述保留，所有者明确映射。人物新建为目标账户私有草稿，不重新发布。来源人设ID作为历史出处保留，当前可变人设关联解除；世界书使用此存档快照，不自动复制作者整个资料库 |
| 正文、事件、状态、笔记 | 全量读取同一个可重复读快照；保留中断/候选/已确认状态、原文来源和资源依据。故事ID保留，内部人物/消息/事件/任务ID重建，关联一起改写 |
| 记忆、向量、进度、任务、摘要 | 校验完整五轮来源、向量维度、状态和原提取摘要；映射后重新计算来源指纹。不会重新提取已经保存的检查点，不把候选入确认批次 |
| 知情与来源 | 原文及回复听众必须一致；重映射所有显式人物权限、分类信息、批次来源及记忆链接。公开生成保守排除私聊的既有边界不变 |
| 请求和辅助记录 | 保留终态生成/创建回执、故事覆盖配置、自己的书签/回应和故事内情绪来源；拒绝仍在运行的生成或记忆租约。新版故事出现旧变量数据时拒绝自动迁移 |
| 附件 | 打包冻结材料、正文和附件字段引用的本地`/uploads/`文件，核对SHA-256，写到目标租户的新目录，重写相应引用。拒绝缺失文件、路径穿越和符号链接；单包最大100 MiB、本地附件合计64 MiB、最多1000份 |
| 不迁移的站点数据 | 登录凭据、用户全局资料、积分/支付账本、第三方用户的回应、既有公开分享快照及分享令牌不迁入。外部URL和内嵌数据保持原引用/内容，不联网抓取远端资源；不是整站镜像 |

旧版无冻结快照的聊天继续使用整库恢复，工具明确拒绝自动升级。单故事导入要求源/目标具有相同已支持的表结构；遇到新增而协议未处理的故事依赖表会失败，不能静默丢表。不可用的旧资源、未保存过的上下文或迁移前不存在的删除凭据均不能补造。

## 操作顺序

以下命令中的UUID和路径均为占位符。连接串仅通过服务器环境提供，不复制到聊天或文档。先保存源库、附件和当前目标的完整备份；停止源写入，排空生成与记忆任务；目标必须离线。

1. 为源设置 `STORY_TRANSFER_DATABASE_URL` 和 `STORY_TRANSFER_UPLOAD_ROOT`，由有权读取完整作者材料的管理员导出：

   ```bash
   npm run transfer:story -- export /secure/story.json USER_UUID TENANT_UUID CHAT_UUID
   ```

2. 设置 `STORY_DELETION_SOURCE_DATABASE_URL`，在故事导出之后保存最新删除快照，单独记录命令返回的摘要，并将文件保存到独立可信介质：

   ```bash
   npm run snapshot:story-deletions -- export /secure/deletions.json
   ```

3. 把 `STORY_TRANSFER_DATABASE_URL` 切到离线目标库，`STORY_TRANSFER_UPLOAD_ROOT` 指向目标应用存储；目标账户/租户必须已存在。以应用存储目录的所有者执行，保证600/700权限的附件可由应用读取。把独立记录的快照摘要放入 `STORY_TRANSFER_DELETION_SHA256`，生成只读计划：

   ```bash
   npm run transfer:story -- plan /secure/story.json TARGET_USER_UUID TARGET_TENANT_UUID /secure/deletions.json
   ```

4. 核对目标账户、故事ID、行数、附件数、来源指纹和删除快照时间，用返回的 `planDigest` 应用：

   ```bash
   npm run transfer:story -- apply /secure/story.json TARGET_USER_UUID TARGET_TENANT_UUID /secure/deletions.json PLAN_DIGEST
   ```

5. 在目标核对原文、状态、私聊范围、附件、摘要来源及一轮继续操作，再开放服务。导入不会自动删除源；切换前须明确唯一继续写入的位置，不把迁移当作创建故事分支。

计划期间也需要维护锁；活动读写会让工具拒绝执行。目标已有相同故事ID（包括已删除ID）时拒绝覆盖，不用重新分配故事ID绕过删除。变更包、账户、来源或删除快照会改变计划摘要，必须重新核对。

数据库操作在同一事务里完成。导入既有事件时仅暂时关闭该事务中受排他锁保护的`story_memory_enqueue`触发器，恢复保存的任务/进度后立即重新启用；外键及其他保护保留，失败回滚触发器状态与所有新记录。附件先以独占文件写入并同步文件/目录，再提交数据库；失败删除本次新附件目录。进程在提交前被强制终止可能留下无数据库引用的附件目录，需离线复核后清理，不能当作已完成导入。普通玩家阅读导出继续使用原JSON/TXT/Markdown格式，`restorable: false`不变。

## 无源库时的旧备份删除约束

`scripts/restore-db.sh`支持两种互斥来源：现有 `STORY_DELETION_SOURCE_DATABASE_URL`，或 `STORY_DELETION_JOURNAL` 加 `STORY_DELETION_JOURNAL_SHA256`。后者必须是管理员独立确认的最新可信快照；不能从待恢复的旧备份里取一份旧删除列表当作“最新”。

快照使用独占600权限文件，校验格式、内容摘要和来源库标识；文件及目录同步后才报告成功。摘要证明内容未变，不证明提供者可信或时间最新。目标若已包含快照没有记录的删除，前置检查拒绝覆盖；重放期间来源不符、归属冲突、凭据缺失或目标正被访问都会失败。SQL和custom两条恢复路径均执行前置检查→恢复→重放，失败不报告恢复完成；PITR仍需在恢复后手工执行同等检查。

```bash
npm run snapshot:story-deletions -- replay /secure/deletions.json TRUSTED_SHA256
```

独立快照明确覆盖到`capturedAt`，不是实时灾备订阅。源库和最新删除证据都丢失、只有较早快照时，无法判断之后发生的删除，必须保持恢复目标离线、先核对更晚的可信记录；不得承诺零丢失或无条件开放旧备份。迁移前删除且无凭据的历史不自动修复，管理员绕开工具直接启动旧库也不在保护保证内。
