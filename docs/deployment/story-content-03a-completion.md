日期：2026-10-25 19:11（香港时间）。原要求逐项核对见[工作包](../product/story-content-03a-closure.md)。EXP-03A工程收尾完成，3081已部署并复验；全产品及人工签收仍保持各自状态。

## 实际变化

| 用户操作 | 此前问题 | 当前实现 |
| --- | --- | --- |
| 新建或编辑世界书条目 | 有用途诊断但无作者维护入口 | 可声明背景与人物、知识、规则、风格；未声明不猜测，未识别的原声明可保留或主动更改 |
| 新建常驻条目 | 页面允许无关键词，API拒绝；新建API丢弃settings | 可无关键词保存常驻条目；触发设置及用途完整落库 |
| 修改注入位置和排序 | 把排序列当注入位置，字符串逻辑与数字选项不一致 | 位置保存在settings.position，排序保存在position列；数字旧逻辑仅在编辑时规范为相同含义的枚举 |
| 导出并重新导入 | 用途、角色、递归及部分位置丢失或错位 | 已支持字段共用映射，独立导入与追加导入保持一致；追加导入先校验全部条目并事务写入 |
| 作者同时修改卡与书、玩家开局 | 多次SELECT可能捕获旧书加新卡 | 同一SQL读取卡、明确绑定书及条目；冻结诊断与正文共同使用这份结果，幂等请求事务不变 |
| 已开始的故事与另开故事 | 已有冻结机制，本轮需证明用途也遵守 | 旧故事保留原用途与内容；另开读取新版本；不自动回填旧故事 |
| 通过其他API维护绑定 | 新建书可传入其他作者角色；改scope可绕开绑定流程 | 创建时校验角色归属和租户；已绑定书必须先显式解绑再改范围 |

用途是作者对资料的说明，不是模型语义裁决器，不会自动识别全部设定冲突或提高条目执行权限。人物补充归入“背景与人物设定”，不把每本资料当完整世界。玩家无需增加选世界步骤；未声明、缺失、停用、空书和重名依赖沿用显式诊断，不从全库猜配。

## 工程边界

- 不增加迁移，仍为beta0011/累计12项。单条读取快照保证同一数据库时点的一致视图；作者分多次提交的修改仍以当时已提交状态为准，不伪造“整份作品发布事务”。
- 创建请求继续使用原READ COMMITTED事务和唯一幂等键，不通过切换隔离级别破坏并发重试。
- 导出保证本项目已支持的上述条目字段，不承诺任意第三方扩展、脚本或原文件逐字节归档；角色导入原对象存储保持既有03B边界。
- 冻结阵容的故事仍拒绝中途增减角色。动态扩容不是本轮新增能力，后续若支持须定义身份、知情及新增资料版本的行为。
- 本轮不改纠正、回退与分支决定；原生状态、行动、记忆和完整产品验收按各自工作包跟进。
