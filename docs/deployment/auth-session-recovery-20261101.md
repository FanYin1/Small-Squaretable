# 登录令牌失效与自动续期修复

2026-11-01。用户反馈 `Invalid authentication token`；对应 INV-05/08，仍归既有体验验收缺陷。本次处理平台登录认证。

## 原因与行为

- 服务端 HTTP 认证中间件和 WebSocket 认证都会返回该文本；远程应用最近三小时日志汇总发现两条同名认证错误。日志没有足够上下文确定用户具体哪一次操作失败，不能据此归因到供应商密钥。
- 后端 `/auth/refresh` 返回 `data.accessToken` / `data.refreshToken`，旧前端读取了不存在的 `data.tokens`。此外，旧 HTTP 拦截器即便续期成功也不重试原请求；并发 HTTP 与 WebSocket 续期可能竞争轮换令牌。
- HTTP、用户 store 和 WebSocket 共用一次正在进行的续期，同时更新两个令牌并同步前端登录状态。明确被平台认证拒绝的普通 JSON 请求至多重试一次，重新取得与新凭据绑定的 CSRF，保留原请求体。
- 续期失败时结算全部等待请求；仅明确的登录失效清除对应会话，保留当前页面及未保存表单。临时网络故障保留凭据，账户切换时不把旧结果写入新账户。
- 网络失败、供应商模型错误和聊天生成不自动重发。WebSocket 的瞬时传输错误由关闭/重连流程处理，避免在成功续期后仍显示旧的通用连接错误。

## 验证

- 六个定向文件共 66 项测试通过，覆盖续期响应契约、HTTP/聊天共享轮换、原请求重试、CSRF、账户切换、失败等待结算及用户状态同步。完整类型检查、客户端构建及补丁检查通过。
- 首次回归一项旧 CSRF 测试未提供新增自动重试所需响应而失败；更新其预期及响应序列后，六文件完整重跑通过。原始失败日志 `/tmp/auth-session-tests.log` 和最终日志 `/tmp/auth-session-tests-final.log` 均保留。
- `scripts/auth-session-check.mjs` 在 1440/390 两尺寸分别验证续期成功后保存和续期失效后表单保留，共四组浏览器旅程，无页面错误。成功路径只续期一次、保存两次，第二次使用新认证及新 CSRF，两个请求体一致；失败路径只发出一次被拒绝的保存，不离开当前表单。
- 本地证据：`backups/exploration/auth-session-20261101/local/`。浏览器使用隔离认证与接口响应，不写生产模型配置、不调用供应商；不冒充用户现有会话或真实供应商验收。

## 使用与边界

旧标签页需刷新加载修复；刷新前可先复制尚未保存的配置。若旧刷新令牌已经过期或被其他登录替代，需要重新登录一次，修复不能恢复失效凭据。

本轮修复普通 JSON API 和既有 WebSocket 续期链路。独立上传/下载封装、多标签页间轮换协调，以及供应商真实生成权限没有纳入本轮通过声明。
