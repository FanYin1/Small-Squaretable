# 自定义模型容量与剧情输出限额

对应AD-5-CAP、DEC-07/08。用户提供当前别名`gemini-3.8-flash`的1M上下文与64K最大输出；暂按十进制1,000,000与64,000配置，来源为用户说明，不是已验证的供应商极限。短程真实调用不能证明百万上下文全部可用。

在服务器环境配置中设置：

```dotenv
CUSTOM_LLM_MODEL_LIMITS='{"gemini-3.8-flash":{"contextWindow":1000000,"maxOutputTokens":64000,"requestOutputTokens":2048}}'
```

仅对`CUSTOM_LLM_MODELS`中精确匹配、且实际路由到custom供应商的模型生效；不按别名前缀猜能力，不改变其他供应商。三字段均须为正安全整数，输出能力小于总窗口，请求输出不超过能力并留出上下文缓冲；未知字段、未知模型、缺字段或损坏JSON在启动时拒绝，错误不回显配置内容。空配置保留旧注册表/4096与2048回退。

环境中maxOutputTokens表示供应商能力；返回的ModelMeta为兼容既有预算调用，maxOutputTokens仍表示实际请求上限，另以outputCapabilityTokens保存声明能力。上下文选择、点数预扣、单人/多人WebSocket使用请求上限，64K不会自动成为每轮预扣。既有文本模板固定2048策略保持。辅助提取与工程脚本的显式输出参数不因容量声明提高；这不是所有模型接口的全局输出限额。

`compose.beta.yml`传递配置，候选升级工具从`.env.beta`同步到`.env.exploration`并核对容器环境。旧镜像不认识此字段，回滚时仍恢复旧配置，不能认为仅添加环境变量就改变旧程序行为。工程网关输出的私有配置保留同一容量声明，原卡隔离游玩子进程采用；上游密钥不传给子进程。

1M是可用容量的声明，不是每次必须填满的输入，也不是工程可消费额度。固定设定、当前状态和受保护完整轮次的容量守卫保持；不删除关键记忆换取测试通过。工程批次仍由同一持久账本按实际请求保守预留和回执核销，总授权不增加。
