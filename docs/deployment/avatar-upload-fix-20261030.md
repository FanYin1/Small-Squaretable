## 原因与实际修改

个人资料页将图片 Base64 data URL 作为 `avatarUrl` 保存，服务端此前直接写入 `users.avatar_url`，而生产数据库该列为 `varchar(500)`。使用工程账户和合成的 120,492 字节 PNG 在公网复现保存返回 500 / INTERNAL_ERROR（请求号 `G8rqwkhZXLnL6xnkaeMUy`）。未取得包含底层 SQL 原因的日志；字段限制、写入路径和实际失败共同支持该定位。

服务端现在验证 PNG/JPEG/WebP 图片，按 5MiB 文件上限和 2,000 万像素输入上限解码，移除元数据并转为最大 256×256 WebP，写入持久化上传卷的 `avatars/`。数据库只保存 `/avatars/<UUID>.webp` 短地址；数据库更新失败时删除本次新文件。独立公共头像路由仅允许生成的 UUID 文件名，原有受认证保护的上传路由保持原权限。无效图片返回 400，存储失败返回明确的 503 提示。
