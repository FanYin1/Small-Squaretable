日期：2026-10-25。原要求及本轮核对表见[工作包](../product/story-memory-05a-closure.md)。最终结论：EXP-05A工程工作包完成，已部署并核验3081；完整产品体验与人工质量签收仍单列。

## 实际效果

| 场景 | 此前缺口 | 本轮行为 |
| --- | --- | --- |
| 单人故事续写 | 仅多人入口传入知情过滤参数，单人遗漏 | 单人入口显式传入；服务再依据内容快照版本强制启用，遗漏或false参数不能绕过 |
| 原文或事件元数据改变后继续 | 事实检索仅检查知情范围，摘要检查更严格 | 两者共用原文指纹、确认状态、请求号、版本及整批可见性校验；旧派生事实失效后不再注入 |
| 同一句话抽取为不同类别 | 精确去重只比较正文，可能混淆类型和引用 | 同故事/角色/类型/正文精确去重；跨批合并保留所有引用，不把相似但不同的约定覆盖掉 |
| 后续改期或改变表达偏好 | 注入记忆没有事件版本，旧标题把虚构经历写成用户资料 | 逐条带来源事件版本与原文ID，标明历史派生及优先级；保留原约定与后续调整 |
| 转换话题后继续 | 偏好完全依赖向量相似度前五名 | 额外查当前故事/角色最近20条偏好候选；复核来源后按事件版本最多保留两条，其余位置用于相关经历，总数仍最多五条 |
| 达到派生记忆容量 | 按创建时间直接淘汰，较早偏好易被清走 | 在原容量内保护最多两条近期偏好，其余按原创建顺序淘汰；原文与成功检查点不受影响 |
| 旧记忆查询或清理未指定存档 | 查询/删除范围可覆盖此角色的全部存档 | 未指定存档仅操作账户全局旧记忆；指定存档先核对账户、租户和角色归属 |
| 使用旧接口操作新故事 | 可绕过持久派生与知情展示，单条删除仅凭ID | 新故事使用既有故事记忆入口；旧列表/提取/调试返回409，旧单条删除拒绝新故事和他人记忆，不先调用模型 |

候选取回与来源复核之间如数据改变，实际注入使用复核事务内读取的正文与类型，避免取回旧正文后给它附上新来源。复核事务是只读可重复读；查询失败不假装整理成功。

## 工程方案与边界

- 不增加数据库表或迁移，继续使用 beta0011 累计12项结构。所有写入仍走原持久任务及原子提交。
- 五轮批次的确认来源、摘要和事实遵循同一校验。事实还必须与抽取检查点的类型/正文相符，声明的引用齐全，主来源仍在有效引用中。
- 旧全局语义合并和提升不会处理版本化故事。本轮不对存量记忆自动改写、重新抽取或全库回填；有问题的派生内容先排除。
- 偏好候选数20、保护/注入最多2条是本轮有界实现参数，不是用户签收的无限记忆保证；分类仍依赖抽取模型。淘汰依据创建顺序，候选选择再依据验证后的事件版本排序。
- 近期原文、冻结设定、确认状态、玩家手记和有界分批摘要继续使用现有通道。最多20批摘要候选/最多4批注入等容量边界不改变。
- 人物知情沿用04D保守规则：整批含无权信息时排除；不新增人物主动披露模拟或单卡内NPC自动分权。
- 事实纠正、重写和分支仍由EXP-06/OPEN-01决定；本轮没有新增编辑/清空派生记忆的产品语义。

## 验证口径

数据库检查覆盖跨批引用、同文不同类型、源正文/状态/版本/请求号篡改、派生正文/主来源/引用缺失、跨账号/租户/存档/角色、清理及改期；另把派生表达偏好写入备份前的源库，在恢复后的新进程复核来源及版本。来源有效性验证不等于模型生成内容的语义真实性验证。

HTTP/WebSocket/浏览器检查使用隔离库及受控模型。把有来源但无向量的偏好写入合成故事，刷新后检查实际发往模型的请求，再使来源失效，检查下一次续写排除它；同时验证旧API拒绝越权和新故事旁路操作。

首轮浏览器续写在偏好注入断言处失败，定位到单人入口未传入知情隔离标志。该失败用于修复入口及服务内的版本强制规则；不能把此前通过的纯函数/数据库检查当作单人实际入口已经通过。

真实模型连续性复用[05B的真实100+5轮记录](story-memory-05b-completion.md)，不把该历史运行说成本轮新测试。新增真实模型调用及token均为0；已知累计439,863，旧未决预留6,591，累计占用446,454/450,000，剩余3,546。
