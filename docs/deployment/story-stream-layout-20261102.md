# 流式正文宽度修正与数值呈现建议

2026-11-02，关联DEC-14、DEC-31、INV-02/06/08。用户截图反馈流式正文居中变窄，并询问卡片尾部数值的呈现方式。

## 已修改的源码

`ChatWindow.vue` 的流式容器原有独立720px上限，而工作台消息列表使用可达1440px的阅读画布。完成后的MessageBubble已适配画布，流式路径漏改，因此生成前后正文宽度、左边界不同。流式容器现改为跟随父消息列表，正文边距、边框占位和文字颜色与已保存助手消息一致；手机端同步12px外边距及8px/12px正文内边距。不改变模型输出、状态提交、推荐或数据存储。

先前流式合成浏览器验证仅断言可见文本、状态和不溢出，未比对流式与完成后的几何尺寸，漏掉了此回归。本次使用真实ChatWindow、MarkdownRenderer、store、WebSocket客户端和工作台样式，合成传输/API，在1920/1440/390宽度比对正文左边界、宽度、字号、行高及颜色，同时验证最终正文替换、三个推荐、失败替换和迟到块忽略。临时脚本与证据在 `/tmp/squaretable-stream-width/`。这是隔离组件验证，无真实用户数据和模型调用，不代表公网已修复；本次源码未部署。

## 数值呈现建议，尚未实现

上述源码最终三尺寸浏览器检查、客户端构建及补丁格式检查通过。正文几何、字号、行高和颜色一致；截图已查看。未进行远程发布或真实模型调用。

截图的`config`、`theme`、`layout`及方括号分区是卡片输出格式，不宜直接占用正文阅读区。建议采用轻量状态条与已有“此次游玩”覆盖式抽屉，保留暗幕和正文操作阻止规则，不新增常驻侧栏。

- 正文下面优先保留推荐按钮。再以一条可折叠状态摘要呈现少量关键字段，详细库存、商铺经营、固定资产和市场情报放入抽屉；历史回复保留当轮快照，最新抽屉注明来源轮次。
- 现金/库存等必须区分规则确认、开局记录与模型描述。模型描述只作为可追溯的叙述快照，不能直接覆盖作者规则状态；预计日收益不按时间自动变为到账，市价不等于可兑现资产。
- 有规则确认依据时才显示增减及交易记录；缺乏依据时不计算虚构变化。流式期间保持上一轮状态，完成保存后再更新摘要，失败不更新。
- 展示适配保留原文查看入口；完整识别已知格式后再折叠，未知或残缺格式保留可读原文，不全局删除方括号文本，也不执行卡片提供的脚本或样式。

该建议不代表太衍商途的完整经营、交易或结算规则已经适配。需要后续单独核对卡片原文和现有状态来源，再确定字段映射及规则覆盖范围。
