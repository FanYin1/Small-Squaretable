# 绑定世界书快照：实现与隔离验证

记录日期：2026-10-24（UTC+8）。本次为 EXP-03A / EXP-04A 的世界书绑定子项，关联 DEC-07、08、10、11 / INV-01、03、07、09。活动任务状态见 [待办](../product/backlog.md)。角色卡正文版本、状态事件与长期记忆仍未完成。

## 1. 实际行为

新故事保存开局时明确绑定的世界书及条目规则。后续修改或删除来源世界书，已建立故事仍使用保存的版本；同卡另开读取新版本。用户无需先选择世界，系统也不会从整个资料库猜配或追加所有全局世界书。

| 场景 | 当前行为 |
|---|---|
| 新建单角色/多角色故事 | 在创建事务内，逐角色记录绑定与条目；创建请求重放返回原档，不重新捕获 |
| 有绑定资料 | 仅选择 `characterId` 明确指向本卡、`scope = character`、处于启用状态且 `userId` 等于卡作者 `creatorId` 的世界书 |
| 没有匹配资料 | 保存明确的空绑定；后续不因全局资料增加而自动加载 |
| 修改、停用或删除来源 | 旧档继续读取保存的定义；新档读取当前绑定和启用状态 |
| 条目触发 | 使用保存的关键词、位置、概率、角色过滤与递归等字段，沿用现有引擎的扫描规则和预算；不会把所有内容每轮全部注入 |
| 阅读设置 | 显示本次故事沿用开局绑定世界书的说明；不直接展示作者隐藏条目 |
| 快照缺失、协议不支持或读取失败 | 停止该次生成，进入现有失败处理，不降级为读取当前资料或无设定生成 |
| 断线 | 已固定设定的故事等待 WS 恢复；保留未发送输入，不走无法装配快照的客户端 HTTP 生成回退 |
| 旧档 | 标记为空，不推测开局绑定、不补造历史。保留既有生成行为，不借本次修改批量激活旧档的全局世界书 |

世界书定义固定不等于剧情状态固定：宏仍可按当前玩家身份、对话与变量展开；金钱、物品、位置等发生过的事实尚未在本子项持久化。保存条目字段也不代表所有第三方扩展、脚本或变量框架均已兼容。

## 2. 数据与生成链路

- `src/types/story-worldbooks.ts` 定义协议 1，记录每张卡的绑定书名、来源 ID、条目字段、整体内容 SHA-256 与捕获时间。摘要用于识别内容版本，不是数字签名。
- `src/server/services/story-worldbooks.service.ts` 用一次联表查询读取绑定与条目，避免分别读取书和条目时混入不同编辑时刻的数据；来源作者归属按明确关联核对。
- `src/server/services/chat-creation.service.ts` 在建档事务中同时保存玩家身份、世界书版本标记、私有快照、参与角色和幂等请求。失败整体回滚。
- `chats.worldbook_snapshot_version` 只公开版本标记；完整定义放在独立 `story_worldbooks` 表，普通存档响应不展开该私有数据。读取快照按所属存档和用户核对，不按同角色复用另一存档。
- 对已固定版本的故事，单角色和群聊 WS 都向增强提示传入当前对话及版本标记；增强提示读取快照，再交给世界书引擎。明确的 `entries: []` 不触发实时资料回退。
- 快照与版本标记不能通过 SQL UPDATE 改写；缺失的快照行不会被当作旧档。删除故事通过外键级联删除该私有快照。

本次默认绑定来自目前已落库的角色关联，不解析新的作者用途语义。卡内 `character_book` 必须已经由现有导入流程转换为世界书关联；仅存在于原始 JSON 而没有落库的资料不能据此声称已绑定。卡作者为空、其他人挂在本卡上的资料、全局/人设/会话范围资料不纳入此次新档默认绑定。

## 3. 迁移与交付边界

普通迁移为 `0043_story_worldbooks.sql`，beta 迁移为 `0003_story_worldbooks.sql`，分别追加到对应迁移链。新应用启动前必须执行正确的迁移链；不能对同一库重复应用两条链。

**3080 既有 R5 候选与数据库未迁移或部署；5188 原型保持运行。** 本轮验证使用一次性 PostgreSQL/Redis。新增列可空、快照使用独立表，旧数据不被回填。回滚旧应用后，其创建路径仍可能产生无版本标记的存档，不能将镜像回滚当成数据回滚。

## 5. 尚未完成

1. 角色卡正文、开场、模板和覆盖参数的版本固定；当前卡本身仍可能随编辑变化。删除角色卡也不是本次承诺可继续生成的情形。
2. 作者明确标注背景、概念补充、规则或风格用途；缺依赖诊断和更完整的绑定配置页面。
3. 群聊开局之后新增角色的绑定扩展：当前没有该角色的开局绑定时显式失败，不临时猜配；需要另行设计受控的版本变更。
4. 玩家可见资料投影、动态状态、地图、事件来源和长期记忆；不能把快照内容直接当作玩家已知事实展示。
5. 完整导出/恢复协议、升级旧档的交互、备份恢复演练及本机候选部署；数据库备份与玩家分享继续区分权限。
6. 真实供应商叙事质量、用户视觉和手机真机验收；OPEN-01 的纠正/分支、OPEN-02 的推荐行动提交方式保持未定。
