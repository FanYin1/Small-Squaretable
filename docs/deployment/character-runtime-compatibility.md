## 用户实际得到的行为

角色详情在开始之前说明本卡采用原生状态还是普通叙事，并分别提示脚本声明、正则规则、外部变量框架线索、素材声明和未知扩展。旧版/V2/V3归一化后的资料仍保留原始对象。探测是有限的静态诊断，不能发现所有脚本依赖，也不能仅凭字段存在判断脚本已经启用。

开局后的阅读设置展示从冻结资料派生的同一组兼容诊断，不读取后来修改的源卡，也不向浏览器额外返回隐藏设定正文。无需进入后台了解为什么某个作者面板没有自动运行。

| 机制 | 当前运行范围 | 可见限制 |
|---|---|---|
| 本平台原生探索协议v1 | 版本化行动、明确数值、可见地点、事件来源、按故事恢复 | 不把普通模型回复自动当成数值写入 |
| 普通叙事卡 | 开场、角色资料、已绑定书、自由输入、历程与手记 | 不伪造数值、自动推荐规则或地图 |
| 作者HTML面板 | 新故事静态展示，标注脚本/外部资源未运行 | 固定高度内滚动，不代表脚本按钮或显示数值生效 |
| 脚本/正则/外部变量框架 | 保存资料并报告依赖线索 | 不宣称MVU、ERA或TavernHelper全套玩法等价 |
| 历史ERA桥接 | 保留有限变量读取/显示与临时内存更新 | 临时写入不是持久故事状态；未实现API明确失败，外部脚本资源被限制 |

无地图的卡不再显示空地图导航，窄屏资料按钮也不再承诺地图。资源地图与日常约定共用资料区，但显示各自真实字段。

## 隔离与桥接边界

- 新冻结故事不挂载旧脚本执行器；开场、流式正文、历史消息中的完整HTML都使用无脚本权限的静态框架。
- 历史可交互框架移除`allow-same-origin`，使用不透明来源与前置CSP；父窗口检查消息来源窗口和来源值。桥接注入字符串转义，避免名字结束脚本标签。
- 控制脚本只在隔离测试中使用本项目编写的样例。检查父文档/存储访问、网络请求、外部模块加载、变量读取与显示、未实现API拒绝及切档后迟到响应。
- 变量树拒绝原型路径、过深/循环对象和超限值；切换故事重建脚本框架，异步结果不得更新另一个故事。
- 这不是任意不可信代码的完备运行环境：不承诺无限CPU/内存、所有自身导航途径或全部浏览器能力已被限制。未开展批量运行第三方脚本；OPEN-05的首批框架选择仍开放。

## 代表样本与证据分层

本轮真实模型复核实际发现并修复两处正文/面板分裂：问价时系统上下文缺当前可见行动标签，模型编造50枚押金/审核费，而购买规则是20枚；只有姓名、没有简介的冻结身份未注入模型，导致面板确认互通姓名、正文却重新询问。上下文现包含公开行动标签及费用约束，不注入未选择行动的隐藏结果；冻结姓名独立于简介注入，已批准行动不因情绪提示而被推翻。原失败记录保留，不改写历史正文。

1. 原创资源地图卡：真实JSON文件上传→内嵌书入库绑定→详情快速开始→问价不购买→购买扣款→地图浏览不移动→明确旅行→手记→离开/刷新→同卡新档→服务进程重启→恢复继续。
2. 原创日常约定卡：真实JSON文件上传→内嵌书绑定→开局→表达安静边界→互通姓名→约定明晚整理旧书→自由提问→手记→同卡隔离→进程重启→窄屏恢复继续。没有地图或好感分数。
3. 用户目录中的三张原始卡与两份独立书：沿用已核对文件指纹；解析/保留/绑定/冻结/规则触发与CLI对照独立记账。本轮新增原始卡详情及冻结故事诊断检查，保持作者代码不运行。不能将原创原生卡结果转写为三张原始卡作者机制全部通过。

HTTP/WebSocket、真实数据库与浏览器链路使用本机受控供应商，验证工程行为；真实模型使用另外的限额检查，只发送原创样例上下文并单独审阅。真实模型重放不在生产故事中落库，不替代浏览器验收，也不视为用户视觉/玩法签收。两张原创样例仍不是已经确认的首发素材。

## 复测与最终证据

执行`node scripts/card-sandbox-check.mjs`检查组件隔离；运行带授权样本目录的`node scripts/exploration-entry-check.mjs --library`检查完整导入及两类玩法恢复；`--recovery`检查中断/失败与请求恢复。上述运行只使用临时库和回环端口。

真实模型检查使用`node scripts/character-journey-model-check.mjs --config <私有配置> --requests <隔离测试生成的owned-requests.json> --token-budget <当前剩余额度内的上限>`。不能将预算重新计为新的45万；遇到缺usage或未知计费失败须按预留量记账并停止后续付费调用。

仅复核一轮可追加`--only-case late-bookshop:2 --previous <先前原创真实回复文件>`，会复用前序真实回复而只提交指定一轮。脚本对同一输入文件使用排他锁；异常终止产生的旧锁须核对进程和预算后处理，不能自动删锁启动下一轮。`node scripts/character-journey-model-guard-check.mjs`用回环合成供应商验证重复进程在调用前失败、完成后释放锁及定点模式只调用一次，不产生付费消耗。

本轮调度曾发生一次并发重复启动：两个临时文件watch回调在读取文件后同时启动，已停止重复进程，后续改为串行一次性调度并增加脚本级互斥。已知用量与未返回用量的保守预留分别列账，原失败和重复记录都归档；不能把未知请求当作未计费或从授权额度中抹除。
