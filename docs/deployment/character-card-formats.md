## 用户可见变化

此前，单卡入口捕获所有 PNG 解析异常后创建空白图片角色；批量入口只读 `chara`，将 `iTXt` 当普通文本处理，并允许缺少角色字段的 JSON 入库。批量界面的响应类型也与后端不一致：后端返回成功、失败数组，前端按数字处理，而且无论是否失败都弹成功提示。

现在两个入口使用同一解析模块。未识别文件、无角色资料的图片、损坏元数据、已识别的独立世界书/预设都明确失败，不创建空白角色。图片仍可在正常角色创作中用作封面；角色卡导入不再隐式承担图片建角色的功能。依据是[兼容性调研第5节](../product/character-card-compatibility-study.md)中已记录的“不创建空白角色冒充成功”约束。

批量结果持续显示成功/失败数量、失败文件名和原因，可关闭；部分失败及全部失败不会显示全部成功。仅有成功文件时才刷新角色列表。提示明确区分“资料已保存”和“脚本/完整玩法已适配”；不会重复自动提交失败或成功文件。

## 本轮文件支持边界

| 输入 | 行为 |
|---|---|
| 旧式扁平 JSON、V2/V3 包装 JSON | 校验非空名字、角色文本及核心字段类型，保留扩展；兼容本项目已有的扁平 V2/V3 导出 |
| UTF-8 BOM、开头空白、错误扩展名 | 依据实际内容识别；真实 PNG 即使叫 `.jpg` 仍按 PNG 处理 |
| PNG `tEXt` 的 `chara` / `ccv3` | 支持；同时存在时选 `ccv3`，不能因 V3 损坏而静默降级到旧 `chara` |
| 未压缩 `iTXt` | 正确跳过压缩字段、语言和翻译关键字后读取 base64 UTF-8 JSON |
| 同关键字重复记录 | 相同记录接受，不同记录报告冲突；不同版本的 `chara`/`ccv3` 按上述优先级选择 |
| 压缩 `iTXt`、`zTXt` 角色资料 | 明确报告暂不支持，提示导出为 JSON；未添加解压执行能力 |
| 普通 PNG、JPEG/WebP | 不作为角色卡创建；显示没有受支持的角色资料 |
| 非 WebP 的 RIFF、未知文件、PNG 截断/越界/CRC损坏、非法 base64/UTF-8/JSON | 拒绝，错误不携带卡正文、SQL或原始异常内容 |
| 独立世界书、常见预设、数组、空值或只有名字的 JSON | 拒绝作为角色卡导入；世界书使用独立入口 |

每个文件读取上限10 MiB。之后仍经过角色创建的字段长度、标签数量、头像和总 `cardData` 大小检查；批量不再悄悄裁掉超过100个的标签。单请求仍受已有服务端请求上限约束。PNG检查签名、块边界、CRC、头部及结束块；没有把元数据解析扩展为完整像素解码器。

JSON分类是有限规则，不能仅靠文件名或少量字段判定所有第三方格式。含名字与描述的最小旧卡仍允许导入；不宣称任意预设或混合自定义格式都能识别。ZIP等资产包、JPEG/WebP内嵌卡协议等不在本轮范围。

## 数据与导出

统一实现位于 `src/types/character-card-import.ts`，浏览器文件工具与服务端批量路由共用，浏览器继续负责本地文件读取和封面处理。解析错误有稳定代码，页面按语言显示对应解释；未知数据库失败保留通用错误，不暴露内部细节。

标准化运行字段保存在 `cardData`；新增 `_squaretableImport: { version: 1, original: ... }` 保存所选元数据解码后的完整原始对象，包括未知根字段及嵌套扩展。这里保留的是选中载荷的数据，不是整个PNG原文件、所有候选块或逐字节文本归档。两端创建获得相同运行数据和原始对象；不执行原卡脚本、不自动猜配世界书、不改已有存档快照。

内嵌书仍走既有角色仓储事务：任一书/条目写入失败，本文件整体回滚；其他有效文件可独立成功。已有档案不补造新来源信息，也不执行历史漏书修复。

导出使用当前编辑字段，并保留未知作者数据。去除平台导入归档和过时的 `.data` 包装，避免再次导入读到旧版本或使归档逐层嵌套。PNG导出替换旧 `chara`/`ccv3` 文本块，解决旧V3元数据优先于新导出内容的问题；显式V3标记不因缺少可选字段而降级。没有重做世界书导出的完整语义转换，也不将此检查等同完整用户存档迁移。
