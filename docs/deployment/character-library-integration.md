## 修复的问题

此前单卡创建和公开卡复制在路由中单独写入世界书，批量导入没有调用该逻辑。单卡路径还会捕获世界书写入异常后照常返回角色创建成功，造成“原始卡里有设定，但实际绑定没有设定”或只写入部分条目的结果。

现在由角色仓储的统一创建入口，在一个数据库事务中保存角色、内嵌世界书与全部条目。网页单卡、批量及使用该入口的复制操作共享此行为，路由不再重复创建世界书。任一条目写入失败即回滚本文件；批量中的其他有效文件仍可成功，并分别报告结果。畸形内嵌世界书明确拒绝，数据库错误不再把SQL和卡正文回传到批量结果。

新增字段映射保留扩展位置/深度/角色等既有行为，并处理样本中的空匹配选项；扩展中的次级匹配逻辑参与映射，`selective:false`不会误要求次级关键词。原始卡与未知扩展完整保存在`cardData`中，字段保存不等于扩展可执行。

## 实际验证

使用一次性PostgreSQL/Redis、beta迁移和构建后的正式后端，通过真实HTTP与WebSocket执行，没有模拟仓储或写入3080/3081业务库。

| 验证 | 结果 |
| --- | --- |
| 3张原始PNG：鉴定师、公会模拟器、冒险团 | 单卡JSON创建与原始PNG批量导入的数据一致，原始字段保留 |
| 内嵌世界书 | 分别0、5、53条；同卡两条导入路径的持久化映射一致，开局捕获对应绑定 |
| 2份独立世界书：神明级魔法、通用旁白 | 分别10、4条真实入库，归属正确；保持未绑定角色，不自动猜配 |
| 失败恢复 | 畸形书拒绝；第二条记录触发数据库限制时，角色、书及此前条目全部回滚；混合批次只保留有效文件 |
| 内容冻结 | 修改来源后旧档不变，新档读取新版；删除来源后此前两份存档仍可生成，新档不再绑定已删除资料 |
| 生成请求 | 合成卡通过实际WebSocket验证关键词、常驻、禁用、零概率、次级关键词、深度位置及user角色注入；无绑定不加载全局资料 |

最后一项包含4次专门的受控生成：无关键词、主关键词、主次关键词、新开空绑定。原始素材只进行导入与快照检查，未提交给本机或外部模型；触发行为使用小型合成规则，以便明确判定预期结果。无作者脚本执行，不将受控生成当作真实模型剧情质量。
