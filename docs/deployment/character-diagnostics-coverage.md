日期：2026-10-25。对应[复盘R1/R2](../product/exp-03bc-delivery-review.md)与[执行准备](../product/next-development-stage.md)，依据DEC-02/11/12、INV-07/09、EX-11/13。结论：R1/R2已完成原需求映射、补验及所发现缺陷的修复，03C兼容诊断工作包关闭；完整框架执行、文字身份语义验证、人物知情及产品/人工验收仍开放。[本轮证据索引](evidence/character-diagnostics-coverage-completion.json)与前轮记录分别保留，不改写之前的遗漏。

## 本次补验的实际效果

本次新增可复跑的覆盖工具与集成检查，并修复实际外部卡导入失败：内嵌世界书的`sticky/cooldown/delay`为`null`时，原来会整卡拒绝。共享校验现接受未设置值，原始资料仍保留`null`，运行映射沿用0；条目已有明确配置时，扩展中的空值不覆盖它。独立书复用相同规则，负数、小数、字符串、布尔值等错误类型仍拒绝。修复已部署3081，并在实际候选验证文件导入及入库后的参数。已有身份/用途提示和快照行为接受新检查，不计为本轮新增页面能力。

已通过的无声明旧卡链路使用自有材料：作者正文设定玩家是船长，所选人设自述是初次登船的乘客。页面明确身份未自动核对；生产请求保留双方资料，未删除作者设定。此结果证明传递和告知，**不证明模型解决了身份冲突**。无声明旧卡不具备完整语义校验，依据体验合同第3节保留边界，不将其写成支持。

未声明用途的书保持未知，四类内容按原常驻/关键词规则进入请求；同名未绑定和其他角色绑定的书不进入该故事。源卡、书和人设修改后，旧档在实际API进程重启后仍按原版本续写，新档使用新版本。

## R1：原调研结构与证据对应

`scripts/character-coverage-check.mjs`使用正式文件解析器读授权原件，取保留的原始对象；明确按V2/V3封套读取`data`，旧式读取根字段。原始封套可能同时带顶层镜像字段，不能把它当作已标准化的数据库对象。仅输出指纹、结构类型和断言，不归档作者正文或执行未知脚本。

抽样策略是按稳定文件顺序选首次覆盖的结构，满足类别即停止；不是全库通过率或随机统计。当前选出10份原件覆盖12类特征，另沿用既有独立书和格式压缩证据。

| 原要求 | 对应来源/检查 | 可成立的结论与边界 |
|---|---|---|
| V2/V3及旧式 | 三类原件、原始对象与正式导入结果核对 | 格式可解析、原数据可保留；不等于完整玩法 |
| 内嵌书/命名引用 | 原件结构、现有绑定状态矩阵、R2未绑定同名反例 | 绑定有依据；不存在全库自动猜配 |
| 独立书 | 既有两份外部独立书入库证据，加R2实际独立书隔离 | 角色绑定与独立文件不是同一概念；完整源文件归档仍不是本项成果 |
| 多开场 | 原件备用开场与既有备用开场脚本线索测试 | 检查范围包含备用开场，不宣称所有作者菜单已适配 |
| `TavernHelper_scripts` | 原件中数组→`type/value`→脚本对象结构 | 可保留与识别运行依赖；没有执行框架 |
| `tavern_helper` | 原件中`["scripts", [...]]`元组结构 | 不仅是字段别名夹具；仍不执行未知作者脚本 |
| MVU与ERA | 两类实际原件的正文/书条目线索；原生与旧变量执行边界另有证据 | 外部数值不误报原生状态，不宣称框架等价 |
| 正则、HTML、未知扩展 | 原件中的活动正则、作者HTML和未知扩展诊断 | 解析、保留与运行支持分开，降级可解释 |
| 多人物 | 原普通多卡检查；R2一卡含多人、原生规则多卡拒绝 | 一卡多人不拆代理；原生多卡事务拒绝；人物知情仍未完成 |

原件真实API覆盖入口为`scripts/character-coverage-integration.mjs`：按私有选样清单复核文件指纹，逐卡检查入库原始对象、正式诊断、冻结资料与安全预览；原件不发送到模型、不进入执行作者代码的页面。

## R2：无平台声明的真实行为

新增`scripts/character-undeclared-check.mjs`，接入现有诊断集成入口。

| 场景 | 断言 |
|---|---|
| 原卡正文固定背景、玩家人设自述不同 | 源卡原对象入库，诊断为`unverified`；实际生产请求保留两方内容，不把共存说成冲突已解决 |
| 资料没有`squaretable.purpose` | 用途列表为空且明确未声明；常驻背景/常识/风格/规则进入请求 |
| 关键词资料与无关书 | 无关键词首轮不触发，明确询问后触发；同名未绑定书和其他人物书均不注入 |
| 旧新故事连续性 | 正常API修改卡、书、人设后新档读取新版本；旧档三份快照不变，重启后生成仍使用旧内容 |
| 手机界面 | 未核对身份、未声明用途可见；开场使用保存称呼；没有额外选世界步骤；阅读设置可见历史诊断 |
| 多人物边界 | 一卡多人仍为一个角色卡对象；普通多卡沿既有验证；原生规则混用返回明确错误且不留下故事或占用请求 |

## 复跑入口

先设置`CARD_LIBRARY_SAMPLE_ROOT`为已授权本地素材目录，运行`node scripts/character-coverage-check.mjs`。成功后输出临时证据目录；其中`report.json`为无作者正文的报告，`selection.json`包含本地来源路径，仅在本机私有保存，不复制到公开文档。

保持素材目录变量，设置`CHARACTER_COVERAGE_MANIFEST`为该`selection.json`的绝对路径，并运行：

```bash
CHARACTER_DIAGNOSTICS_ONLY=1 node scripts/exploration-entry-check.mjs --library
```

入口会构建当前代码，建立一次性PostgreSQL/Redis并执行正式API/浏览器检查；结束后清理隔离服务。检查期间按正常接口限流等待，3081用户数据库不参与。`CHARACTER_UNDECLARED_ONLY=1`可单独检查旧卡行为，`CHARACTER_COVERAGE_ONLY=1`可单独检查选样入库；单独运行结果不能记为整个组合通过。
