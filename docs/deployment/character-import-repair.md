# 已复核漏绑定的显式补建

2026-10-25后续：本窄范围工具补齐`recursive=false`持久化，原审计映射同步修正，真实CLI回归通过。其他来源/编辑/重复/停用情形由[显式来源与差异恢复工具](character-legacy-reconciliation.md)处理，复用回执表但采用独立的完整计划指纹；本工具没有增加强制覆盖或扩大原准入条件。

日期：2026-10-24。工作包：EXP-03B-REPAIR。对应 [决策基线](../product/exploration-experience-baseline.md) 的 DEC-10/12、INV-03/07/09，承接 [历史导入只读审计](character-import-audit.md)。本轮实现的是**当前有效内嵌书存在、当前没有任何绑定书**时的显式补建，不是所有历史导入差异的自动修复。

## 使用前提与入口

先运行只读审计，确认目标记录为 `missing_bound_book`，并复核缺失确实需要补建。该分类也可能来自用户主动解绑；工具不能判断历史意图。修复需要明确租户、创建者、单张角色和审计的完整复核指纹，以及 `--apply`；没有全库、批量、强制覆盖或忽略指纹选项。重复目标参数直接拒绝。

新增普通迁移 `0049_character_import_repairs` 与 beta 迁移 `0009_character_import_repairs`，建立持久修复凭据表。使用前由部署流程将对应迁移应用到目标数据库；修复工具不自行迁移。两套SQL内容一致，本轮实际数据库验证使用完整beta迁移链，不能据此声称现有普通数据库已经升级。

由操作者明确提供进程环境中的 `DATABASE_URL`。工具不自动读取 `.env` 或 `.env.beta`，不要把连接串或密钥放入文档、报告或聊天。

```sh
node --import tsx scripts/character-import-repair.ts \
  --tenant '<租户UUID>' \
  --owner '<创建者UUID>' \
  --character '<角色UUID>' \
  --expected-review '<只读审计输出的64位指纹>' \
  --apply \
  --report '/受控目录/新的修复报告.json'
```

报告以0600权限独占新建，拒绝覆盖已有文件或符号链接。正文、关键词、名称、脚本和用户对话不进入报告，只保存范围ID、审计指纹、书ID、条目数、首次完成时间及结果。目标属于其他租户/所有者与目标不存在统一报告 `REPAIR_NOT_FOUND_IN_SCOPE`。

## 事务与并发行为

1. 在 `READ COMMITTED` 事务中按租户、创建者锁定角色行 `FOR UPDATE`，等待结束后读取最新状态。单条语句15秒超时，锁等待10秒超时。
2. 同一角色和复核指纹已有修复凭据时直接返回 `already_applied`，不再次写入，也不以旧请求覆盖后来变化。
3. 没有凭据时，若发现绑定书，锁住至少一条现有绑定，防止检查过程中删除最后一本书让目标变成可补建；然后复用审计读取边界和指纹。已有任何绑定、来源失效/冲突或指纹变化均不补建。
4. 仅当前有效、非空内嵌书且无绑定时，使用共享 `characterWorldbookSchema` 和 `mapCharacterWorldbookEntry` 创建一本书及全部条目，再写入凭据。三者处于同一事务；任何条目或凭据失败都整体回滚。待创建条目上限10,000，来源读取上限沿用审计的12 MiB。
5. 角色编辑的行更新锁、现有显式绑定服务的角色 `FOR SHARE` 锁以及绑定外键检查都与修复的角色排他锁协调。没有新增一套与网页脱节的互斥锁。

当前绑定已经变化时，即使新绑定内容与内嵌书相同，也不能拿旧的“无绑定”审计指纹补第二本书。若使用新的审计指纹请求修复已有绑定，返回不符合补建条件。多本书、停用、内容编辑、无效资料、仅嵌套/归档来源及跨所有权异常保持原样，不能通过本工具修正。

JSON设置通过文本参数显式转为JSON对象后入库，避免数据库驱动对已序列化JSON字符串再次编码。条目比较保留所有运行字段，不能用“条数相等”代替设置、正文和作者顺序验证。

## 重试与结果解释

| 结果 | 解释 |
|---|---|
| `applied` | 本次事务已提交，书、条目、凭据一起写入；`writePerformed: true` |
| `already_applied` | 相同范围和指纹以前已经提交；本次不写入，`currentStateRechecked: false`，不是当前数据仍完整的证明 |
| `REPAIR_REVIEW_CHANGED` | 当前资料/绑定与指纹不符，本次不补建；重新审计和复核 |
| `REPAIR_NOT_ELIGIBLE` | 当前审计分类不满足“有效非空内嵌书且无绑定”，本次不补建 |
| `REPAIR_INSPECTION_LIMIT` | 超过读取或待创建条目边界，本次不补建 |
| `REPAIR_NOT_FOUND_IN_SCOPE` | 不存在或不在指定范围，不泄露其他范围数据 |
| `CHARACTER_IMPORT_REPAIR_FAILED` | 参数、迁移、连接、写入约束或输出故障等固定脱敏错误，不能由此断定事务一定没有提交 |

退出码0表示取得 `applied` 或 `already_applied` 结果；退出码1表示未取得成功报告。尤其是提交后的报告写入失败、连接中断或进程被终止，必须以**相同范围和原指纹、新报告路径**重试核对凭据，不能换指纹盲目再补。持久凭据与书、条目原子提交，重试不依赖上一次报告文件存在。

凭据中的书ID故意不设随书删除的外键：后来删除或解绑书，不会删除修复凭据；重放旧命令不会重新建立该书。即使重新审计又得到相同的无绑定指纹，仍返回旧凭据。如果用户确实要再次恢复已主动删除的内容，需要另行复核和明确恢复流程，不应删除凭据以绕过保护。删除角色本身会级联删除其凭据。

指纹检查只能比较当前载入内容，不能识别没有版本日志的所有历史往返变化，也不能证明原文件来源。它是乐观一致性检查，不是数字签名或用户授权。

## 故事连续性

补建只改变角色供后续开局使用的绑定。已建立的 `story_content`、`story_worldbooks`、消息、状态和记忆不重写；原来缺书的旧故事仍保留其原始空绑定快照。新开局才捕获新书。把新资料带入旧故事是另一项需要明确交互与事件语义的能力，不在本次补建中暗中实施。
