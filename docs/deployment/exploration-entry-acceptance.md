## 4. 隔离联调发现的修复（2026-10-23）

真实服务下发现两条此前 fixture 检查未暴露的故障链：

- `/auth/me` 原本和登录共用严格认证限流，重复刷新详情会触发 429；客户端又把任何资料请求失败当作退出登录，后续失去租户信息。现在资料读取保留普通 API 限流，登录限制不变；资料初始化仅在 401 时清认证，429、503、断网保留令牌和租户并允许再次恢复。
- 入口导航和账号恢复原本并发。账号资料晚于故事列表返回时，存档隔离监听会将这次初始化当作账号变化，清空列表。现在由导航守卫等待身份恢复，再进入页面；保留真正切换账号时清空旧存档及丢弃旧响应的行为。

新增延迟身份恢复、临时失败重试与限流分离回归；连同原有聊天隔离测试，4 个文件共 80 项通过。修复后重新执行三个入口浏览器文件，29 项全部通过；类型检查通过，定向 ESLint 为 0 error、13 条既有 warning。

`npm run check:exploration-entry` 完整通过。脚本构建当前源码，在一次性 PostgreSQL/Redis 中执行空库迁移，使用真实注册、角色、人设、存档、WebSocket 与账本接口；模型为本地确定性替身。原有停止、失败、释放冻结和账本隔离冒烟先执行，再运行新版入口检查，避免长时间截图等待使测试用旧连接闲置。

4. 同卡另开得到不同 chatId，新档不复制原正文，原档三条消息保留。
5. 可选身份取消不创建故事。
