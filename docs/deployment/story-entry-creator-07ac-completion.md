## 本次开发后的实际效果

| 操作 | 原问题 | 本轮行为 |
| --- | --- | --- |
| 编辑后清空介绍、分类或标签 | 空值被省略，服务端可能留下旧内容 | 显式提交清空，重新读取仍为空；未知卡扩展继续保留 |
| 预览、套模板或恢复版本 | 缺少保存边界，旧备用开场/语音/表情可能混入 | 预览不写入，恢复仅载入编辑器；缺省可编辑内容完整替换 |
| 离开编辑器、重复保存或读取失败 | 可能丢稿、重复请求，读取失败直接跳走 | 未保存提示、离开/关闭保护、异步校验前加锁、失败原页重试；新建响应未知先核对作品，不自动重发 |
| 作者工具与发布 | 非作者被前端当作者，直接进入页面未加载发布权限；待审核提示为已公开 | 使用真实归属、主动读取并隔离账户权限，保留原服务端授权；区分服务端保存、待审核、公开与隐藏 |
| 创作列表 | 仅载入第一页；错误可能被当成没有作品 | 加载更多、已加载范围说明、错误重试与迟到响应隔离 |
| 账户资料与点数 | 无法清空简介；保存后刷新失败被当保存失败；URL可触发支付成功提示 | 清空可落库；已保存仅重试读取；余额失败显示错误，权益与支付以服务端为准 |
| 页面核对 | 入口同内容对照缺768px | 六页三尺寸明暗对照，共72张；逐项记录原型与正式实现的差异 |

新建结果未知时，本轮提供防重复重发与人工核对入口，不新增角色创作幂等协议，也不声称自动找回新角色ID。故事创建仍使用已有完整幂等恢复协议。发布仍受原套餐及审核权限约束，本轮没有给免费账户增加发布权限；测试Pro权益是隔离数据库夹具，不是真实支付。

## 失败记录与修复

1. [创作第一轮](evidence/story-entry-creator-07ac-creator-first-failure.json)停在发布按钮：脚本查找“发布”，实际入口名为“提交发布”。同时源码核查发现创作直达页未加载套餐权限；修复权限读取、在途复用及切账户隔离，再用隔离Pro账户验证真实发布，未移除授权。
2. [第二轮](evidence/story-entry-creator-07ac-creator-second-failure.json)期待“加载失败”，实际文案是“加载角色失败”。修正精确文本，不改变故障注入。
3. [第三轮](evidence/story-entry-creator-07ac-creator-third-failure.json)发现新增按钮显式disabled=false覆盖父表单禁用。保存函数已阻止写入，但视觉仍可点；补齐按钮禁用并重新跑完7组。
4. [浏览器首轮](evidence/story-entry-creator-07ac-browser-first-failure.txt)13项失败/16项通过；旧夹具使用非64位十六进制CSRF值，被现有严格校验拒绝。替换为合格式合成值，保留生产校验。[第二轮](evidence/story-entry-creator-07ac-browser-second-failure.txt)28项通过，剩余标题定位因03C新增诊断标题而匹配两处；改为按角色名称定位标题，保留只浏览不建档/取消不提交断言。第三轮29项全部通过。
5. [完整入口第一轮](evidence/story-entry-creator-07ac-entry-first-failure.json)完成13组后在记忆工具组发现6个旧system-prompt/debug请求409。隐藏标签页也会挂载旧调试子组件，不能依赖异步导入偶然慢于断言而漏检。按故事协议隔离调试入口，旧档仅显式选中时挂载，切档关闭旧抽屉；新增测试覆盖新旧切换，保留服务端409和原零失败断言，完整流程重跑。
6. 作者权限核查发现历史版本在授权前写入。[新增测试先失败](evidence/story-entry-creator-07ac-author-first-failure.txt)，2项越权用例均复现“返回403但调用了saveVersion”。调整授权与写入顺序后，作者、协作者、版本读取/恢复及角色路由共49项通过。为验证同租户/跨租户请求确实没有数据库副作用，给真实创作专项追加一组；中断当时尚未完成的入口复验，整包重新运行，不将中断记录计作通过。
7. [部署检查首轮](evidence/story-entry-creator-07ac-deployed-first-failure.json)将32次性能指标上报误计为业务写入。源码核对确认是`webVitals.ts`的`POST /analytics/vitals`；脚本单独记录并继续拦截该端点，其他非GET请求仍计为错误并全部阻断，未关闭生产监控或放宽业务写入断言。
8. [部署检查第二轮](evidence/story-entry-creator-07ac-deployed-second-failure.json)完成页面与摘要检查后，发现5188原型进程未监听，健康检查失败。恢复原有本机原型服务器后重新核对全部入口；失败轮的记忆任务/尝试及生成请求前后不变，未将失败轮计作通过。
