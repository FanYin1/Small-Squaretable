## 本轮交付

新增 `scripts/character-import-audit.ts` 运维入口，对显式选定的角色检查：当前卡内是否保留世界书、已绑定的书是否与共享映射结果一致、绑定权限和启用状态是否异常。报告用于定位需要复核的对象，不代表已经确认历史导入丢失，也不证明角色玩法完整兼容。

工具只有只读模式，没有 `--apply`。不会扫描整个素材目录、按名称猜配独立世界书、重导卡片、补建世界书或修改既有故事快照。新增导入逻辑不会自动修复历史数据。

## 使用

在项目根目录运行；由操作者明确向进程提供目标数据库的 `DATABASE_URL`。工具不自动读取 `.env` 或 `.env.beta`，避免默认连错环境；不要把连接串、邀请码或密钥复制到报告或聊天中。

```sh
node --import tsx scripts/character-import-audit.ts \
  --tenant '<租户UUID>' \
  --owner '<角色创建者UUID>' \
  --character '<角色UUID>' \
  --character '<另一个角色UUID>' \
  --report '/受控目录/新的审计报告.json'
```

一次必须指定1至50个角色ID，同次重复ID合并；租户、创建者均为必填，不支持全库默认扫描。此工具面向持有数据库权限的运维人员，参数范围检查不能替代数据库凭证访问控制。没有创建者的旧卡不在本轮范围内。

数据库使用 `REPEATABLE READ READ ONLY` 事务，各条语句15秒超时。每张卡的资料最多读取12 MiB，绑定书最多50本；条目总数最多10,000条，书和条目预检序列化体积合计最多32 MiB。超出范围标记 `inspection_limit`，不给完整复核指纹。这些是审计加载边界，不是导入限制或进程总内存保证；大小预检仍需数据库读取对应数据。

报告只允许新建，文件权限0600，拒绝覆盖已有文件或符号链接目标。标准输出仅含模式、总数及分类计数；详细报告保留明确请求的ID、数量、分类、归档存在标记和SHA-256复核指纹，不包含名称、角色正文、条目正文、关键词或对话。失败时返回退出码1和固定脱敏错误，删除本次未完成的报告；正常审计返回0，**有待复核项也返回0**，不能把退出码0解释为资料全部健康。中断产生的不完整文件不能当成有效报告。

## 分类及解释

| 报告状态 | 含义与后续动作 |
|---|---|
| `matching_bound_book` | 恰有一本启用且角色作用域的绑定书，其条目与当前内嵌书映射一致；不证明该书的历史来源 |
| `missing_bound_book` | 当前有非空有效内嵌书，现无绑定书；可能是历史漏建，也可能是主动解除，须复核意图 |
| `bound_content_differs` | 已有绑定书，但没有完整条目匹配；可能为作者编辑、部分缺失或另一本书，不覆盖、不追加 |
| `matching_with_additional_bindings` | 有匹配书，另有其他显式绑定；不删除额外绑定 |
| `multiple_matching_books` | 多本书内容匹配，存在重复候选；不自行去重 |
| `matching_book_inactive` | 内容匹配的书被停用或不是角色作用域；不自动启用或改作用域 |
| `binding_ownership_conflict` | 绑定的租户、所有者或角色关联与目标不符，优先复核权限与数据来源 |
| `no_embedded_source` | 当前资料中没有可识别内嵌来源；不等于原文件从未带书，不能凭空补建 |
| `empty_embedded_source` | 当前有效内嵌书没有条目；不计为漏书 |
| `nested_source_only` / `archive_source_only` | 来源只出现在旧包装或原始归档中；不静默提升为当前有效设定 |
| `source_conflict` | 顶层与保留的嵌套书不同，先确认哪份是当前设定；可能是正常编辑后旧副本仍保留 |
| `invalid_embedded_source` | 当前内嵌资料不满足共享字段结构，需显式修正来源 |
| `not_found_in_scope` | 不存在或不属于指定租户及创建者，统一返回，不暴露其他范围的资料 |
| `inspection_limit` | 超出本轮读取边界，未完成检查；不能算健康或可修复 |

所有分类均输出 `automaticRepairAllowed: false`，这是本轮不提供自动修复的明确边界。

比较按**完整运行字段的多重集**进行，保留重复条目数量、作者顺序、关键词及次级条件、正文、启用、优先级、设置、递归、人物过滤、扫描深度和上下文比例。SQL返回顺序和JSON对象键顺序不构成差异；数组顺序和未知设置仍保留。共享映射中未落库的作者扩展不被伪装成已运行支持。

复核指纹覆盖审计版本、角色ID/租户/创建者/名称及完整 `card_data`、所加载的绑定书字段与条目字段；包括归档、扩展和已加载的更新时间。稳定的重复读取指纹相同，资料或绑定变化使旧指纹失效。指纹不是历史来源证明、签名或修复授权，未来写入工具仍须重新读取、校验和锁定目标。

## 验证与证据

验收结果及源码摘要归档于 [审计验证报告](evidence/character-import-audit.json)。24项审计测试加9项共享世界书映射回归，共33项通过；应用与CLI类型检查、定向lint、生产前后端构建通过。真实隔离集成共17组检查，其中新增3组审计验证，覆盖14个合成历史案例；同时保留此前授权3卡/2书、41种格式与浏览器回归。首轮空资料测试夹具被创建接口正确拒绝，修正夹具后完整复测通过，没有放宽生产校验。真实隔离检查接入现有角色库集成入口：

```sh
npm run type-check:imports
npx vitest run src/db/character-import-audit.spec.ts src/types/character-worldbook.spec.ts
CARD_LIBRARY_SAMPLE_ROOT='<已授权本机素材根目录>' node scripts/exploration-entry-check.mjs --library
```

只读检查使用一次性PostgreSQL及正式beta迁移，构造历史漏书、修改、停用、权限冲突、来源缺失/旧包装/归档、无效来源、大小/条数越界等样本。对审计前后的角色、世界书、条目、聊天、消息、角色快照、世界书快照和状态表进行数据库指纹比较，另单独核对既有故事快照。直接核验事务隔离与只读设置，并在同类审计事务中验证写入被数据库以25006拒绝。

本轮没有连接3081进行存量审计，报告不包含现有候选库的缺失数量；没有执行任何历史修复或候选部署，也没有新增真实模型消耗。既有3卡/2书导入和浏览器回归与合成审计分别记账，不能把合成历史缺陷说成用户库实有问题。

## 后续显式修复方案

1. 先对明确范围产生报告，复核来源、绑定意图与所有权。`missing_bound_book`只代表候选，其他差异不能套用“补一本书”处理。
2. 写入工具须限定目标角色与预期复核指纹，在事务内锁定并重读角色、当前绑定与条目；若资料变化或出现新绑定则拒绝，不能使用审计时的陈旧数据直接写入。绑定并发须与现有编辑接口遵循同一锁定协议。
3. 对确认的漏建，只恢复当前有效内嵌书，复用共享映射与整书事务；重试不得重复创建。书、条目或约束失败须整体回滚，并保留可脱敏审计的来源与结果。
4. 旧包装、仅归档、内容差异、重复、停用及权限冲突单独复核，不自动覆盖或删除。无法恢复来源的旧卡，需要用户明确提供原文件及目标卡映射，不能按同名猜配。
5. 修复改变角色供后续开局使用的绑定；已经建立的故事继续使用原快照。若用户希望将修改带入旧故事，需另行明确产品交互和事件语义，本工具不承担此操作。
6. 后续验收必须覆盖：同一修复重复执行、审计后编辑、绑定并发、事务失败回滚、跨租户/所有权隔离、旧故事不变及新开局读取修复后的书。完成这些行为与证据前，历史修复子项保持开放。
