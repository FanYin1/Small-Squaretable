# EXP-04D：行动理解与人物知情交付记录

日期：2026-10-25。对应原 [EXP-04D](../product/backlog.md)，DEC-02/04/05/06、INV-03/06、EX-01至06。协议及完整原要求映射见[工作记录](../product/story-intent-knowledge.md)。

当前状态（2026-10-25 17:00，香港时间）：EXP-04D工程工作包完成，3081已部署并核验。338项针对性测试、35组组合集成、71表迁移比较和实际桌面/手机页面及重启核验通过。完成范围是单卡行动确认和显式多人知情协议；完整产品、真实长程叙事质量与人工签收仍开放。

## 本次开发后的实际效果

1. 单卡故事里，“我想拿一张通行证”等改写可以形成可核对的行动候选。玩家确认后才按卡片规则执行；输入或状态已变时拒绝旧候选。原有推荐行动与精确自由行动保留。
2. 菜单外的观察、交谈和其他自由探索可以进入同一确认链路。没有作者规则依据时，只继续叙事，不编造数值变更。复合规则行动按顺序校验、整批提交；任何一步条件不足都不执行。
3. 传闻、意向、推测、见闻和表达偏好带类型及原文依据展示；它们与余额、道具、地点等规则状态分开。拒绝或听说金币不会增加资产或触发购买。
4. 新多人故事可选择“在场所有人”或“单独对某人”。私下原文、回应、经历和派生记忆不进入无权人物的生成上下文；刷新恢复所选听众，私下草稿不会串到公开输入框。
5. 候选卡位于正文，手机输入区不再被大块确认说明占用。没有自动追加理解调用；确认后的续写是用户显式发起的一轮生成，沿用现有计费。

## 发现的问题及处理

真实供应商第一次样本的JSON正确标记“拒绝+自由探索”，但正文提前写了玩家靠近观察。此原始结果完整保留在[真实模型记录](evidence/story-intent-04d-model.json)，不能把结构通过当作剧情完全正确。

修复采用服务端隔离：待理解输入先缓冲响应；若形成候选，只显示程序生成的核对说明与结构化步骤，提前行动的正文不写入玩家历史或后续上下文。新增 `proposed` 事件状态，不进入确认事件的摘要任务。真实失败响应已作为受控回放样本验证此保护。来自被丢弃候选正文的人物见闻也不作为事实保存。代价是待理解自由输入的首段显示会延后；已确认行动续写仍保留流式显示，停止片段仍保留并明确标为未完成。

另修复角色卡正则可能擦除协议的路径：协议始终从模型原始响应解析，展示后处理不能改写协议权限；人物事实的引用还须存在于最终保存的正文。隔离组合运行器修复了Drizzle复用连接改变后续原始SQL序列化，以及跨检查组限流余额未初始化的问题；没有降低生产限流或放宽验收断言。

### 保留边界

- 通用候选确认用于单卡故事；多人原生数值规则仍不支持，新多人故事增加的是知情范围。单张世界卡正文里的多个NPC尚不能自动拆成独立授权身份。
- 人物知情范围按显式听众与已有角色绑定执行，不自动识别未标记的作者秘密。旧未分级消息沿用原公开语义；手记仍是共享背景，页面已有说明。
- 公开生成保守排除私下材料，即使说话者本人知道；没有实现NPC自主决定透露秘密。用户可以在新的公开输入中明确讲述，而不改写过去。
- 真实短样本、受控故障、工程部署和用户视觉/真机签收分开。OPEN-01至07和完整EXP-07D保持开放。
- 写入私下对话后，不能直接退回不识别知情范围的04C应用继续生成；应使用兼容范围的修复镜像，或在停止受影响故事后评估完整恢复方案。

模型用量：本轮2次真实调用共3,135 token；已知累计439,863，加旧未回执预留6,591后占用446,454/450,000，剩3,546。隔离回放和部署页面核对不新增真实调用。
