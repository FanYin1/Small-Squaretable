# 单人聊天输出额度被4096覆盖

对应 DEC-30/31/32、INV-02/04/05/08。本次调查用户报告的长度上限中断，不复制用户对话、模型密钥或卡片。

## 生产证据和原因

会话 `567691f7-4151-46e0-8c18-bd9eccfabdf7` 的请求 `temp-afdd1ee9-14bb-42f5-998d-32a33d0ca37e`，香港时间2026-11-03 14:30:06至14:30:50，记为failed / GENERATION_OUTPUT_TRUNCATED。用户在发起前切换到 `GLM-5.3-FlashX`。预扣与结算元数据记录请求输出上限4096，供应商实际输入14531、输出4096；没有助手正文落库或新增剧情事件。此前同故事GLM-5.3三次正常结束且提交状态。

运行时该别名的每次输出配置为128000，但单人默认WebSocket路径在调用预扣时使用 `min(模型配置, DEFAULT_MAX_OUTPUT_TOKENS)`，把4096默认值当作显式上限。随后按照预扣返回值发送max_tokens，因此后台大于4096的配置未生效。这不是JSON语法错误。输出token达到上限但无可保存正文；原始推理内容未保存，不能断言这些token全是隐藏推理。

## 修改后的行为

单人默认WebSocket路径将模型配置的每次输出额度传给预扣，模型最大能力值不直接作为请求额度。计费层既有16384硬上限保留；实际发送值仍与预扣一致。因此配置10000时请求10000，配置128000时在点数模式下请求16384；订阅模式沿用模型配置。后台已保存的容量、密钥及上下文不改动，也不把手填容量标为核实规格。

完整性保护不变：length仍是中断，已有片段保留、不提交剧情/事实/推荐或后续记忆，不自动重放；无正文时结算实际用量后报失败，不伪造正文。默认之外的固定文本模板和已暂停群聊不在此次改动范围。

新增流结束的固定元数据日志：模型别名、实际请求输出额度、结束原因、截断/不完整标记、正文字符数和供应商输出token数；不记录原始流、推理文本或私有正文。后续可区分额度耗尽与传输失败。
