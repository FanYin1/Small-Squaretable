# 独立世界书绑定与角色资料提示

日期：2026-10-24。对应EXP-03B、DEC-10/11/12、INV-07/09。实现角色作者的明确绑定入口及有限的命名依赖提示；不关闭完整兼容验收或OPEN决策。

后续修复：下文独立发现的CSRF会话撞键与覆盖问题已完成修复，移除「每次写前刷新令牌」绕行后原5组检查再次通过，见 [后续实现与证据](csrf-session-isolation.md)。下文保留首次验收时点，不将其旧报告当作当时已经完成会话修复。

## 用户可见行为

在已保存角色的编辑页，新增「本角色使用的资料」区域，显示已绑定世界书、启用条目数量和未启用状态，可进入资料详情核对内容。作者选择已导入且未绑定的世界书，再点击「绑定资料」才保存；选择本身不产生写入。解除绑定也在此完成。

这些操作单独保存，不依赖上方角色表单的保存按钮，仅影响之后新开的故事。玩家仍从角色卡直接开局，不普遍增加选世界步骤。绑定前、绑定后、解除绑定后的存档分别使用其开局时快照，不因后来的操作改写规则。

沿用现有数据模型：一张角色卡可绑定多份世界书，一份世界书目前只能绑定一张角色卡。已绑定其他角色的资料不作为候选；需要迁移绑定时先在原角色解除。仅支持未绑定的global/character资料，persona/chat用途资料不在本入口转移。解除绑定后保持character范围且角色为空，不自动升级为全局资料。

保存失败或结果无法确认时，不展示成功，也不保留可盲重试的操作列表；用户刷新核对后继续。界面说明已有存档保持原版，并提供中英文文案、键盘焦点、加载/错误状态和窄屏排版。

## 命名依赖提示的边界

本轮读取已保存卡数据中的`extensions.world`（兼容外层`data`包装），报告以下状态：

- 尚未绑定同名资料：即使库里已有同名书，也不会自动绑定。
- 已绑定同名资料且有启用条目：仍提示核对内容，不等于完整依赖或玩法通过。
- 同名资料整书未启用，或没有启用条目。
- 绑定多份同名资料：提示检查重复与冲突，不自动选择其中一份。
- 未识别到名称声明：明确不等于没有其他依赖。

这是可检查的提示，不是所有第三方格式的依赖解析器。不会据此阻止普通开局，也不会改写原始卡声明。世界书用途分类、任意命名引用/脚本依赖、作者核心玩法完整性仍需后续验证。

## 接口与并发保护

- `GET /characters/:id/worldbooks`：只允许角色作者读取本租户拥有的资料和提示，不向公开角色访客泄露作者库。
- `PUT /characters/:id/worldbooks/:bookId`：显式传入`action`及`expectedCharacterId`。服务端在事务中复核角色/世界书归属并锁定记录；绑定被其他操作改变或属于另一角色时返回409。
- 畸形参数拒绝，跨作者或跨租户目标返回404。并发请求不会静默抢走别的角色的绑定。
- 沿用已有故事快照机制，没有新增迁移，不回填历史缺失绑定或修改既有存档。

## 独立发现与后续

首次多用户联调中，另一测试账户获取CSRF令牌后，前一账户创建角色返回403。源码`src/server/middleware/csrf.ts`的`extractSessionId`使用Bearer令牌前32字符作为会话键，而`getCsrfToken`覆盖同键存储；这存在不同JWT共享前缀导致互相失效的问题。本轮没有修改CSRF中间件，绑定测试客户端在各次写入前取当前有效令牌，并发测试共用一次获取的令牌。不能将最终通过误报为会话隔离已修复。

该问题单独登记为EXP-07C-CSRF，需用不冲突的会话键以及双账户/双浏览器回归解决，随后复核多人候选。其他剩余项包括多角色共享资料、完整依赖诊断、历史漏书恢复、CLI路径统一、作者脚本隔离与代表卡真实游玩，继续由 [活动待办](../product/backlog.md) 跟踪。
