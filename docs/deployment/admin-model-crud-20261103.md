# 后台逐模型管理与隐藏

对应DEC-34/35、INV-05/08。用户要求在后台模型平台增加模型增删改查，并支持隐藏。

## 操作与行为

后台 `/admin/models` 顶部增加逐模型列表，按模型名称、上游名称、渠道搜索，并可筛选全部/公开/隐藏。每行提供查看、编辑、隐藏/显示及删除；新增模型选择已有渠道，继承其端点、协议、密钥和兼容设置，不需要重复输入凭据。新模型容量必须按供应商说明填写，不自动猜测。无渠道时使用下方“新增渠道”。

模型详情与编辑弹窗包含上游名称、上下文、独立输入上限（可选）、最大输出、每次输出额度、隐藏状态、平台默认设置。用户模型名称是会话引用标识，创建后不直接改名；可以修改上游型号。默认设置同时影响系统默认生成和记忆整理，界面明确说明。模型能力和每次额度继续按DEC-34校验。

隐藏是列表可见性功能：用户重新打开聊天模型选择器时看不到该模型，新切换请求不可选它；已有会话及直接指定该型号的调用仍可使用它。隐藏不是禁用供应商访问的权限控制。管理员列表仍可查看并恢复隐藏模型，模型容量与密钥保持。

删除操作先确认，移除模型名称、上游映射、容量及隐藏条目，不删用户故事或消息。旧会话仍保留原模型标识，需要重新选择其他模型，不静默更换已有会话。空渠道保留端点和加密密钥供再次新增使用，重启后不恢复已删模型。默认模型被隐藏/删除时自动选择其他公开模型；禁止移除最后一个公开可选模型。

## 接口与持久化

- 管理员GET `/api/v1/admin/models`返回全部模型含隐藏项及渠道元数据，不返回密钥。
- POST `/api/v1/admin/models/entries`新增；PATCH和DELETE `/api/v1/admin/models/entries/:model`编辑/删除，路径型号需URL编码。
- 单模型变更基于服务端当前配置，只修改目标项，保留兄弟模型。先原子替换加密配置文件再更新运行时；文件写入失败不改变运行中配置。最后一个公开模型保护也适用于旧渠道整体保存接口。
- 用户GET `/api/v1/llm/models`只返回公开模型，并把平台默认放在首位，与新会话前端默认值一致。前端已有在选择器打开时刷新列表的机制。
- 所有管理接口继续要求管理员权限；隐藏不是权限封禁，不自动中断已有模型请求。
