# WebSocket 生成请求持久化

2026-10-25后续：04C新增旧故事助手正文与整批ERA的数据库事务，按请求/人物恢复已提交回复；多人故障、提交期间停止与客户端整轮/分页恢复已验证并部署3081，见 [实际效果与边界](story-effects-04c.md)。本页关于模型消费、用量与点数不是同一跨系统事务、无请求标识无法跨连接关联的限制仍成立。

## 行为

WebSocket 完成会话归属、配额和点数可用性检查后，先在 `generation_requests` 记录请求，再保存用户消息和调用模型。`(chat_id, request_id)` 唯一索引配合 `INSERT ... ON CONFLICT DO NOTHING`，使连接同一 PostgreSQL 数据库的多个应用实例中，只有一个请求处理器取得执行权。正文和按顺序指定的角色列表参与 SHA-256 摘要；同一标识对应不同输入会返回 `IDEMPOTENCY_CONFLICT`。

状态为 `accepted → running → completed / stopped / failed`；保存用户消息前停止或失败时，可以从 `accepted` 直接进入终态。记录包含用户消息 ID、错误码和时间戳，不保存第二份正文。终态不会被后续收尾覆盖。删除用户消息只清空关联 ID，仍保留防重记录；删除整个故事时级联删除记录。

已接受请求无论处于哪种状态都不会自动重新执行。进程退出后遗留的 `accepted` / `running`、数据库写入回执丢失、部分群聊失败均保守阻止同标识重放，避免重复生成。重复提交的错误和结束事件只发送给提交连接，不向整个故事广播结束。旧数据没有请求记录时，仍按用户消息中的 `clientMessageId` 阻止重复生成。

这实现的是同一请求的单次执行权，不是模型调用、消息、用量和点数结算的一次性原子事务。故障可能发生在任意两步之间；记录不用于证明已经完成计费。没有客户端标识的旧请求仍会获得服务端随机标识，但跨连接重发无法关联。

## 部署

1. 在已有项目数据库上先应用 `src/db/migrations/0040_generation_requests.sql`。该迁移已登记到 Drizzle journal，可通过项目迁移流程 `npm run db:migrate` 执行；不要先手工执行 SQL 再重复执行同一迁移。
2. 确认 `generation_requests` 表、唯一索引和外键存在后，再启用新的 WebSocket 处理器。缺表时处理器会拒绝生成，不会退回无防重保护的旧路径。
3. 全部 WebSocket 实例都需更新。混用不检查请求表的旧节点时，不能保证跨实例防重。

本轮没有在业务数据库执行迁移。历史迁移中有未登记在 journal 的手工 SQL，本轮只新增 0040 的登记；已有环境应按原迁移流程确认此前结构已就绪，本轮测试不代表从空数据库完整安装通过。回滚应用时可保留新表，但回到旧代码后不再具备此处的防重能力。

## 验证

路由测试覆盖双处理器竞争、请求内容冲突、已接受请求无消息记录、写入结果不明、停止、终态写入失败和租户隔离。真实 PostgreSQL 脚本使用两个连接池发起 40 个并发请求，验证唯一获胜者、状态持久化、终态保护、消息删除后防重、外键和删除隔离。

本轮相关 4 个测试文件 107 项通过，类型检查、生产构建通过；定向 lint 0 error / 3 条既有 warning。

运行 `scripts/generation-request-concurrency-check.ts` 前创建一个空的一次性数据库 `generation_request_test`，将 `DATABASE_URL` 指向该库后执行：

```bash
npx tsx scripts/generation-request-concurrency-check.ts
```

脚本拒绝其他库名，创建最小依赖表并应用实际 0040 迁移；不会清空已有表，因此每次验证需要新的空测试库。验证结束后删除这一个测试库。本轮 17 项真实数据库检查通过，测试库已清理；未调用真实模型或进行真实点数结算。

## 后续工作

- 同一故事不同请求的跨实例串行化，以及跨实例实时事件与取消指令同步。
- 异常退出后遗留状态的核对、可恢复正文和有明确依据的人工 / 自动恢复流程。
- 持久化群聊每个角色的执行进度、模型调用与结算关联后，再开放部分群聊续跑。
- HTTP 生成路径接入同一请求协议，旧消息逐步迁移，以及重连消息分页补拉。

当前 `JOIN_CHAT` 回放和停止控制仍依据当前进程内的生成状态；请求表没有接管这些行为。不能仅根据 `accepted` / `running` 判定另一个进程仍然存活，也不会定时删除记录后自动重放。
