## 发现并补齐的截断保护

105条真实回复中104条正常stop，主故事第24轮有1条length截断，末尾为“你想在”。原服务级脚本直接提交了这个片段；该历史证据保留，不改写成105条完整回复。

进一步检查发现生产WebSocket只检查用户主动中止，没有保留供应商的length终止原因。现已修复：

- Gemini转换后的SSE、聊天兼容SSE、Ollama终态及文本模板返回明确长度终止时，标记本段为中断。
- 非空片段照常保存并按实际用量结算；原生故事不确认该段状态变化、不进入记忆批次；旧链路不执行变量更新或助手派生。
- 群聊保留此前已完成角色的回复，在截断角色处停止后续生成；不回滚已确认的前段。
- 返回稳定错误码 `GENERATION_OUTPUT_TRUNCATED` 和中文/英文提示，整轮不开放重试，防止重复行动或扣费。空输出达到上限也不能静默成功。

新增10项针对性用例，包含原生Gemini转流、usage帧、Ollama、文本模板、单聊/群聊、旧档/原生故事、空片段、结算和前端提示。相关5个测试文件共161项通过；类型检查、前后端构建通过，定向lint零错误、5条既有警告。

实际本机HTTP/WebSocket/Chromium与PostgreSQL完成6组恢复检查，其中新增的截断购买案例验证：片段可见且刷新后保留；钱款仍为120、凭证未取得；事件为interrupted，记忆任务/进度/记忆均为零；只结算一次、无悬空预扣、没有整轮重试按钮。见 [独立浏览器与数据库证据](evidence/story-output-truncation-verification.json)。该组使用受控供应商，不将它冒充真实模型百轮的一部分。
