# 会话内切换模型：连续性与格式兼容

日期：2026-11-02。用户对切换模型差异处理方案回复“可以按照这个方案处理”后实施；关联 DEC-32、DEC-05、DEC-30、DEC-31、INV-02/04/05/06/08。本次为单人故事源码交付，未部署远程，未调用真实模型，不改变工程测试预算暂停状态。

## 可见变化

每轮使用同一套故事连续性要求：延续已确认场景、名字、关系、悬而未决的问题和玩家选择，参考近期已确认正文的语言、视角、时态、人物语气和段落长度；本轮玩家明确提出的风格要求优先。不重新播放开场、不要求确认同一行动、不在正文宣布切换模型。

连续性块复用现有状态、笔记和最多六条已确认事件摘录，不新增概括模型调用。提案和中断记录不进入该块的已确认事件；原始对话历史仍可能包含这些记录，提示词明确其后果未经提交。未知场景或关系保持未知，玩家的打算和自述保留归属，不能当作已取得的资产。

生成或停止尚未完成时，前端拒绝切换模型。服务端 HTTP 模型选择与 WebSocket 生成共用故事操作门闩，其他标签页的切换请求返回 409 / `GENERATION_BUSY`。本轮在所有权校验后、异步准备前固定选用的模型，操作结束后释放门闩。

校验失败现在显示固定类别的原因，例如控制信息不完整、JSON 格式错误、字段不合约定、缺少输入依据、选择了不可用规则、仍返回旧提案或没有正文。保存的失败回复仍不提交剧情后果；生成请求记录为 failed，并附 `STORY_*` 原因，不能再把“已保存失败提示”计作正常生成完成。页面保留具体提示，不额外重复一个笼统的传输错误或自动重发。

## 统一协议的范围

继续复用现有 OpenAI 兼容、Anthropic Messages、Gemini 原生和 Ollama 传输适配。剧情层共用流式正文与末尾 `<story-intent>` 文本控制块，增加有效表达示例；没有强制所有模型使用 JSON mode、工具调用或供应商原生 JSON Schema，也没有增加第二次模型修复请求。

| 输入差异或错误 | 处理 |
| --- | --- |
| 标记前省略换行、CRLF、缩进及末尾空白 | 统一解析，记录 `format_normalized` |
| JSON 本身的代码围栏、紧贴控制块的外层代码围栏 | 去掉表现层包装，流式正文隐藏控制信息及围栏 |
| 合法 JSON 中推荐或引导字段格式不合约定 | 与行动权限分离；有效正文和规则后果仍可保存，推荐使用已有正文回退机制 |
| 错误 JSON、未知权限字段、无当前输入依据的行动、不可用规则 | 校验失败，不猜测修复、不自动执行旧提案、不提交候选后果 |
| 输出上限截断 | 沿用中断路径，记录结束原因及 `output_truncated`，不提交事实和后果 |
| 正常结束却没有正文 | 保存明确失败诊断，不作为成功的空轮次 |

结构化资产仍由作者规则与事务校验决定。停止、幂等、版本冲突、输入证据、知情范围和真实消费账本沿用原边界；模型请求即使剧情校验失败，也可能已产生供应商消费。事件版本可能因保存一条中断记录而递增，不代表资源或行动已确认。

每条新故事回复的 `extra.storyDiagnostics` 保存：版本、配置的模型别名、供应商适配后的结束原因（若有）、协议版本、校验结果、固定原因码及警告码。DONE 同步这些字段，刷新从已保存消息读取，分支复制白名单保留诊断。日志记录这些固定字段，不记录原始失败回复或密钥。别名不证明中转站实际使用的上游型号。
