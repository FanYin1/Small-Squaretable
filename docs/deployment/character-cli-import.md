# CLI 与网页导入一致性

后续已添加共享压缩资料读取及上限验证，见 [PNG压缩资料兼容](character-card-compression.md)。`prepareImportFile`现为异步；下文压缩仍待实施项是此前交付边界。原始条目对比后续改为包含全部字段及作者顺序值的多重集，以避免对相同SQL排序键强加未定义的额外顺序。

日期：2026-10-24（香港时间）。对应 EXP-03B-CLI、DEC-02/11/12/14、INV-07/08/09。此交付完成旧导入工具的有限路径统一；完整第三方玩法、历史修复及正式候选更新仍开放。

## 修复范围

此前 `scripts/import-cards.ts` 只把PNG作为角色处理，忽略JSON角色卡；PNG另有一套不完整解析。它按名字加描述去重，会丢掉同名同描述、开场或规则不同的版本；还向标签追加目录名并截断为20个。角色、内嵌书和条目分开写入，失败可能留下部分记录。`--dry-run` 将静态解析数量称为已插入，无法据此判断真正写入结果。

现在CLI采用网页共享的文件解析与创建校验，识别JSON角色卡、V2/V3、`ccv3`、未压缩`iTXt`，保留所选原始卡对象与作者扩展。扫描候选后按文件实际内容识别，不依据后缀假设PNG格式；候选扩展为`.json/.png/.jpg/.jpeg/.webp`，其他扩展和非普通文件单列跳过，目录内符号链接不跟随。文件仍受10 MiB上限及角色创建字段/总数据大小限制。

CLI和网页角色仓储共用 `src/db/character-import.ts` 的单文件事务，角色及其内嵌书、全部条目一起成功或一起回滚。不同文件独立提交，一份失败后继续处理其他文件。导入角色保持私有，使用明确选择的既有用户及其租户，不创建账户、不发布、不改已有存档。

作者标签原样遵守网页的数量/长度校验，不再追加目录标签、截短为20个或推断分类。重复判断改为本轮扫描内的原始文件字节SHA-256，且仅在静态检查通过或实际提交成功之后记录；同名同描述的不同内容会分别导入，失败文件的另一份副本不会被当成已成功重复项。

## 独立世界书

独立书也使用共享准备与事务入口：`src/types/worldbook-import.ts`、`src/db/worldbook-import.ts`。网页 `/worldbooks/import-file` 同步使用这个入口，不再出现书已创建、部分条目失败但残留半本书的情况。畸形条目在写入前拒绝，数据库写入失败则整本回滚。

独立书的`key/keysecondary/order/disable`等字段先转换，再共用内嵌书的条目映射。扩展中的位置、深度、角色、概率及选择条件按同一规则处理；`selective:false`不误要求次级关键词。保存描述；不再把无效条目静默略过或将非字符串正文改成空字符串。有效历史资料的映射可能因这次语义修正而改变，已存在数据库记录不会被自动重写。

CLI默认跳过独立书；只有明确传入`--include-worldbooks`才导入。选中的独立书沿用现有网页入口的`scope: global`及启用状态，所有者明确、`character_id`为空，不推断角色绑定。在版本化探索故事中仍只加载开局明确绑定的资料；旧聊天对global资料的既有行为不变。因此不要把整套素材库作为默认补充书开启，选取需要的资料后通过作者绑定入口配置。

原始角色对象归档与未知卡扩展保留继续成立；此轮没有增加独立世界书原文件的完整归档字段，也不承诺所有未知世界书扩展执行等价。

## 参数与报告

先对选定的小目录试运行。无需账户或可用数据库，返回`ready`表示静态检查通过，`imported`始终为0；它不验证目标数据库约束或保证后续提交一定成功：

```sh
npx tsx scripts/import-cards.ts --dir '/path/to/selected-cards' --dry-run --report '/tmp/card-review.json'
```

明确选择目标配置和已存在账户后实际导入；以下只是调用示例，本轮没有对候选库执行：

```sh
DOTENV_CONFIG_PATH=.env.beta npx tsx scripts/import-cards.ts --dir '/path/to/selected-cards' --email 'owner@example.com' --report '/tmp/card-import.json'
```

如需导入独立书，在已选目录上显式增加`--include-worldbooks`。内嵌书始终随角色事务保存，不能以省略依赖的方式宣称角色完整导入。

| 参数或结果 | 当前行为 |
|---|---|
| `--dry-run` | 静态检查，无数据库连接；可搭配`--include-worldbooks`检查独立书 |
| `--email` | 实际写入时必填，对应现有用户；未找到则停止，不代建用户 |
| `--report` | 新文件，权限0600，必须位于输入目录之外；既有文件拒绝覆盖，防止覆盖来源或上次证据 |
| `--skip-worldbooks`、`--batch-size` | 旧参数停止接受，不静默沿用可能漏书或跨文件部分提交的行为；改用默认跳过独立书和单文件事务 |
| `ready/imported/failed/duplicate/skipped` | 分开计数；逐文件记录相对路径、状态、稳定错误代码、可用时的SHA-256/条目数/新记录ID |
| 退出码0 | 本次无文件失败，仍应看实际导入数量，不能将全部跳过当作已导入 |
| 退出码2 | 至少一份文件失败；其他文件可能已经提交，按逐文件结果处理 |
| 退出码1 | 参数、配置、目录、连接或报告输出等致命错误；检查终端错误及目标库，不自动重跑 |

报告和终端不打印角色正文、SQL或数据库密码。错误返回稳定代码，原始异常不会随文件结果输出。JSON报告包含文件名和测试外的真实记录ID时仍应由操作者妥善保管。

**去重仅限同一次执行的完全相同文件字节。** 重新执行可能再次创建记录；同一内容重新编码为另一格式也可能分别导入。尚无跨进程导入收据、恢复续跑或全库重复清理。不要直接对整目录反复重试，应先核对成功项并只选择需要重试的文件。工具也不会修复历史CLI生成的旧包装数据、漏建内嵌书或旧存档绑定。
