## 本次开发后的实际效果

- 角色详情及可选身份页会读取真实绑定，区分未绑定、停用、无启用条目和同名歧义。不会按名称从资料库猜配世界书；玩家不必重新选择一个世界。
- 书的用途只有在作者显式声明时才展示；未声明就说明尚不能判断。常识、背景、风格和规则可以同时存在，标签不改变触发语义，也不是执行脚本的许可。
- 可校验的固定玩家称呼与所选人设冲突时，开局返回明确原因，用户可选择符合要求的人设后继续。失败不创建故事，也不留下已占用的创建请求。
- 新故事保存开局诊断及原内容/绑定快照。阅读设置显示每位人物的开局支持情况，后来编辑或停用原资料不修改旧档。旧档没有诊断时明确说明，不从现在的资料补造过去。
- 诊断接口只返回派生能力、数量、状态、用途及显式公开的固定称呼；不增加隐藏世界书名称、条目、作者脚本或私密设定正文的返回。

## 作者可选声明

以下为本平台新增的可选声明，不是第三方角色卡通用标准。旧卡没有该声明时保持原有身份选择；正文中的职业、经历、关系或隐含身份尚不能自动判定是否冲突。它们不会因此被删除或改写。

```json
{
  "extensions": {
    "squaretable": {
      "playerIdentity": { "protocol": 1, "fixedName": "澄舟" }
    }
  }
}
```

仅校验公开称呼；不是完整身份锁定或职业/关系裁决。多人物故事的固定称呼必须同时满足，不能以最后一张卡覆盖前一张。已有存档继续使用原身份，不反向应用新声明。

内嵌或独立世界书的条目可以声明用途：

```json
{
  "content": "作者条目正文",
  "extensions": { "squaretable": { "purpose": "knowledge" } }
}
```

`purpose`支持`setting`（背景）、`knowledge`（常识/概念）、`style`（风格）、`rules`（规则）。导入时保存为条目设置的`squaretablePurpose`，只用于说明。未知值保持“未声明用途”，不会猜测或执行。未补齐独立书整个源文件归档，不把条目映射说成完整文件保真。

## 03B复盘及修复

1. 原扫描只读取部分主字段，遗漏其他开场、人物性格、系统/历史提示、深度提示和书中依赖线索。现纳入这些内容及实际启用的绑定条目，设置字符/条目上限，超限显示检查不完整。脚本线索仍是有限静态诊断，不是任意代码的依赖解析器。
2. 命名依赖函数直接优先使用`data`，可能读取归一化卡中已过时的嵌套副本。现在优先使用当前人物字段，保留包装格式兼容。
3. 群聊服务的一条旧测试没有纳入03B新增的安全兼容字段。已更新其精确预期，保持隐藏提示词与脚本正文不返回。此前相关测试范围未覆盖这条断言，是验收覆盖遗漏，不能把测试数量当作没有遗漏的证明。

本次补修归属03B原诊断要求，不把它们搬到03C后宣称03B从未存在缺口。原03B没有承诺的任意框架等价、全部历史修复、真实模型浏览器长跑与人工签收仍单列，不属于本次静默关闭项。
