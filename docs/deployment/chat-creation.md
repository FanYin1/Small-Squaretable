## 接口行为

`POST /api/v1/chats` 新增可选 UUID 字段 `clientRequestId`。同一租户、同一用户的同一个标识，只能绑定一份创建输入；连接同一 PostgreSQL 数据库的应用实例共享防重结果。

| 请求 | 返回 |
| --- | --- |
| 首次成功提交 | `201`，新故事 |
| 同标识、同输入再次提交 | `200`，原故事的当前数据 |
| 同标识、不同输入 | `409 IDEMPOTENCY_CONFLICT` |
| 原故事已删除 | `410 CREATED_CHAT_DELETED`，不重新创建 |
| 身份不存在或不属于当前用户 / 租户 | `404`，不保留此次失败的请求记录 |
| 标识不是 UUID | `400`，不进入创建服务 |

SHA-256 摘要覆盖规范化后的角色列表、身份 ID、标题和 metadata；携带`opening`时还覆盖完整开场选择。未携带该字段时保持此前摘要形式，兼容已有回执。角色列表去重并保留顺序；同时提供单角色和角色数组时，以数组为准。对象键顺序不影响摘要，数组顺序会影响；缺省 metadata 等同 `{}`。修改身份、标题、角色顺序、开场或 metadata 内容不能沿用已成功绑定的键。记录只保存摘要与资源关联，不额外复制完整输入。

事务先争取唯一请求记录，再创建故事及全部群聊角色关联，最后绑定结果，一起提交。并发请求通过数据库唯一约束等待提交结果；关联插入失败时全部回滚，同键可在修复原因后重试。删除故事只清空请求记录的 `chat_id`，保留删除标记，防止迟到的请求重新创建已删除故事。不要按普通缓存策略定期清空这些记录。

重放返回原故事的当前状态，因此重命名后会返回新标题；原身份删除后返回原故事且身份关联为空。此时不会重新校验已删除的原身份，更不会再创建一个故事。

创建事件与角色成长计数只在此次事务新建故事时触发。它们仍在提交后执行，没有事务 outbox：进程在提交后退出时，事件或计数可能遗漏，不能宣称三者原子完成或可靠送达。

未携带标识的旧调用由服务器生成随机UUID并使用同一创建事务，仍有事务原子性，但调用方无法凭自己的稳定标识跨请求防重。

## 创建前选择开场

`GET /api/v1/characters/:id/story-entry`要求登录，只返回本人且属于当前租户的卡，或已审核的公开卡，并遵守内容可见性设置。响应不缓存、不创建故事、不调用模型。返回资料版本`revision`、有来源的介绍、逐项开场预览、身份要求、公开原生初值及有限兼容摘要。

开场引用为`{ source, index }`：`first_mes`的index固定为0，`alternate_greetings`使用原数组下标，不因空项、排序或相同正文改变；`none`的index为0，只用于没有可用开场时明确自行输入第一步。介绍摘录另外返回对应开场引用，原文和作者/用户修改不被覆盖。

新建时传入`opening: { characterId, revision, reference: { source, index }, reviewed }`。未知宏或交互需`reviewed: true`；明确自行输入第一步也需确认。单角色开场协议不扩展为多人卡自动拼接。前端只发送引用，不能上传伪造的开场正文、规则或初值。

| 情况 | 返回/行为 |
| --- | --- |
| 卡片或绑定资料已变更 | `409 STORY_ENTRY_CHANGED`；重新查看，不退回默认开场 |
| 引用越界、空项、初始化/目录内容、错误人物或未确认兼容限制 | `409 STORY_OPENING_INVALID` |
| 跳过仍然可用的开场，或未确认自行输入 | `409 STORY_OPENING_REQUIRED` |
| 选择合法且创建成功 | `201`；身份、内容/世界书、初始状态、选择、开场消息与回执同事务提交 |
| 同请求在源卡后来变更后重放 | 返回原故事，不重新校验或升级已冻结开局 |

新故事选择存于角色内容快照的可选`opening`字段；不新增数据库迁移，也不回填旧快照。读取端只提供所选开场，已有正文不再用客户端索引切换开局。`none`不写虚构开场。原始卡保留全部内容；保存正文使用冻结身份展开既有宏。

2026-10-26接续：每个开场的准备结果增加只读`record`兼容说明，含适配器版本、所选来源摘要、有限公开初值及原因；创建输入仍仅传`opening`引用，客户端不能提交初值。服务器将结果作为可选`openingRecord`一起冻结到角色快照；`/chats/:id/story-state`返回已保存记录，不重新解析当前源卡。准备指纹现在包含`preparationVersion: 3`（此前开局记录版为2），旧草稿需重新核对；已提交请求仍先按原回执恢复。

每个开场同时返回只读`adaptationReport`，区分开局记录与持续机制。已审查来源仅匹配本卡角色作用域、当前绑定且启用的书及条目正文摘要；未知、改版、禁用或其他作用域不继承结论。页面仅显示机制类别和影响，不输出条目正文/标题。创建输入仍不接受客户端报告；服务器把报告作为可选`adaptationReport`与开场、内容及回执原子保存，严格校验开场引用和预览版本一致。创建重放和`story-state`读取冻结报告，不重新按当前源卡分析；旧内容快照没有此字段仍可读取，不自动补造。整库恢复与单故事迁移保留报告，迁移重新映射资源ID不改变其历史结论。报告不生成动作规则或当前资产，不执行第三方脚本。

开局记录是历史初值，不写入当前余额或动作规则。只有已审查格式的有限字段可展示，未知/损坏结构明确降级；原生规则与外部初始化冲突时返回`STORY_INITIAL_RULES_CONFLICT`（409），事务不留故事或创建回执。旧快照不自动补造记录，来源字段和数值的支持边界见[开局记录适配交付](../product/opening-record-adaptation-delivery-20261026.md)。

有开场正文时沿用消息配额检查，拒绝会回滚创建；只有真正新建时才计量一次。计量仍在提交后执行，不是事务outbox，不能承诺崩溃窗口内可靠送达。此次不调用生成模型或扣取剧情生成点数。

准备选择使用按账户/卡片隔离的会话草稿，仅存引用和版本；进入提交阶段后既有未决回执优先，不能凭草稿换请求号绕过结果未知保护。刷新验证资料版本，取消准备不建档。

## 只读查询创建结果

`GET /api/v1/chats/creation-requests/:requestId` 要求登录及 UUID 参数，按当前租户、当前用户查询，返回 `Cache-Control: no-store`，不创建故事、不触发事件或成长计数。响应位于标准 API 的 `data` 中：

| data | 含义 |
| --- | --- |
| `{ "protocol": 1, "status": "created", "chatId": "…" }` | 原请求已提交，返回其故事 ID |
| `{ "protocol": 1, "status": "deleted" }` | 请求存在，但原故事已删除 / 不再可访问 |
| `{ "protocol": 1, "status": "not_found" }` | 当前查询快照没有可见记录，不能证明创建失败 |

查询用一条带归属条件的左连接读取请求与故事，避免分两次读取时把并发删除误判为未找到请求。不返回载荷摘要、其他用户的记录或原输入。未提交的创建事务对查询不可见，因此 `not_found` 也可能代表请求仍在进行；旧节点的 404、非预期协议及损坏响应同样不能作为重新创建的依据。

## 前端行为与边界

故事入口首次确认时生成键并保存输入快照；当前流程中、身份不变的明确失败重试复用相同的键和角色数组。明确拒绝后切换身份属于新的操作，使用新键。API 和 store 原样透传标识；重放返回的故事不会重复出现在侧栏。

网络、408、5xx 或响应解析失败仍视为结果未知，不自动重新创建。关闭弹窗、清理入口查询参数、在当前页面重新打开入口不会解除阻断；可以关闭窗口检查故事列表。同键内容冲突与原故事删除分别显示提示并停止提交，不会自动换键绕过。故事已经创建但路由跳转失败时，只提供进入原故事的重试，不再选择或创建身份。

2026-10-22 起，提交前将版本号和请求键保存到当前标签页的 `sessionStorage`，键按租户 / 用户隔离；成功回包后再保存故事 ID。不复制角色描述、身份内容等输入。保存或读取失败时不发送新创建请求，提示检查浏览器存储权限后刷新；损坏的已有记录不会被覆盖。明确拒绝后删除未决记录，当前页面仍保留同流程重试用的键。

刷新或卸载后重新进入聊天页，会在账户资料就绪时恢复该账户的未决记录并发起只读查询，不自动 POST 或跳转。找到原故事后提供“进入原故事”；跳转成功才删除记录，跳转失败保留入口。已确认创建的故事 ID 在查询暂时不可用时仍可用于进入原故事。确认原故事删除后允许主动“关闭此请求”，清理入口参数，之后才可另开故事；结果未知时不能直接关闭请求来绕过保护。用户仍可通过侧栏阅读已有故事。切换用户 / 租户或卸载后，迟到响应不会覆盖当前恢复状态。

同标签页恢复依赖浏览器保留存储；关闭标签页、清理浏览器数据、独立标签页和不同设备不共享保证。复制标签页可能复制同一键，同键的服务端保证仍适用，但独立新操作各自生成键，不能据此宣称全局防重。新身份保存仍是独立请求，尚未接入持久化防重。

保留上述保守处理，是因为旧服务器可能忽略新增字段；发送了键或收到一次成功响应，不能证明所有节点已支持防重。未查到的请求保持暂停，下一步需要能力协商和明确的重试协议，才能安全放开未知结果重试。
