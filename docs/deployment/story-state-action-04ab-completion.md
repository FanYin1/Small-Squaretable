# EXP-04A / EXP-04B 状态与行动闭环收尾

日期：2026-10-25。04A/04B原要求工程收尾和3081部署复验完成；原要求逐项对应见[工作包](../product/story-state-action-04ab-closure.md)。人工视觉、真机和真实剧情质量签收仍开放。本轮发生验收夹具触发付费记忆任务的预算事故，见下文；最终功能通过不抵消该失误。

## 实际变化

| 场景 | 此前问题 | 本轮行为 |
| --- | --- | --- |
| 读取面板时另一轮刚提交 | 状态与历程分次读取，可能拼成旧余额与新事件 | 整次读取使用只读可重复读事务；状态、来源、行动和历程来自同一数据库快照 |

| 作者填写条件类型错误 | 部分配置能开始，但条件永远无法成立 | 作者编辑/诊断和新开局拒绝类型错配、非数值边界；既有快照沿用兼容读取，不回写或自动修复 |
| 打开新故事或使用记忆工具 | 页面调用旧记忆接口被409拒绝，工具可能显示旧角色缓存 | 版本化故事使用本故事的整理进度与原文入口；旧记忆/情绪加载仅保留给旧档，不显示跨故事的旧情绪数值 |

阅读导出继续复用它自己已有的只读可重复读事务；不会因为面板改造而嵌套一个不同隔离级别的事务。

## 在页面中怎样检查

1. 打开一个有原生状态的故事，推进一次会改变资源或约定的行动；概况中查看该项，再点“查看依据”和“阅读依据原文”，应能对上确认轮次和原文。
2. 继续多轮后再次查看早期依据，应直接定位该事件；手机端关闭资料区后，焦点返回“此次游玩”开关。
3. 浏览地图不应移动、扣费或发出生成；执行可用的移动行动才推进。日常关系卡显示约定和表达边界，无地图时不显示地图标签。
4. 状态读取失败时保留最后已读记录并明确标注，阻止基于未核对状态的推荐/候选执行；重试恢复后再操作。
5. 在新故事的“阅读与故事设置 → 工具 → 角色记忆”中，应看到此次故事的自动整理进度和原文入口。旧档仍保留旧记忆界面；这两个入口不再混用。

自动化中的35轮来源故事为明确预写验收数据，三轮关系卡使用受控供应商。上述路径的工程结果与真实模型能否自然延续语气、角色和剧情分开判断。

## 原要求覆盖与边界

- 04A的持久化、单调版本、事件来源、未知值、条件可见性、旧档读取、Redis独立性和备份恢复，使用现有状态表及04C/05B/07E实现，本轮补查读取一致性和旧来源直达。
- 04B推荐执行与精确自由输入走同一服务；04D模型候选额外绑定来源消息、输入和版本。地图浏览不发送行动；停止、断线、重放及费用处理沿用04C的事务和请求状态。
- 推荐由作者规则和当前版本计算，不声称是模型依据最新消息自动生成的推荐。模型候选的确认是独立显式操作，仍沿用通常生成计费。
- 两种机制的验证分别检查资源/地图和日常关系/约定；没有给日常卡添加好感分数或虚构地图。受控模型证明工程链路，不证明全部叙事表现。
- 位置字段隐藏于概况列表不等于作者配置的已知地图也必须隐藏当前位置；地图按节点可见条件过滤位置标记、节点及连接。该既有语义保持不变。
- OPEN-02仍保留“填入输入框”和“执行”两入口，未代用户签收默认交互；06纠正/回退/分支、多人原生规则和完整07D分别保持原状态。

## 已发现失败与处理

1. [类型检查失败](evidence/story-state-action-04ab-type-first-failure.txt)发现阅读导出传入已有事务，初稿却要求完整数据库对象。改为复用导出自身的读取事务，类型检查及导出恢复回归通过。
2. 初稿把概况列表的隐藏位置当成地图必须隐藏的位置，导致原示例[恢复断言失败](evidence/story-state-action-04ab-map-first-failure.txt)。核对原卡和协议后撤回这项不兼容变化，保留未发现节点过滤并补测试；没有通过修改测试预期掩盖地图回归，也未修改现有存档。
3. 首次手机浏览器检查发现来源请求成功后焦点未移入结果，Escape没有关闭面板。补上可聚焦来源区域及焦点移动，再用实际键盘Escape验证返回开关。
4. 完整入口回归发现模拟供应商只识别第一轮“先别出发，问问林澈消息来源。”，遗漏第二轮“现在再核对消息来源。”的提示词校验，因此两次计费成功但严格校验计数仍为1，断言要求2而失败。已让两句输入均检查冻结身份、角色语气和世界书，并把计数放在全部校验通过之后；保持原断言不变。该次[失败证据](evidence/story-state-action-04ab-entry-first-failure.json)保留，最终结果以修复后重跑为准。
5. 第二轮完整入口回归确认新故事页面仍调用旧记忆接口，被隔离保护返回409，导致无失败请求的断言不通过。[第二次失败](evidence/story-state-action-04ab-entry-second-failure.json)表明它必须在本工作包处理。初次记录只存pathname而误判为未带故事范围；源码确认实际传了chatId，问题是接口世代错误。修复ChatWindow预加载和工具面板，保留服务端409及原零失败断言；新旧故事切换单元测试、完整入口第三轮及实际候选工具复验通过。
6. 首次部署验收错误地将SQL预写等同于不会触发模型调用，遗漏了数据库的记忆派生触发器。它创建7项任务，6项已被后台尝试，其中5项提取成功后嵌入失败，1项提取失败。原零调用结论撤回；保留[首次报告及更正](evidence/story-state-action-04ab-deployed-first-invalidated.json)。修正版在预写事务提交前统一延期合成任务，另建安全夹具，检查重启前后7项任务attempts=0、due=0。原夹具的任务、尝试及提取检查点保留，不清空记录掩盖事故。

原合成故事7项任务的到期时间已改至2099年，保留6次尝试与5份提取检查点，确认无运行中或到期任务。[最终隔离复核](evidence/story-state-action-04ab-containment-final.json)确认原夹具尝试仍为6、新夹具仍为0，平台计账保持8,633。后续夹具必须在同一事务内隔离派生任务，并验证尝试次数，不能以没有生成请求记录推断没有后台花费。后续付费验证需要新增授权；其余不调用付费模型的开发可继续。合成事件、受控供应商以及意外的记忆提取均不得冒充新的真实连续游玩质量证据。
