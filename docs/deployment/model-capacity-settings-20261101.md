# 模型容量参数与远程配置

日期：2026-11-01。对应 INV-05/08；用户要求后台可修改模型容量，并按供应商实际公布值更新远程配置。

## 可见行为

后台 `/admin/models` 每个模型分别显示可编辑的「上下文总上限」「最大输入（可选）」「模型最大输出」「每次输出额度」。高级容量 JSON 仍保留，与数字编辑共用同一份数据；保存、重新读取和重启恢复保留独立输入限制。

客户端和服务端共用容量校验：要求正安全整数，输入不超过总上下文，每次输出不超过模型输出能力，并为输入和缓冲保留空间。粘贴 JSON 的模型键首尾空格自动清理；清理后重名、未配置的模型、拼错字段会被拒绝，错误指出模型及字段。失败保留编辑内容，不回显密钥。

已有聊天上下文、概括和故事记忆上下文检查使用独立输入上限，并同时预留请求输出与 100 token 缓冲。此修改不代表所有通用模型调用入口均增加了统一预检，也不保证供应商精确分词与本地估算一致。

## 容量依据

用户提供的[中转站说明入口](https://code.mmkg.cloud/custom/6fb5f5c7645ba27e)链接至[价格与模型页面](https://code.mmkg.cloud/pricing)。核对其公开数据源：

- [模型定价 JSON](https://code.mmkg.cloud/pricing/api/model_pricing.json)：三个 Claude 的精确模型名均有 `max_input_tokens=1000000`、`max_output_tokens=128000`。
- [动态价格数据](https://code.mmkg.cloud/portal-api/pricing-data)：Haiku/Sonnet 的上述容量一致；Opus 容量为空，以前一项明确字段为依据。
- `glm-5.3-flash` 动态容量字段为空，静态数据未找到精确条目；认证模型列表与单模型元数据返回模型标识，未提供容量。不能用 `glm-5.3` 或相似名称推定它的限制。

这些是中转站公布的规格，未独立验证实际上游型号，也未进行极限长度压力测试。来源未单独声明合并输入与输出后的总上下文；应用保守设置总窗口为 1,000,000，并从该窗口内预留输出，不能把它称作已验证的供应商合并窗口。未公布实际最小输入/输出；表单的最小值 1 只是应用校验规则。

下表为首次发布时的配置；GLM 后续按官网调整，见文末补充。

| 远程模型 | 应用总上下文 | 独立最大输入 | 模型最大输出 | 每次输出额度 | 依据 |
| --- | ---: | ---: | ---: | ---: | --- |
| claude-opus-5-5 | 1,000,000 | 1,000,000 | 128,000 | 10,000 | 中转站公布输入/输出；总窗口为保守策略 |
| claude-haiku-5-5 | 1,000,000 | 1,000,000 | 128,000 | 10,000 | 同上 |
| claude-sonnet-5-5 | 1,000,000 | 1,000,000 | 128,000 | 10,000 | 同上 |
| glm-5.3-flash | 500,000 | 未提供 | 100,000 | 10,000 | 保留原手填值，容量待核实 |

输出能力与请求策略分开：128,000 不意味着每轮请求这一长度。外部 API/高级 JSON 的 `maxOutputTokens` 为模型能力，`requestOutputTokens` 为每次额度；内部持久化分别映射到 `outputCapabilityTokens` 和 `maxOutputTokens`，避免更改旧配置语义。
