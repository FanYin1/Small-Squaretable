# 旧备份恢复后的故事删除重放

2026-10-25补充：现有可信源库路径保留，已新增[独立删除快照及恢复脚本接入](story-lifecycle-07e.md)，16组生命周期、9组重放及16项脚本流程检查通过。07E工程收尾已交付；缺最新可信证据或仅有迁移前无凭据旧档时仍不能无条件恢复开放。以下“尚未完成独立灾备”须区分新快照工具与仍未提供的实时灾备订阅，不把快照截止时点之后的未知删除说成已覆盖。

日期：2026-10-24。对应 EXP-07E、INV-01/04/09、EX-12。源码及隔离数据库验证已完成，本机3080/3081未执行本轮迁移或更新；完整生命周期任务仍见 [backlog](../product/backlog.md)。

## 解决的具体问题

以前删除故事会清理正文及关联状态/记忆，但恢复删除发生前的备份仍会带回这些内容。本轮在正常删除事务中保留最小删除凭据；恢复旧副本后，先从当前可信源库重放删除，再允许恢复工具报告成功。

这套机制需要保留最新源库，源库可以只开放给维护工具，应用和后台写入应停止。凭据没有自动复制到独立灾备存储；源库也丢失、被旧备份覆盖或无法证明足够新时，不能将恢复副本直接开放。本轮不宣称完成了源库完全损毁的灾难恢复。

## 数据与迁移

新增主迁移 `0047_story_deletion_receipts.sql`，beta等价迁移 `0007_story_deletion_receipts.sql`；两份SQL一致，按各自迁移体系执行，不混用。当前候选仍运行此前的0000–0006，本轮没有操作其数据库。

| 数据 | 用途与边界 |
|---|---|
| `story_restore_lineage` | 为数据库建立一个随备份保留的来源标识；恢复目标必须和可信源库具有相同标识 |
| `story_id_reservations` | 保留已使用的故事ID；迁移时覆盖现有故事，新增故事自动占用ID，删除后不释放，防止旧快照事务或迟到插入复用已删除ID |
| `story_deletions` | 保存故事ID、租户/用户ID、删除时间、删除时仍关联的创建请求ID/输入摘要/创建时间；不保存正文、卡、世界书或向量 |

数据库删除触发器与正文/记忆级联在同一事务执行：删除回滚，凭据也回滚；正常仓储删除及账户级联产生的故事删除均能留下凭据。凭据和ID保留表不依赖用户或故事外键，不随其级联清理。普通UPDATE/DELETE/TRUNCATE不能修改这些记录；也禁止直接TRUNCATE聊天绕过逐故事删除，以及重写故事ID。

记录保留期限尚未定案，目前没有自动清理。回滚应用代码时应保留这些表与触发器，不能把移除删除证据当作普通回滚步骤。这里验证的是故事数据生命周期，不能替代账户全部数据、共享内容和交易记录的删除验收。

## 恢复操作

1. 保留一份已执行新迁移、具有最新删除记录的可信源库。停止源环境的应用/后台写入，恢复目标应用也保持离线；工具不会自动停止服务。不要覆盖这份唯一可信源库。
2. 按既有操作恢复到另一个数据库。`scripts/restore-db.sh` 的SQL及custom文件恢复路径现在强制执行删除前置校验和恢复后重放；交互模式也走相同路径，dry-run不执行数据库变更。
3. 前置校验读取PostgreSQL集群标识及数据库名，拒绝覆盖删除凭据的源库，同时检查源库的迁移、来源与凭据是否可读。该校验需要读取 `pg_control_system()` 的维护权限；权限不足时失败，不绕过。
4. 文件恢复完成后，目标保持离线，原脚本自动执行删除重放。SQL输入使用 `ON_ERROR_STOP`；重放失败返回非零退出码，不输出恢复完成。PITR入口仍只提供人工步骤，恢复后必须另行运行重放，不能把打印步骤当作完成。
5. 核对重放结果、剩余数据及服务健康后再开启目标访问；源环境保持停止写入，不能让源环境继续产生新的删除而目标已经切换。

原恢复脚本使用原有 `POSTGRES_HOST/PORT/DB/USER/PASSWORD` 指定目标，新增必填 `STORY_DELETION_SOURCE_DATABASE_URL` 指向可信源库。目标连接由脚本配置直接传给校验，不接受另一个目标URL偷偷替换正在恢复的数据库。凭据通过服务器环境配置提供，不写进日志或产品文档。

其他工具已恢复好且保持离线的目标，可设置 `STORY_DELETION_SOURCE_DATABASE_URL`、`STORY_DELETION_TARGET_DATABASE_URL` 后，从项目根目录执行：

```bash
npm run restore:story-deletions
```

该命令会实际删除目标中的已删除故事，只适用于维护中的恢复目标。它不是候选之间的常规同步命令；3080和3081现有独立候选不因此相互同步。

重放期间锁定源库的相关表，阻止故事/创建请求写入改变删除集合；目标表需要排他访问，忙碌时立即失败。所有目标变更在一个事务内完成：

- 拒绝来源标识不同、来源缺少目标已有凭据、所有者/租户冲突、创建请求摘要冲突的情况。
- 复制删除凭据及ID保留记录，删除旧备份中的对应故事，使正文、状态、历程、笔记、内容/世界书快照、记忆和向量按既有外键级联清理。
- 对备份后才创建、随后删除的故事，补回已删除的创建请求记录，防止旧请求以新故事重新执行。目标中已无所有者时，不补造账户，跳过的请求数单独报告；之后若再导入该账户，需要重新重放并验收。
- 失败整体回滚，重复执行不重复产生删除或创建记录。源库只读不修改。

`result: replayed` 仅表示这次快照的删除已重放，不能证明指定源库就是最新的，不能代替人工确认停写、来源可信及整个站点就绪。数据库管理员仍能通过移除触发器等特权操作绕过保护，这不是防篡改审计系统。
