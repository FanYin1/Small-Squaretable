## 已实现的代码修复

- 前端角色列表使用 `view=summary`：只返回展示字段和最多 500 字简介，不随列表发送完整 `cardData`、世界书和扩展设定。服务端先按原来源校验 presentation，再计算简介，未跳过有效性检查。
- 编辑和详情仍读完整卡片；私人库的发布预览、单卡导出改为操作时读取完整详情，避免将截短简介或缺失扩展字段保存/导出。
- 内嵌封面按需生成最大 480 × 480、编码体积不超过 32 KiB 的 WebP。只缓存有限数量派生图片、串行解码、限制输入大小/像素，不抓取远端 URL；坏图保留页面字首占位。原图和数据库不修改。
- 私人合集列表也使用摘要和小封面，并修正后端 `avatarUrl` 到客户端 `avatar` 的映射；聊天历史列表改用小封面。
- 角色统计直接执行计数，避免为了统计拉取最多 1000 张完整卡片；列表和总数查询并行。
- 旧版未指定 `view=summary` 的角色接口保留，以兼容既有调用；部署后浏览器需要加载新客户端。

### 公共脚本未压缩的追加定位与修复

独立浏览器资源计时发现：应用 JS 的实际 MIME 是 `text/javascript; charset=utf-8`，原 Nginx `gzip_types` 仅列 `application/javascript`，因而公共脚本未压缩。Element Plus 单脚本 transfer 约 880 KB、下载约 3.48 秒，是首次打开各页面的另一项可定位负担。

备份站点配置至远端 `nginx.before.conf`，在原 `gzip_types` 增加 `text/javascript`；`nginx -t` 通过后平滑 reload。公网实际 GET 验证 `Content-Encoding: gzip`、`Vary: Accept-Encoding`，同脚本传输主体由 880,177 降到 295,654 字节；没有改变 WebSocket、流式缓冲和超时设置。

同一浏览器脚本重新启动 Chromium、空缓存访问私人库：等待页面与后台请求静默由 5,738 降到 3,124 ms；有缓存再访问 1,645 ms（压缩修复前同项 1,414 ms，存在正常波动）。此计时包含 Playwright networkidle 的静默等待，不等同于首次绘制。修复后的冷页脚本和详情 compatibility 请求均成功，无页面异常或失败网络请求。对应 `browser-timing-before-js-gzip.json`、`browser-timing.json`；这个独立检查不是对原两尺寸旅程失败记录的覆盖。

复测时 app / ML / PostgreSQL / Redis 均健康，app、ML 重启计数 0，无 OOM；app 约 237 MiB、ML 约 376 MiB，内存 available 446 MiB。IO 压力在镜像构建中升高，结束后 avg10 归零；短时采样不能替代长期稳定性验证。

证据位于私有 `backups/exploration/latency-20261030/`：`before-api.json`、`after-api.json`、`warm-api.json`、`browser-report.json`、`browser-timing*.json`、两尺寸 10 张截图；原始登录信息和卡片响应仅保存在忽略目录，不进入产品文档。本轮无付费模型调用，不修改预算账本；真实模型多轮 / 记忆的既有未知用量阻塞仍保留。EXP-02 / EXP-07D 不因本次性能修复自动关闭。
