# 探索式角色体验：参考研究与页面讨论稿

记录日期：2026-10-22（UTC+8）。状态：保留原研究与草案；后续七页示例已获准作为开发参考，按 [实施计划](../product/exploration-implementation-plan.md) 推进。精确交互、生产效果与真机另行验收，本稿不代表生产页面已修改。

已确认方向以 [决策基线](../product/exploration-experience-baseline.md) 为准。本文回答如何将其转成页面，不创建一个固定世界观，不要求用户每次选世界，不把其他产品的功能当作本项目已实现。

## 1. 参考方法与边界

查阅相关产品的官方公开说明及部分官方配图。没有登录体验全部产品，没有进行付费功能、真机或所有现行 UI 的完整审计。过去发布的官方文章用于研究其公开描述的设计模式，不声称截图代表当前每一端的最终界面。功能知名度或品牌规模不等于某种交互必然适合本项目。

来源按检索日记录，后续可能变化。以下链接为来源归档，用于复核功能事实；“如何应用”均为本项目提案。

### REF-01 Character.AI Scenes

官方 2025-10-16 文章描述：先浏览与预览情境，固定人物情境可直接进入；自由人物情境才额外选择人物。来源标题：Introducing Scenes: your new way to tell stories on c.ai。

```text
https://blog.character.ai/introducing-scenes-your-new-way-to-tell-stories-on-c-ai/
```

借鉴：内容入口清楚交代情境，固定配置少一步选择。应用到 DEC-03、10、13：本卡可直接开始时不强制选择背景；不照搬其所有人物混搭方式。

### REF-02 AI Dungeon

官方游玩说明区分 Do、Say、Story 等输入，以及 Continue；官方 Story Cards 说明资料可描述人物、地点和概念，按触发词进入上下文。

```text
https://help.aidungeon.com/faq/how-to-play
https://help.aidungeon.com/faq/story-cards
https://help.aidungeon.com/faq/the-basics
```

借鉴：让用户理解自己在行动或表达，区分故事参与和资料配置。应用到 DEC-04、05、11：推荐行动与自由输入在同一区域；是否增加 Do/Say 模式属于 OPEN-07，不直接复制整组按钮。其文本编辑机制不能直接证明本项目带数值的回退正确。

### REF-03 NovelAI

官方 Editor 说明以正文编辑区为主要工作区，并有分支式编辑历史；Story Settings 将记忆、作者说明与 Lorebook 快速入口放在右侧设置区域。

```text
https://docs.novelai.net/en/text/editor/
https://docs.novelai.net/en/text/editor/storysettings/
```

借鉴：正文优先、辅助资料按需展开、历史可理解。应用到 DEC-06、08：右侧优先给玩家状态和已知资料，模型与高级配置放设置；不把面向写作者的整套控制台作为玩家首屏。

### REF-04 SillyTavern World Info

官方说明将 World Info 作为动态资料注入机制，并支持人物、身份、会话等上下文绑定；资料不局限于世界背景。

```text
https://docs.sillytavern.app/usage/core-concepts/worldinfo/
```

借鉴：保留作者的资料组织与绑定表达能力。应用到 DEC-11、12：玩家默认看到“已使用本卡设定”，作者可以查看依赖与触发；不将全量配置面板放进快速开始流程。

### REF-05 Disco Elysium — The Final Cut

开发商在 Steam 商店说明中强调对话、观察、多种选择与探索城市。它是用户指定的体验参照，不是需要复制的网页模板。

```text
https://store.steampowered.com/app/632470/Disco_Elysium__The_Final_Cut/
```

借鉴：一段情境留下参与空间，通过行动逐步获取信息。应用到 DEC-04、05：观察/交流/行动的候选表达，不固定每轮三选项；不照搬游戏美术、完整技能树、固定剧本或未经实现的检定概率。

## 2. 提案总体结构

平台层负责找到内容、继续存档、管理创作和账户；游玩层负责当前情境、正文、行动与状态。两层共用品牌和基本操作，密度与布局按任务变化。

既有“我的故事 / 发现 / 创作 / 我的”暂作为导航基线。是否更名或重排属于 OPEN-03；本稿不把建议当作已批准路由修改。

## 3. P-01 发现与快速开始

关联：DEC-02、03、10。

- 首次进入：简短标题，少量经过验证的实例卡，搜索/浏览入口；导入自己的卡保留为次级操作。实例数量待定。
- 已有存档：首屏增加真实继续入口，显示有依据的停留处境，再提供新体验。
- 卡片优先展示封面、名称、我的起始位置/情境一句话、少量主题信息和开始操作。没有对应公开字段时保持简化，不从私密提示词截取。
- 固定开局且必要信息齐全时可以快捷开始；多开局或确需确认身份时只增加必要步骤。内容提示、认证或费用前提仍需在真实生效前说明。
- 详情是了解内容的补充入口，不强迫所有用户经过长篇介绍。
- 必画状态：无存档、无内容、筛选无结果、加载失败、卡不完整或缺必要依赖。

验收关注：第一次看到页面是否知道能玩什么、自己的位置是什么、如何开始，而不是先学模型和世界书术语。

## 4. P-02 体验预览与必要开局选择

关联：DEC-03、10、11、12、13。

- 预览：我是谁、眼前处境、可参与的事情、体验提示与已有存档入口。
- 作者提供多个开局时展示起点差异；名字与可修改身份简洁处理。
- 默认收起“体验设定”：本卡背景、人物资料、补充知识和规则。高级视图才显示文件、版本和依赖详情。
- 不出现默认必选“世界”下拉框。世界选择仅适用于基线规定的例外。
- 必画状态：固定背景、多个开局、可选补充资料、缺必要资料、已有存档继续/新开分离。

## 5. P-03 探索主界面

关联：DEC-04、05、06、07、INV-02、06、08。

细化讨论见 [P-03 布局与交互稿](exploration-play-screen.md)。用户同意继续讨论，本稿的具体布局和选项提交方式仍未签收。

桌面草图（结构提案，非尺寸定案）：

```text
┌────────────────────────────────────────────────────────┐
│ 返回我的故事  体验名 / 存档             保存状态  设置   │
├─────────────────────────────────┬──────────────────────┤
│ 当前地点 · 当前在场人物           │ 此次游玩             │
│                                 │ 概况 / 人物 / 物品   │
│ 叙述与角色对白                   │ 线索 / 地图          │
│ 用户已做出的行动                 │                      │
│ 本轮的观察或行动结果             │ 按卡显示真实内容     │
│                                 │ 可查看近期变化依据   │
│ 推荐行动                        │                      │
│ 自由表达输入                    │                      │
│ 发送/停止 · 清晰的费用入口        │                      │
└─────────────────────────────────┴──────────────────────┘
```

- 主体是连续剧情；区分旁白、人物对白和用户行动，但不为每句话增加大头像与独立卡片。
- 地点、人物及面板数据必须有真实依据。示例展示的“保存状态”只有在服务端确认相应内容后才能显示成功；未接通时原型明确标示模拟。
- 推荐选项描述意图，不预告隐藏结果，不固定数量，不制造不存在的成功率。点击立即执行或填入草稿属于 OPEN-02。
- 自由输入保持同等参与能力，可表达行动和对白；是否设置模式切换尚待讨论。
- 生成中允许停止；正文可以流式显示，未确认的状态不能装成已保存。失败保留输入，回包结果未知时先核对，不自动重发。
- 右侧为玩家资料窗口，技术调试和模型参数不常驻。没有地图/物品的卡不显示空壳模块；必要状态缺失时明确标记未知或同步异常。
- 纠正入口只预留讨论位置，不接假“修复成功”流程，也不提前实现未经确认的回退语义。

手机提案：保留正文、推荐行动与输入；状态窗口变为可展开的面板，打开时可切换人物/物品/地点，关闭后回到原阅读位置。避免同时打开面板和键盘挤压正文。最终形态、焦点行为与软键盘布局须在原型和真机验证。

## 6. P-04 我的故事与恢复

关联：DEC-07、08、INV-01、03、09。

- 每项对应独立存档，区分同一卡的多次游玩。
- 仅显示已有依据的最后地点、近期经过、未完成事项和最后活动时间；没有摘要时回退真实消息摘录。
- 继续回到已确认的剧情与状态；历史浏览和分支管理不冒充完整恢复机制。
- 保存异常、版本变化和未完成生成需要清晰表达，不能一律显示“已保存”。
- 表达风格与角色一致性属于后端与内容验收，不能用一个“长期记忆已开启”开关替代。

## 7. 视觉方向提案

沿用已认可的暖纸/暖黑、阅读字体与清晰强调色作为可复用基线，尚不新增品牌定案。首页通过真实封面与具体情境表达内容；主体验让正文与行动拥有最大注意力。

作者的世界个性先通过封面、少量局部场景和资料命名表达。不同卡不改变发送、返回、停止和查看状态等基础操作位置。避免把主体验做成数据仪表盘，也避免为了纯阅读隐藏用户明确要求的状态窗口。

颜色、留白和配图必须服务于信息结构；不以更换主题代替 DEC-04 至 DEC-08 的行为实现。外部产品图片仅用于研究，不复制进产品素材。

## 8. 下一轮讨论与交付方式

优先讨论 P-03：正文/推荐行动/自由输入/状态窗口的关系，确定桌面与手机结构，再校准 P-01 快速入口。2026-10-22 根据用户“给出一个示例”的要求，已制作 [独立交互示例](exploration-demo/README.md)，运行于本机 5188；未替换生产页面，具体视觉与选项提交方式仍待用户体验反馈。

原型至少使用两种机制不同的示例（例如有资源地图与只有人物关系的卡），题材尚未确认；覆盖空态、生成中、停止、失败、状态未知和恢复。示例不是上线内容承诺。

每页必须记录：对应决策、已确认与待定部分、真实接口需求、模拟数据范围、与生产差异、用户反馈。完成后才将已确认部分转为实现工作包。

2026-10-22 页面扩展：依据用户“给出各个页面的实例效果”，示例已扩为七类页面，覆盖 P-01 的发现与详情、P-02 的可选开局称呼、P-03 游玩、P-04 的两卡继续列表，并补充创作草稿和账户偏好。直达路径、各页可操作范围与截图见 [示例说明](exploration-demo/README.md)。这不是通用开局系统、完整存档管理或创作后台完成记录；所有页面仍待用户视觉评审。
