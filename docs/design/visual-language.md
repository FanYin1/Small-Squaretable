## 1. 设计语言的使用方式

设计文件、组件样板与实现采用同一组语义名。色彩实现来源是 [variables.css](../../src/client/styles/variables.css)，断点来源是 [_breakpoints.scss](../../src/client/styles/_breakpoints.scss)，主题解析来源是 [theme.ts](../../src/client/utils/theme.ts)。

规则优先级：用户确认的体验方向 → 本规范 → 页面局部设计。现有代码未达到规范时登记差异，不通过文档将其认定为已经完成。

| 维度 | 采用 | 避免 |
|---|---|---|
| 色彩 | 暖中性色、少量琥珀强调 | 全站霓虹渐变、每个题材改变整站主题 |
| 内容 | 封面、情境短句、舒适长文本 | 卡片塞满运营指标与功能标识 |
| 表面 | 明度分层、必要边界 | 多层玻璃模糊、大面积发光 |
| 排版 | 界面与阅读分开，层级明确 | 整页采用同一种小字号 |
| 动效 | 短促反馈、轻微过渡 | 自动视差、持续浮动、额外打字特效 |
| 图标 | 统一线性风格、清楚的名称 | 同一功能多套图标或含义不明的图形 |

强调色用于当前动作、选择与焦点。阅读区不把每个角色名、台词和链接都染成强调色。插画主要用于内容封面；登录、余额与设置以信息清晰为先。

## 2. 颜色与主题

### 2.1 基础语义令牌

以下为当前源码取值，不新增第二套故事颜色系统。

| 语义 | CSS 令牌 | 暗色 | 浅色 |
|---|---|---|---|
| 页面底 | `--bg-base` | `#0F0E0D` | `#FAF9F6` |
| 侧栏 / 次级底 | `--bg-subtle` | `#1A1918` | `#F5F3EF` |
| 面板 / 输入 / 弹层 | `--bg-surface` | `#242220` | `#FFFFFF` |
| 悬停表面 | `--bg-hover` | `#2D2B2A` | `#F0EDE8` |
| 图片占位底 | `--bg-sunken` | `#0A0908` | `#EFEDE8` |
| 主要文字 | `--text-primary` | `#F2EFEA` | `#2D2B2A` |
| 次要文字 | `--text-secondary` | `#C5C2BF` | `#57524E` |
| 说明 / 时间 | `--text-tertiary` | `#A39D98` | `#726D67` |
| 强调填充 | `--accent` | `#F59E0B` | `#D97706` |
| 强调文字 | `--accent-text` | `#F59E0B` | `#A55B05` |
| 强调填充上的文字 | `--accent-on` | `#1A1918` | `#1A1918` |
| 表单边界 | `--border-interactive` | `#847F7B` | `#93897A` |
| 普通分隔线 | `--border-default` | `rgba(242,239,234,.16)` | `#E8E5E0` |

普通强调文字取 `--accent-text`，主按钮底色取 `--accent`，其文字取 `--accent-on`。浅色下三个角色尤其不能混用。装饰线与控件边界也分开使用。

暗色层次依靠表面和边框，阴影只做辅助。浅色保留暖纸色页面底和白色内容面。侧栏、teleport 弹层、表单自动填充与原生控件都必须跟随主题。

### 2.2 对比度依据

下表数值来自当前源码已记录的计算，供设计沿用；本次文档交付不将它们当作新一轮浏览器测量结果。

| 组合 | 已记录对比度 | 使用结论 |
|---|---|---|
| 浅色强调字 `#A55B05` / 白色 | 5.12:1 | 可以用于普通文字 |
| 浅色强调字 / `#F5F3EF` | 4.62:1 | 可用于该次级表面 |
| 深炭字 `#1A1918` / 浅色琥珀 `#D97706` | 5.51:1 | 主按钮采用深色字 |
| 白字 / 浅色琥珀 | 3.19:1 | 不用于普通字号按钮文字 |
| 深炭字 / 暗色琥珀 `#F59E0B` | 8.17:1 | 暗色主按钮同样采用深色字 |
| 暗色三级字 `#A39D98` / `#2D2B2A` | 5.26:1 | 可用于说明信息 |
| 暗色交互边框 / `#2D2B2A` | 3.56:1 | 可用于控件识别边界 |

正文目标 ≥ 4.5:1；需要凭边界识别的控件与关键图标 ≥ 3:1。透明叠层、新背景和图片上的文字须按实际合成背景重新验证。不可通过降低整个容器 opacity 制造次要文字，这会同时降低图标和控件对比度。

`--text-faint` 仅用于纯装饰，不承载费用、错误、时间或输入提示。成功、警告、错误文字使用现有 `--color-*-text`，同时配文字或图标，不仅靠颜色。

### 2.3 主题行为

沿用当前规则：已保存的用户显式选择优先；否则系统明确偏好浅色时使用浅色；其余使用暗色。主题在首帧前设置到 `<html data-theme>`，与 TS 解析规则保持一致。

不因为进入某个故事而自动改变全站主题。封面可局部使用固定暗色遮罩，局部控件必须验证令牌级联。首版提供「浅色 / 暗色」；未来增加「跟随系统」时，须同步存储模型、首帧脚本和测试，不能只增加一个标签。

## 3. 字体与阅读排版

### 3.1 字体角色

| 角色 | 令牌 | 规范 |
|---|---|---|
| 导航、按钮、表单 | `--font-body` | Plus Jakarta Sans 与系统无衬线中文栈 |
| 故事标题、展示标题 | `--font-display` | Newsreader 与中文衬线回落栈 |
| 故事正文 | `--font-reading` | 当前继承展示字体，保持可独立调整 |
| 金额和用量 | 界面字体 | 等宽数字特性，避免数值刷新时跳动 |

中文回落沿用 Songti SC、Noto Serif CJK SC、Source Han Serif SC，并在通用 `serif` 前保留 PingFang SC、Microsoft YaHei 等无衬线兜底。不能删除这些回落而让中文依赖浏览器默认宋体。

首版不引入大型中文网络字体。后续引入时须核对许可、分片、显示策略和布局偏移。为阅读区提供无衬线字体选项是设计提案，不能描述为现有设置。

### 3.2 字号层级

| 用途 | 建议值 | 行高 / 说明 |
|---|---|---|
| 桌面详情大标题 | 32px | 1.25；长标题可换行 |
| 手机详情标题 | 24–28px | 1.3；避免挤掉主操作 |
| 页面标题 | 24px | 1.35 |
| 区块标题 | 18–20px | 1.4 |
| 卡片标题 | 20–24px | 1.3；最多两行 |
| 常规 UI | 14–16px | 1.5 |
| 说明文字 | 13–14px | 1.5；关键费用不小于 14px |
| 阅读正文 | 默认 17px | 当前支持 15/17/19px，行高 1.75 |
| 手机文本输入 | 至少 16px | 避免部分浏览器聚焦缩放 |

UI 字号与聊天字号分别控制，不修改 `--font-size-body` 来实现阅读放大。使用相对单位支持浏览器字体缩放；规格中的 px 是设计基准。

正文沿用 `--chat-measure: 36em`，17px 时约 612px。主要面向中文，一行约 36 个全角字符；西文实际字符数依字体而变，不承诺固定范围。窄屏自然折行。

段落间距建议 0.8–1em，不默认首行缩进，不使用强制两端对齐。长链接允许断行，代码块局部滚动，不能把整个页面撑宽。

### 3.3 台词、行动与旁白

正文使用主要文字色，Markdown `em` 所承载的动作描述使用 `--chat-action-color`。保留 `font-synthesis: none`，避免伪造中文斜体；西文可以使用字体提供的真实斜体。

模型输出未必遵循固定标记，前端只按明确的 Markdown 语义渲染，不猜测引号和人名给段落分类。角色区别在消息层显示发言者。

长篇叙事不统一放进高对比边框卡片；用户消息可用轻背景或左边界加强身份区别。弱气泡样式须比较多角色与连续短消息两种密度，验证发言者仍然清楚。

## 4. 空间、布局与响应式

### 4.1 间距和形状

使用 4px 基础步长，优先复用当前 `--spacing-xs/sm/md/lg/xl/2xl`，对应 4/8/16/24/32/48px。12px 等中间值仅在有明确需求的局部使用，不创建另一套全局体系。

| 对象 | 建议规格 |
|---|---|
| 手机页面左右边距 | 16px；极窄屏可降至 12px |
| 桌面内容边距 | 24–40px，随容器变化 |
| 发现页内容最大宽度 | 1200px |
| 阅读区最大宽度 | 36em，外加工具与页面内边距 |
| 桌面会话侧栏 | 280px，复用现有令牌 |
| 页头 | 手机约 56px、桌面约 64px，允许长标题适配 |
| 普通按钮 / 输入 | 建议最小高度 44px |
| 主操作按钮 | 建议 48px |
| 标签 | 视觉高度 24–28px；可点击时扩展触控区域 |
| 故事卡圆角 | 20px，复用 `--radius-card` |
| 面板 / 输入容器圆角 | 10–16px，复用现有令牌 |
| 标签圆角 | 全圆或 6px，同一类保持一致 |

触控目标建议至少 44×44px，相邻小图标至少 8px 间距。图标本身可以只有 20px，点击区域仍需扩大。

### 4.2 断点

沿用现有 480、768、1024px 三个断点，不新增平行体系。

| 范围 | 导航 / 发现 | 阅读页 |
|---|---|---|
| <480px | 单列横向故事卡，主要导航底栏 | 单栏，侧栏抽屉，无常驻右栏 |
| 480–767px | 优先单列，改善封面比例 | 单栏，较宽阅读区域 |
| 768–1023px | 两列卡片，导航可折叠 | 会话抽屉，正文优先 |
| ≥1024px | 两至四列，取决于内容宽度 | 可常驻 280px 侧栏，设置按需打开 |

列数由卡片最小可读宽度和容器决定，不按屏幕宽度强制四列。宽屏也不默认同时常驻左右两个工具栏。

Sass 使用现有 `below(md)`、`from(md)`、`between(md, lg)`，767px 与 768px 两侧互补。现有代码采取桌面优先，不要求为了文档改为移动优先。CSS 自定义属性不能直接用在媒体查询条件中。

### 4.3 键盘与安全区

聊天页由页头、可滚动正文和输入区组成，优先使用 flex/grid 与 `min-height: 0` 控制单一正文滚动容器。采用动态视口高度并提供兼容回退；需要时结合 VisualViewport 校正，但必须真机验证，不能假定 `100dvh` 自动解决全部软键盘行为。

底部安全区使用 `env(safe-area-inset-bottom)`，输入框展开时发送/停止仍可见。进入会话后可隐藏全局底栏，通过返回和菜单访问其他页面，避免底栏与输入框争夺空间。

键盘打开不自动滚到错误消息位置，退出输入后保持阅读上下文。横屏、地址栏收起和浏览器缩放都纳入验收。

## 5. 封面、图像与背景

竖向封面建议 3:4；横向紧凑卡使用同源裁切，详情使用自适应大图。比例是布局提案，导入图片不需要强制重新上传。

所有图片声明尺寸或 `aspect-ratio`。使用 `object-fit: cover`，焦点优先作者指定；缺少焦点时使用默认并允许后续调整。人物脸部与标题尽量避免重叠，不同封面的裁切要逐类检查。

沿用 `--cover-scrim` 整图氛围遮罩与 `--cover-scrim-text` 文字区域遮罩。文字遮罩跟随内容高度，不只靠整图渐变保证可读性。至少用纯白、高亮复杂和深色图片验证叠字。

正文默认纯色。可选场景背景要有关闭入口、低干扰合成方式和对比度证据，不默认播放视频或音乐。

无图、加载中和失败都保持布局。图片为已有完整标题链接的装饰时替代文字可为空；独立角色图应有简短描述。图片来源与许可随内容交付记录维护。

## 6. 组件规范

### 6.1 按钮与链接

一个局部任务区保留一个主操作。主按钮为琥珀填充与深炭文字，次按钮使用表面和边界，文字按钮用于低优先级动作。删除采用危险语义色与明确文字。

状态包括默认、悬停、按下、焦点、加载和禁用。禁用原因在需要时提供邻近说明，不能只降透明度。导航使用链接，执行行为使用按钮。

加载保持按钮宽度，使用「正在进入」等真实动作名。防重复请求由状态与服务端能力共同保证，不只靠动画。

### 6.2 StoryCard（优先复用现有角色卡）

输入建议：角色标识、标题、情境、封面、标签、收藏状态。缺字段时按体验文档安全回退。最多三个标签，其余放详情。

主导航链接与收藏按钮独立，收藏不触发导航，不嵌套交互元素。hover 可有 2px 以内抬升或边框变化，键盘焦点同样明确。关键信息不能只在 hover 时出现。

### 6.3 ContinueStory（继续入口）

显示最近会话名称、角色、时间、简短摘录与继续操作，无会话时不占位。摘录取已存消息，纯文本化后展示，不执行内嵌 HTML，不额外触发付费摘要。

多个会话时主入口指向最近记录，提供全部列表。记录失效时显示可恢复的列表状态，不进入无限加载。

### 6.4 Message / ReadingArea

输入为消息、发言者、生成状态、可执行操作和费用状态。组件不自行发起生成或推断费用。

流式追加保持已有布局，不叠加打字动画；用户消息有姓名或「你」标识。工具通过 hover/focus 显示，手机提供永久更多入口。

Markdown、代码、公式与链接复用现有安全渲染链路。角色卡富文本的 iframe 沙箱不因视觉统一而放宽。

### 6.5 Composer（输入区）

初始约两行，随内容增长，最大建议为可见视口的 30% 且不超过 200px；到上限后内部滚动。需以真机键盘下的可用空间验证。

占位文案：「描述你的行动，或说出你的台词……」。标签或可访问名称独立存在，placeholder 不能代替。身份为次级操作，模型详情在页头或菜单，不重复堆叠。

生成时发送位置替换为停止。中文组合输入不发送，手机回车默认换行。失败保留草稿；已保存的用户消息不重复塞回草稿导致误重发。

### 6.6 开场与设置面板

身份确认、阅读设置与世界设定分开，每次只展开当前任务所需内容。手机用底部面板或全高抽屉，长内容不塞进矮弹窗。

打开后移动焦点并限制在弹层内，关闭后恢复触发元素焦点；支持 Escape，未保存修改按规则确认。背景滚动锁定须恢复，允许内部滚动，不嵌套多层抽屉。

### 6.7 费用与状态组件

余额区分可用与冻结；冻结解释为「生成中暂时预留」。结算区分已确认、核对中、未知与失败，未知不渲染为零。

采用 UI 字体和等宽数字。详情展示时间、模型、token 与计量来源；使用估算时标注。单次费用依赖服务端关联结果，不能通过两个余额快照相减推算，避免并发请求或充值造成错误。

### 6.8 表单、提示与空状态

标签常驻，错误邻近字段，提交失败给出总体反馈并定位首个错误。成功 toast 用于短暂确认；余额不足、断网与未保存内容使用持久状态区。

toast 不挡输入，同类错误合并，不为每个流片段弹出通知。骨架屏仅用于已知结构区域，减少动态效果时停止闪烁。空状态提供原因与下一步，不能把请求失败当作空列表。

## 7. 图标、动效与交互反馈

继续复用 Element Plus 图标，新增图标匹配线宽和视觉尺寸。常规 20px、辅助 16px、主触控可 24px；动作通过文字或 `aria-label` 提供名称。

| 动效 | 建议时长 | 行为 |
|---|---|---|
| 按钮悬停 / 按下 | 120–150ms | 颜色、边框或极小位移 |
| 卡片反馈 | 180–220ms | 小幅位移，不缩放文字 |
| 面板进入 | 200–240ms | 小距离位移与透明度 |
| 页面切换 | 150–200ms | 长聊天正文不整体滑动 |
| 流式输出 | 无额外打字动效 | 按真实内容到达追加 |

优先使用现有 `--transition-fast/normal/slow` 和缓动令牌。`prefers-reduced-motion` 下去掉位移与非必要动画，状态仍清楚可见。

不添加循环光效、强制背景运动、自动音效和发送后的庆祝动画。充值完成只需明确到账状态。

## 8. 文案与国际化

故事内容可以有文学表达，系统文案具体直接。关键操作使用进入、继续、停止、保存、查看点数等动作词，避免不能说明结果的宣传语。

| 场景 | 示例 |
|---|---|
| 无会话 | 你的第一段故事还没有开始。 |
| 无搜索结果 | 没有找到符合条件的故事。可以试试其他关键词。 |
| 等待回应 | 正在准备回应… |
| 长时间等待 | 响应时间较长，你可以继续等待或停止。 |
| 连接中断 | 连接已中断。重新连接后将检查已有记录。 |
| 费用未确认 | 本次消耗正在核对。 |
| 模型不可用 | 当前模型暂时不可用。你可以稍后重试或选择其他模型。 |

未知状态不承诺「没有扣费」「已自动恢复」「内容永不丢失」。文案服从真实持久化和结算结果。

UI 文案走现有 i18n，不拆词拼接句子；数字、日期和复数按 locale 处理。英文按钮更长时允许增长，不按中文字数固定宽度。用户创作内容不自动翻译或改写。

## 9. Element Plus 与自有组件边界

| 区域 | 实现策略 |
|---|---|
| 故事卡、消息阅读、输入与流式状态 | 在现有自有组件上迭代 |
| 登录、账户、创作表单 | Element Plus + 令牌映射 |
| 管理员与账本表格 | Element Plus，优先清晰度 |
| 下拉、菜单、弹窗、抽屉 | 复用现有成熟组件，验证焦点与移动端行为 |
| 图标、提示、分页 | 统一现有体系 |

通过公开 `--el-*` 变量适配，不依赖内部 DOM 类名做大面积 `:deep()` 改造。需要不同交互时提取自有组件，不为视觉统一重写所有表单。

主题挂根节点解决 teleport 继承；侧栏等独立令牌组显式映射。深色弹层不能出现浅色内层或不可辨认的选中项。

## 10. 实现约定与令牌治理

1. 新代码优先引用语义令牌，不在页面重复写颜色与字体。
2. `--chat-*` 负责阅读，`--font-size-body` 负责 UI，两者互不替代。
3. 组件名说明职责，避免按某轮迭代或皮肤命名。
4. 全局主题放令牌，局部布局放组件，不复制两套主题判断。
5. 遗留别名逐步收口；删除前搜索 TS、Vue、样式与运行时引用。
6. 保留现有对比度与字体回落推导；新增颜色记录用途和测量组合，可记录在设计文档，不强制添加代码注释。
7. 本文不要求新增 UI 框架、字体服务、动画库或全站重写。

建议样板覆盖 Button、StoryCard、ContinueStory、Message、Composer、IdentityPanel、GenerationStatus、CreditsSummary 八类职责；名称是设计提案，可以复用既有文件，不要求逐一新建。

## 11. 可访问性验收

- 使用现有双环 `--focus-ring`，不能去除 outline 后不提供替代。
- 操作可用键盘完成，图标有名称；选中、错误和禁用不只依靠颜色。
- 对话框焦点进入、约束和关闭恢复完整；抽屉、菜单支持 Escape。
- 流式正文不逐字播报，独立状态区域适度通知；焦点不随新消息跳动。
- 触控不依赖 hover，长按不是唯一入口；保留文本选择与浏览器缩放。
- 200% 缩放和 320px 宽度仍可使用核心操作，表格、代码局部滚动不传播到页面。
- 中文、英文、长名字、长标题、无封面与大字号分别检查。
- 弱网、存储不可用、图片失败、减少动态效果均有可用界面。

自动对比度检查、键盘检查与真机体验共同验收。截图不能证明输入法、屏幕阅读器或软键盘行为正确。

## 12. 设计与前端交付清单

关键页面交付暗浅两套、390px 与 1440px 主视图，并说明 768/1024px 转换；另在 360px、320px 和 200% 缩放验证重排。

交付包包含：

- 颜色、字号、间距、图片比例与现有令牌映射。
- 输入法、发送、停止、历史滚动、返回恢复和费用查询行为。
- fixture 与真实内容的区分，缺字段时的回退。
- 视觉差异截图、目标设备检查记录与已知限制。

样板覆盖都市悬疑、奇幻冒险和日常关系三类内容，使用同一套 UI，验证视觉语言没有绑定单一题材。上线同时参考[体验交付验收矩阵](../product/story-experience-design.md#14-前端交付验收矩阵)。

## 13. 修订与待验证项
