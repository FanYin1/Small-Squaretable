# 冻结规则存档：恢复、迁移与续玩

日期：2026-10-27。对应 EXP-ADAPT / AD-4、DEC-18/27、INV-01/04/09，补齐[仪式计数交付](story-ritual-delivery-20261027.md)留下的恢复验证边界。本包是管理员迁移工具修复与隔离验收，不增加角色卡适配种类，不关闭 AD-3 或父项。

## 本次实际效果

此前迁移器核对了快照、事件数量、消息与来源引用，却没有依据冻结规则重算状态。把已存力量改成600，甚至同时把事件增量改成600，结构仍可能合法；管理员导入后会继承错误数值。

现在导出、导入计划、实际写入前以及引用重映射后的校验，都会按事件版本重放冻结规则：校验行动条件、一次性行动、复合行动、每轮自动效果、每次差值、最终数值、完成记录和数值出处。中断或候选轮次不能制造变化，重复请求和重复回复来源被拒绝。失败不修成猜测值，也不写入目标故事。

原始 `kakaa.png` 的已适配故事已验证：已保存力量6，待确认与中断不增加；整库恢复或迁到另一账户后继续到9；重复提交不再增加。从第一轮建立分支时力量为3，分支继续到6，父档仍为9。迁移目标数据库重启后，父档继续到12、分支保持6，且可以再次导出。无需原适配任务表中的任务仍然存在，也不重新读取当前卡片来替换冻结规则。

这改变的是恢复可靠性，页面视觉和既有故事不会因此自动变化；本轮没有在3081替用户执行导入、恢复或修复。


- 修复位于工作区管理员工具 `scripts/story-transfer.mjs` 的共享校验入口，按[既有离线流程](../deployment/story-lifecycle-07e.md)运行；没有数据库迁移，也未重建容器镜像。3081仍为 `small-squaretable:exploration-20261027-ritual`（afe5522e11e1），3080未操作。
- 规则重放核对的是“存档与冻结规则一致”，不是对第三方作者来源的密码学认证；管理员仍需使用可信包和独立删除凭据。若规则及全部历史被一起恶意重写，不能凭内部一致性证明原始真实性。
- 整库恢复仍通过原有备份/摘要流程核对，本次新重放守卫位于单档迁移器；不宣称任意直接SQL恢复都自动执行它。
- 真实原卡用于导入和适配，剧情回复由测试程序受控提交；没有验证真实模型的长篇文风或数值叙述质量，也没有新增浏览器或人工体验签收。
- 新增付费调用0、个人点数调整0，未启动常驻付费worker。原预算账本和未知预留不改。
- 下一开发重点仍是 AD-3 有完整来源依据的条件/赋值/一次性/交易转换，以及 AD-5 真实模型玩法。四张用户卡的复杂持续机制和 EXP-07D-LOAD 偶发加载故障仍开放，不能用本包恢复检查替代。
