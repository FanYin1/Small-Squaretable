# 已适配原卡：真实模型短程游玩验收

对应 EXP-ADAPT / AD-5、DEC-18/27，使用既有精确版本 `kakaa.png`；不把此验收算作 AD-3 新增规则转换，也不改变“每个完整保存的确认轮次+3”的既有语义。

## 固定验收范围

| 编号 | 必须验证的用户行为 |
|---|---|
| GP-01 | 原始PNG经实际导入和检查后创建新故事；用户只询问、不执行行动，真实应用生成并保存回复，角色力量0→3；重复请求不生成或计数第二次 |
| GP-02 | 用户请求先确认行动；生成结果保存为候选，力量保持3；服务重启后仍待确认，用户明确确认后才继续到6，不泄漏候选中可能提前执行的正文 |
| GP-03 | 从第一轮建立独立分支，冻结力量3，真实模型续写后为6；父档的三轮记录及力量6不变，分支不读取父档未来消息 |
| GP-04 | 父档和分支在桌面、手机阅读页显示实际保存的回复和力量6；导航不会触发生成，无横向溢出 |

所有测试使用隔离数据库、Redis和注册账户，不调整凡音点数或生产故事。原卡、模型文本和截图只保留在私有证据。叙述输入要求简短、非露骨；完整文风、长程记忆、任意卡机制及用户签收不在四轮短测的证明范围。

## 执行和预算

先运行不调用供应商的完整预演，再以同一链路使用共享工程预算网关。原卡来源、生产提示词组装、WebSocket、协议解析、事务提交、扣费和浏览器读取都经过实际应用；真实模式不将离线回复直接写入数据库，也不以固定回复替代真实模型。

```bash
STORY_RITUAL_GAMEPLAY_CHECK=1 node scripts/exploration-entry-check.mjs --adapter
STORY_RITUAL_GAMEPLAY_CHECK=1 RITUAL_GAMEPLAY_GATEWAY_CONFIG=/private/gateway.env node scripts/exploration-entry-check.mjs --adapter
```

第一条应在未设置 `RITUAL_GAMEPLAY_GATEWAY_CONFIG` 的环境下运行。真实模式要求尚未使用、最多4请求且预留不超过180,000 token的批次；本次计划分配160,000，续用既有唯一工程账本。启动时验证网关身份与预算，失败不自动重开批次或重跑付费测试。流结束后只读等待回执核销，不重发模型请求；失败/未知按原账本保留。

完成后先检查实际回复的语义、数值、协议与体验，再记录工程结果和剩余问题；schema或状态检查通过不等于故事质量通过。关闭批次与网关，释放未用分配，未知预留保持。没有产品运行代码修改时，不为测试脚本重建3081候选。

## 身份声明续聊专项

对应RI-02/03/04/05、DEC-18/27和AD-5。在原命令额外设置`STORY_RITUAL_IDENTITY_GAMEPLAY_CHECK=1`，替换四轮输入，不增加调用数：

| 编号 | 验收行为 |
| --- | --- |
| IG-01 | 引述并否认自称，力量3、声明false且界面隐藏；重复请求不重复生成 |
| IG-02 | 完整输入“我是鸟神”，力量6、声明true且有保存依据；模型作出原卡对应回应，不授予世界能力或资产 |
| IG-03 | 重启服务，再普通聊天，力量9、声明仍true；实际回复保留原卡对应态度，不要求再次声明 |
| IG-04 | 从第一轮分支，力量3/false续写至6/false；模型不继承父档未来声明，父档仍9/true |
| IG-05 | 桌面与手机宽度读取父档9/true、分支6/隐藏声明；无横向溢出，导航不生成 |

自动状态断言和受控预演不能证明真实文风与态度。需复核四条真实回复及发往供应商的上下文，分别记录态度连续性、越权奖励、隐藏条件泄漏和未来消息污染；不因生成成功而自动判定这些语义通过。此专项不替代原GP-01至04的行动确认验收，也不关闭父任务。
