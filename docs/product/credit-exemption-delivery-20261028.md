# 指定账户无限点数交付

日期：2026-10-28。用户明确要求为指定账户开通无限额度；按此前点数语境将“无限段数”理解为“无限点数”。账户标识、授权前状态及实际截图仅保存在私有证据目录，不复制进产品文档。

## 实际效果

- 对明确授权的单人租户账户启用免扣点权限。零余额也能通过点数前置检查和预扣检查；普通账户继续原计费规则。
- 账户、点数页、故事入口与对话余额区显示“无限”，不制造一个巨大的有限余额；原有充值、扣费账本及普通用户角色保留。
- 生成仍建立预扣生命周期记录，结算保存输入/输出用量及消息关联，扣点为0；重复、过期结算及失败释放保持幂等。免扣点请求不占用充值余额。
- 模型用量计量、供应商额度、单次输出和安全限制仍有效；免扣点不改变工程模型测试预算。

## 权限与运维

授权存于租户设置中的`creditUnlimitedUserId`，必须匹配该租户唯一账户；其他账户或共享租户不获得权限。没有增加客户端可写授权接口；当前服务端没有对外开放租户设置修改入口。请求提供的同名结算标记不能覆盖服务端决定。

容器内管理员维护命令：`node scripts/credit-exemption.mjs grant <user-id>`，撤销使用`revoke`。仅持有服务器数据库凭据的操作员可执行；修改与审计在同一事务内，重复操作不重复审计。撤销后新请求恢复余额限制；已经预扣的免扣点请求按开始时权限完成结算。共享租户后来增加成员时不再接受新的免扣点请求。

免扣点用量保存在`credit_reservations.metadata`以及原有用量计量链路；点数账本仅保留实际金额变化，因此免扣点生成不会伪造充值或扣费流水。账户现有“扣点记录”不是所有免扣点调用的用量明细；如需面向用户展示完整免扣点用量，可单列后续需求。
