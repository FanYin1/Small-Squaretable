# EXP-03B-LEGACY 历史来源与差异恢复

2026-10-25。对应DEC-10/12/14、INV-03/07/09，保留[原审计要求](../deployment/character-import-audit.md)。本工作包工程收尾完成；[操作、实际效果及证据](../deployment/character-legacy-reconciliation.md)记录66项单元回归、20组真实CLI/数据库/接口及非空恢复验证。没有对现有用户资料执行修复，未声称来源不明记录已恢复。

## 原要求及处置

| 历史情况 | 明确的处置能力 |
| --- | --- |
| 仅旧包装/归档来源 | 操作者指定current、nested或archive来源；只复制该份书，不提升或覆盖角色正文 |
| 来源丢失/损坏 | 操作者提供原角色PNG/JSON或独立书JSON，并映射明确租户/所有者/角色ID；文件摘要参加复核，不按名称搜索 |
| 已编辑/内容差异 | 可保留编辑书并新增来源副本，或明确解绑被替代书；不覆写或删除原条目 |
| 重复书 | 明确选择保留的已有书，逐本声明其他绑定keep/detach；不自动去重 |
| 停用或错误作用域 | 显式选择已有书时，预览将启用并设为角色作用域；没有此选择不改变停用状态 |
| 所有权/租户冲突 | 拒绝整个计划，不迁移所有权或绕过权限；必须由有权操作者先复核来源及归属 |
| 原文件无法找回 | 无来源就不生成设定；保留待处理记录和明确错误 |

## 行为与验收约束

- 工具仅供持有数据库凭证的管理员离线使用，不是用户可调用的HTTP端点。每个请求限一张卡，不默认扫描库，不自动加载环境文件。
- plan只读；apply必须提供同一请求与预览指纹；receipt仅核对历史回执。所有报告仅新建0600文件，不输出角色/条目正文、文件路径或数据库密钥。
- 当前全部绑定必须在请求逐本声明，新增/修改/删除绑定、条目、来源和请求任何变化都使旧计划失效。来源摘要和绑定字段差异可复核，不把相似文本当作历史来源证明。
- 角色、绑定书、条目按固定顺序加锁，重复执行使用持久凭据；任意步骤失败事务回滚。复用已有修复回执表，以带版本命名空间的完整计划摘要作为键，不增加数据库迁移。
- 解绑不删除书或条目；解绑时将作用域设为character，防止旧global绑定在解绑后意外变成全局资料。此作用域变化必须包含在预览中。
- 已冻结的故事不写入、重算或升级；没有世界书/内容冻结快照的旧聊天可能动态读取当前资料，整个修复拒绝，不能承诺这种旧档自动安全。
- 隔离验收覆盖各类来源、选择冲突、绑定完整性、重复提交、条目与绑定竞态、故障回滚、报告故障重查、跨范围隔离、旧档不变及新开局读取。真实历史数据实际修复需具备具体来源和复核计划，不能用持续开发授权猜测用户历史意图。
