# 前端改版修改计划书

> 本文为已获授权的 R1–R5 历史改版范围。之后讨论的探索式体验以 [新决策基线](exploration-experience-baseline.md) 为准；不能用旧“仅前端 / 不新增 schema”的范围排除新需求，也不能将 R5 验证视为新系统已完成。新页面仍在 [讨论阶段](../design/exploration-page-proposal.md)。

日期：2026-10-22（香港时间） · 版本：R5 候选执行记录 · 状态：R1–R4 生产改造已落地，R5 本机候选已部署；视觉与真机签收独立保留。

本轮实现、测试、镜像和逐页差异统一登记于 [R5 本机验收记录](../deployment/frontend-r5-acceptance.md)。下文 R0 的“仅演示 / 不替换服务”是当时计划交付边界，不是本轮已经获准的生产改造范围。

## 1. 目标与确认边界

将已确认的互动故事方向落实为生产界面，而不是给旧聊天工具换色。沿用原样板的暖黑 / 暖纸、琥珀强调、叙事排版、低干扰阅读与情境卡片，不重新发明一套品牌。

- 产品主线：发现故事 → 理解情境 → 确认身份 → 行动与回应 → 离开后继续 → 核对消费。
- 已确认基础：[体验设计](story-experience-design.md)、[视觉语言](../design/visual-language.md)、原 `public/story-experience-demo.html`。
- 本轮提出的具体导航分组、阅读工具收纳、空态与异常样式，以 R2 演示供再次核对。未得到确认不称为视觉验收通过。
- 范围是 Small Squaretable 网页；`/var/苏苏设计文档.md` 是另一产品，不作为本项目实现依据。
- R0 当时仅交付计划和独立演示。用户随后确认持续修改到 R5，本轮已改造并替换 3080 的生产前端；未迁移或清空现有业务数据，未消耗真实模型额度。

## 2. 当前差距与纠正原则

| 差距 | 原因 | 本轮必须纠正 |
|---|---|---|
| 故事页面套在旧后台式导航中 | 复用组件时保留旧信息架构 | 复用数据与权限，不保留不符合设计的组织方式 |
| 阅读页与发现页像两个产品 | Dashboard / Chat 布局独立演进 | 共用品牌、主导航与主题；阅读布局可不同但规则一致 |
| 参数、情绪、导出长期占据页头 | 技术能力直接暴露为一级操作 | 默认仅标题、返回、阅读设置；模型、记忆、导出分层访问 |
| 局部截图通过即称改版完成 | 缺少设计符合度验收 | 每页功能和视觉分别签收，保留对照图与差异说明 |
| 没有内容时看不到设计效果 | 只验证正常 fixture | 真实空库也必须有完整导航、解释和合法下一步 |

禁止用改名或换色替代结构改版；禁止把静态演示发布为正式产品；禁止用无来源的推荐、记忆、费用、关系数值填满页面。

## 3. 信息架构与路由

| 一级入口 | 路由 / 组件基础 | 内容与次级入口 | 返回规则 |
|---|---|---|---|
| 我的故事 | `/chat`、`Chat.vue` | 最近会话、摘要摘录、继续、开始新故事 | 无会话时进入明确空态；新建指向发现 |
| 发现 | `/market`、`Market.vue` | 搜索、题材、收藏、继续入口 | 从详情返回恢复查询、页码、滚动 |
| 创作 | `/my-characters`、`MyCharacters.vue` | 草稿、导入、编辑、世界书、预设 | 高级工具放在此分组，保留既有授权 |
| 我的 | `/profile`、`Profile.vue` | 点数、身份、阅读偏好、安全、帮助 | 点数查看保留故事返回地址，仅接受合法站内路径 |
| 阅读（子页面） | `/chat/:chatId`、`ChatWindow.vue` | 正文、行动输入、设置、账本入口 | 浏览器返回、直达深链接、刷新都可恢复当前会话 |
| 详情（子页面） | `/characters/:id`、`CharacterDetail.vue` | 公开情境、作者、开场、身份确认 | 有已验证历史时“继续”；“开始新的故事”不覆盖历史 |

移动端四项导航同名同序。阅读中隐藏常驻底栏，用“我的故事”返回与菜单保留导航，给输入和软键盘让出空间。桌面主导航收敛，最近故事列表只在需要时展开，不常驻两层宽侧栏挤压正文。768–1023px 优先正文，避免照搬 280px 常驻聊天侧栏。

登录、注册、帮助纳入同一设计语言；后台管理不强制故事化，权限入口不得因导航收纳而消失。旧 URL 保留，禁止为了视觉重命名全部路由或领域对象。

## 4. 逐页修改清单

### FE-01 应用整体布局与令牌（首批）

- 修改 `DashboardLayout.vue`、`LeftSidebar.vue`、`BottomTabBar.vue`、聊天布局及中英文导航文案。
- 提取共享主导航配置，合并主动路由匹配规则，解决“首页 / 会话”同时选中；只有一个主内容区域与一套移动导航。
- 主题、标题、间距、边框、触控尺寸统一复用现有 CSS 令牌；Element Plus 输入、弹层、选择框通过局部主题桥接，不全局暴力覆盖所有组件。
- 次级能力入口清单：身份→我的；世界书 / 预设→创作；模型 / 记忆 / 导出→阅读设置；管理员 / 可选模块仍按现有权限与开关过滤。
- 验收：四主入口一致，键盘焦点清楚、深链接选中正确；关闭可选模块不出现死入口；不同页面主题无跳变。

### FE-02 发现与故事列表

- 修改 `Market.vue`、`StoryCard.vue`、`FilterToolbar.vue`、`SearchCombo.vue`。
- 页面以“进入哪一段故事”为中心；搜索独立于继续阅读条，题材筛选紧凑、可清空；不从随机列表制造“精选”。
- 卡片统一封面比例、标题两行、公开简介、最多三标签、独立收藏、明确详情入口；坏图和无封面有稳定回退。
- 改造 `/chat` 无选中会话时的列表与空态：展示真实最后活动和可公开摘录，不额外调用模型生成标题。
- 验收：加载、无内容、无结果、网络失败四态可区分；账号切换无上个账号继续入口；返回不丢筛选和位置。

### FE-03 详情与身份确认

- 修改 `CharacterDetail.vue`、`PersonaSelector.vue` 与相关样式。
- 桌面封面 / 介绍双列，手机单列；清晰解释角色、情境、我的参与方式、开场、内容边界与费用。
- 只有已公开且权限允许的字段可展示；角色提示词不能直接截取当公开介绍。缺关系、钩子字段时省略，不伪造。
- 身份面板：已有身份、名字与简述、模型与余额；高级设置默认收起；取消不创建会话，不改变全局默认身份。
- 保留现有幂等创建、未知结果先核对、失败保留输入；可继续与新建分开，不为了 UI 动效重写请求流程。
- 验收：点击一次最多创建一个故事；已有会话返回链路正确；弹层焦点约束、Escape、关闭后焦点恢复通过。

### FE-04 阅读与输入（核心）

- 修改 `Chat.vue`、`ChatWindow.vue`、`ChatSidebar.vue`、`MessageBubble.vue`、`MessageInput.vue`、`ScrollToBottom.vue`。
- 页头以故事名和角色为主，不常驻 token 进度条、情绪状态、多组导出；模型仍可查看和切换，不能为“沉浸”隐瞒计费相关选择。
- 正文默认 17px、1.75 行高、约 36em 行宽；用户行动轻背景 / 边界，角色回复弱气泡；多角色仍清晰标注发言者。
- 阅读设置收纳字号、模型、世界设定 / 记忆、搜索、导出；保留已有管理功能与权限，不仅将按钮藏掉。
- 输入区显示身份、可用点数、发送 / 停止；建议行动仅填入草稿，不自动发送；中文输入法确认不触发发送。
- 前情回顾只在有真实摘要时展示，标明来源和覆盖范围，不新增无来源“场景编号”“记住了”等承诺。
- 验收：上翻阅读不被流式输出拉回；停止保留部分正文；断线不自动重发；草稿与消息按账号 / 会话隔离。

### FE-05 费用与异常状态

- 修改 `CreditsBalance.vue`、`Subscription.vue`，复用 `useStoryCredits` 和 credits API。
- 用真实余额、冻结、最近消费说明费用；尚无整轮汇总时保留“此故事最近一次消费”，不能换成“本轮费用”。
- 明细入口能返回原故事；页内错误可重试，不清空草稿；余额不足给点数入口而非失效按钮。
- 流水分页与精确消息定位作为独立工作包，先核实 API 支持范围；不耦合在首次视觉切换里。
- 验收：未知费用不显示 0，不在前端估算真实扣费，订阅模式隐藏点数；迟到响应不覆盖新账号状态。

### FE-06 创作、账户、认证与首次使用

- 改造 `MyCharacters.vue`、`CharacterEditor.vue`、`Profile.vue`、`auth/Login.vue`、`auth/Register.vue` 的整体布局和主操作层级。
- 首批保留现有编辑 / 导入 / 审核能力，统一样式；专用故事字段需单独 schema / 导入兼容方案，不在样式 PR 中偷偷新增字段。
- 编辑预览复用生产卡片与阅读展示，不复制第三套样式；草稿保存失败保留内容，发布确认遵循服务端审核。
- 首次引导最多三步、可跳过、按账号记录；不遮盖费用、输入和错误提示；无故事时解释如何发现或创作。
- 验收：登录后回到允许的目标页面；匿名、普通用户、作者、管理员权限分别检查。

## 5. 设计语言执行值

| 项目 | 约束 |
|---|---|
| 配色 | 现有暖黑 / 暖纸与琥珀令牌；不新增互相冲突的全局 palette |
| 字体 | 本地 Newsreader / Plus Jakarta Sans + 中文回落；正文支持 15 / 17 / 19px |
| 页面 | 发现最大 1200px；正文 36em；手机左右 16px，桌面 24–40px |
| 布局 | 480 / 768 / 1024px 断点；390 / 768 / 1440px 作为固定对照尺寸 |
| 控件 | 可操作区域至少 44×44px；圆角、阴影、焦点一致，不以颜色单独表达状态 |
| 对比度 | 常规文字至少 4.5:1，大字及关键非文本控件至少 3:1；深浅主题分别测量 |
| 动效 | 轻微过渡，支持 reduced-motion；不以逐字动画阻碍读屏，不自动滚动打断阅读 |
| 移动输入 | 使用动态视口与 safe-area；真机软键盘、横屏、长输入、200% 缩放补验 |

## 6. 接口、状态与安全边界

首批不新建 Story 后端领域模型，不改现有会话 ID、生成请求 ID、账本规则和租户隔离。所有前端重构必须保留业务测试。

| 状态 | 页面应如何表现 | 不允许 |
|---|---|---|
| 空库 / 无故事 | 清晰介绍、去发现 / 创作入口 | 用演示故事冒充已发布数据 |
| 等待回复 / 生成中 | 可停止，保留用户行动，适量状态提示 | 锁死导航或重复提交 |
| 已停止 | 保留部分正文，结算以账本返回为准 | 将停止误报为完全成功或免费 |
| 明确可重试失败 | 保留草稿、解释原因、按服务端许可重试 | 前端自行推测 retryable |
| 请求结果未知 | 先核对已有消息与生成状态 | 自动新建请求重发 |
| 余额不足 | 保留内容，展示查看点数入口 | 虚构充值、赠送点数或扣费成功 |
| 模型不可用 | 阅读历史仍可用，发送提示可理解原因 | 演示文本冒充 AI 回复 |

## 7. 阶段、依赖与预计工作量

工作量为单开发者有效工作日粗估，不是交付日期承诺。外部模型、用户审阅、真机反馈另计；发现后端缺字段时单列变更。

| 阶段 | 工作 | 依赖 | 粗估 | 必交证据 |
|---|---|---|---|---|
| R0 设计映射 | 本计划、演示、差异清单与用户确认 | 已确认旧方案 | 1–2 日 | 用户确认具体页面及允许偏差 |
| R1 统一整体布局 | FE-01，认证外壳，清点旧入口 | R0 | 2–3 日 | 四入口桌面 / 手机截图与路由测试 |
| R2 故事进入 | FE-02、FE-03，我的故事列表 | R1 | 3–4 日 | 发现到身份到阅读的真实 API 联调 |

| R4 配套体验 | FE-06、账户返回与引导 | R2、R3 | 2–3 日 | 空账号、作者、管理员操作验证 |

## 8. 测试与完成定义

每个工作包分别报告：设计对齐、数据接通、异常处理、自动化验证、人工验收、部署验证。六项不得相互代替。

- 单元 / 组件：导航选中、权限开关、主题、弹层焦点、输入法、草稿隔离、迟到响应、费用模式。
- 浏览器：发现→详情→身份→阅读→输入→停止→返回→继续；刷新、深链接、退登再登录、无内容、404、429、断网。
- 视觉：关键六类页面 × 三尺寸 × 两主题；同时保留设计样板与生产截图，逐项记录偏差，不能只检查无横向溢出。
- 数据：用独立库和受控模型复验创建幂等、停止正文、冻结释放、流水隔离；真实供应商验收单列，不与 fixture 混称。
- 人工：手机软键盘、读屏、200% 缩放、长中文标题、多角色长正文、无封面；必须由真实操作验证。
- 构建：`npm run type-check`、相关 Vitest / Playwright、定向 lint、生产构建；最终运行镜像与验收版本一致。
- 硬门槛：导航不能新旧并存；所有可见主操作有正确去向；不丢原功能；用户确认视觉后才能把“视觉完成”设为是。

### 验收登记模板

| 工作包 | 设计对齐 | 数据接通 | 异常处理 | 自动化 | 用户确认 | 部署版本 |
|---|---|---|---|---|---|---|
| R1–R4 生产改造 | 已按四主导航 / 故事卡片 / 阅读设置实现，逐页差异见 R5 记录 | 沿用真实 API；隔离镜像验证单列 | 幂等 / 草稿 / 账号隔离 / 点数模式保留回归 | 见 R5 最新记录 | 等待生产界面签收 | 已部署 beta.2-r5，镜像 ID 见 R5 记录 |

## 9. 实例演示与使用方式

文件：`docs/design/frontend-redesign-demo/`。启动：`npm run demo:frontend`，打开 `http://localhost:5187`。检查：`npm run demo:frontend:check`（先启动演示，需要 Playwright Chromium）。

演示保留旧样板不覆盖，新增版本支持：四主导航、搜索 / 题材筛选、故事详情、身份确认、开始新故事 / 继续、模拟逐字回复 / 停止、模拟失败 / 余额不足 / 空列表、阅读设置、点数说明、深浅主题。

演示的封面为 CSS 装饰、正文与金额为固定示例，不调用模型、不连接业务 API、不读认证数据、不写真实账本；浏览器刷新恢复初始样例。创作示例仅演示布局，不保存 / 发布内容。故障选择器是设计评审工具，不进入生产页面。3080 目前为生产 R5 本机候选，独立演示不打包进生产镜像。

建议验收顺序：先看发现页整体 → 点开故事 → 身份确认 → 阅读与设置 → 手机宽度 → 切换浅色 → 空态 / 异常 → 四个导航。请对布局与交互逐项确认，不能以一句“演示能打开”替代生产验收。

## 10. 实施与回退纪律

1. 每批只改一个完整体验切片，记录相关组件与保留能力，避免两个导航系统长期并存。
2. 新组件共用真实 composable / store，不复制生成与计费逻辑；界面 fixture 留在演示目录。
3. 每阶段演示部署前记录镜像 ID；不执行 `down -v`，不为前端改版清库。
4. 更改已确认布局或交互必须记录原因、影响和用户决定；不允许用开发便利静默替换。
5. 最终把本清单逐项回写到主开发计划；后续技术工作不得掩盖尚未签收的视觉差距。
