# 工作包 2：实际请求的提示词诊断

日期：2026-11-05。用户在工作包 1 交付后指示“继续下一个包”。对应 DEC-10/12/14/27、INV-01/03/04/07/08/09。前置交付见[世界书兼容与触发诊断](worldbook-compatibility-work-package-20261105.md)。

## 固定范围

本包交付单人聊天真实生成链路的**只读元数据诊断**：提示词来源、最终消息顺序、历史选择、记忆和世界书选入、模型容量以及上游请求指纹。不是提示词编辑器，也不是事后重新生成的预览。

对照本地 SillyTavern 1.19.0 的 `public/scripts/itemized-prompts.js` 和 `PromptManager.js`，借鉴按请求记录、按来源分段及按需检查的方式。SillyTavern 可在浏览器保存原始提示词；小小方桌有多用户和私有故事边界，本包使用经所有者授权的服务端短期元数据，不把原始设定或用户原文存入浏览器诊断库。

工作包 3 的单轮输出可靠性、工作包 4 的玩家/作者界面整理继续独立；群聊仍暂停。本包不更改提示词文本、消息选择策略、世界书抽样、记忆检索策略、原卡/旧故事规则和计费策略，不做生产迁移、自动重放或模型重试。

## 用户可见行为

聊天右上角“更多 → 本轮上下文诊断”，以及阅读设置中的上下文入口，打开同一个覆盖式抽屉。沿用暗幕、正文 inert、Esc 关闭、焦点返回；默认关闭，不占正文宽度。

- 按时间、用户消息 ID、模型选择最近请求；显示 requestId，避免把旧轮次误认为当前轮次。
- 显示布局、模板、总上下文、可选输入上限、最终解析的输出申请、输入估算、安全余量和深度注入预留。
- 显示实际读取/保留/本次省略的历史数量和消息 ID；省略仅影响本次上下文，不删除原始历史。已加入摘要单独标记。
- 展示裁剪和深度注入后的应用消息顺序、role、来源、深度、字符数和估算 token。
- 来源分段包含角色设定、示例、世界书位置/身份、行为指引、记忆和情绪；深度来源区分世界书、动态块、作者注释、历史后指令、角色深度提示及当前剧情状态。
- 显示本次选入的记忆 ID、数量和世界书扫描诊断。v2 记录逐条排除原因；v1 只呈现原扫描器已有统计，明确没有逐条排除记录，不重新扫描补造历史。
- 身份 revision、世界书 revision、内容/世界书快照 schema 版本和最终请求体 SHA-256 可用于对照。没有记录的信息显示未记录，不从当前资料补齐。

查看时只读已保存记录，不调用扫描器、宏、向量检索、模型或剧情写入。切换故事/账号、关闭/销毁抽屉、刷新时丢弃过期响应；失败清除旧结果并允许重试。新功能启用前的轮次不可回溯。

## 捕获位置与含义

1. `chat.service.ts` 在实际宏展开、世界书扫描和记忆选取完成后旁路整理元数据。原有返回的 systemPrompt 和 atDepthEntries 不变，诊断失败不改变生成。
2. `context-manager.service.ts` / `prompt-assembly.ts` 的真实深度插入过程通知观察器；用对象身份关联来源，不靠文本包含关系猜测，避免重复文本/相同深度误归因。历史使用本次已读分支中的消息对象。
3. `websocket.ts` 在现有裁剪、摘要、开局模式投影、控制协议追加和深度注入之后保存本次应用上下文引用；普通聊天与模板路径均接入，群聊不接入。
4. `llm.service.ts` 在容量/供应商预检和原生适配完成、`fetch` 前触发观察器：输出申请取最后解析的 `limits.maxOutputTokens`；对将发送的请求体计算字节数和指纹。覆盖 OpenAI 兼容聊天、文本模板、Anthropic、Gemini、Ollama。

记录阶段固定为 `upstream_request_prepared`：表示已组装上游请求，**不证明供应商接收成功、模型完成或剧情校验/提交成功**。上游 HTTP 错误仍可能有记录；容量、额度、认证配置或取消等前置失败可能没有记录。本包不存储模型回复或控制 JSON，不能用该记录重建历史格式错误。

消息顺序是适配器之前的应用消息。原生适配器可能合并 system/role，模板可能把消息拼成单段；字节数/指纹才对应适配后的请求体，不能称为逐项上游 JSON 查看器。分段数据在开局模式投影和平台控制协议追加之前生成，界面明确其阶段，不把分段估算之和当成最终请求量。

所有 token 数是现有保守估算，不是供应商 tokenizer、账单或缓存命中量。最终输入估算对模板使用格式化后的 prompt，对普通路径使用最终消息；不重复计入预留。容量及内容并未因为记录诊断被另设硬上限。

## 权限、存储及容量

- `GET /api/v1/chats/:id/prompt-traces`：登录后校验故事存在、userId 与 tenantId 均匹配，再读缓存；其他用户、其他租户及删除故事均返回 404。响应 `Cache-Control: no-store`，管理员身份也不自动绕过所有者校验。
- Redis 索引按租户/用户/故事隔离。每个故事最多 10 条，每条独立 TTL 24 小时；Lua 原子写入、裁剪索引并删除淘汰正文。后来的写入不延长旧记录 TTL，重复 ID 不制造重复项。只适用于项目现有单实例 Redis 连接方式，不声称支持 Redis Cluster 跨槽脚本。
- 不保存提示词正文、记忆正文、世界书内容/匹配关键词、响应原文、密钥、请求头、网关 URL；不向日志打印诊断载荷。不会在导出/分支/迁移中冒充永久剧情事实。
- 消息、历史 ID、世界书逐条诊断和来源明细有 200 条展示上限；数量统计和输入估算仍以完整本次请求计算，不影响模型实际输入。单记录最大 128 KiB，超限不写入。
- 写入异步执行、不等待 Redis 才发起模型请求；每进程最多 32 个未完成写入。读取最多 32 个未完成操作，300ms 超时返回可重试的诊断不可用。过载、Redis 故障或进程退出可能丢失诊断，不阻塞生成或改变其成功判定。
- 故事删除后立即因权限/存在性校验不可读取；残留缓存由独立 TTL 清理。本包不新增数据库表或迁移。
