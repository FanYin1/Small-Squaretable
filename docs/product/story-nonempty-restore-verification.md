## 样本与结果

机器可读记录：[非空恢复证据](../deployment/evidence/story-nonempty-restore-verification.json)。复现命令：在项目根目录执行 `npm run check:story-restore`；需已安装依赖、可用 Docker 及本地 `pgvector/pgvector:pg15` 镜像。脚本不自动拉取镜像。

备份时保留2个故事、6条原文、3个事件（2个已确认、1个中断）、1条风格笔记、2条有原文来源的记忆及2条向量。另一个故事在备份前已删除，保留创建请求的删除记录。开局后修改身份及世界书来源，用于确认旧故事快照不会跟随来源变化。

通过19项恢复行为检查、13项证据守卫测试、2项真实数据库损坏探针：

| 检查范围 | 已观察行为 |
|---|---|
| 完整性与来源 | 恢复前后集合行数和摘要一致，记忆关联同故事原文，事件关联输入和回复，状态依据指向已确认事件 |
| 非空与损坏检测 | 拒绝空消息/事件/记忆/向量、缺少覆盖、无效来源及旧报告格式；向量内容被改但行数不变、记忆指向其他故事原文均被发现；损坏探针事务回滚 |
| 冻结开局 | 身份、角色内容与绑定资料可读；身份描述、世界书条目仍使用开局快照 |
| 检索与隔离 | 真实 pgvector 查询找回对应故事记忆；相同向量的另一个故事单独检索，不串档；不同所有者读取失败 |
| 恢复后继续 | 已确认购买重放不重复产生事件；生成准备含已确认状态与风格笔记；新行动前往灯塔，版本2升为3，钱款保持100；消息序列分配新ID |
| 中断保留 | 备份前前往灯塔的中断事件恢复后仍为中断，位置保持码头；恢复后另行完成行动才改变位置 |
| 删除连续性 | 备份前删除的故事恢复后仍为已删除，重放创建请求被拒绝 |
| 恢复后删除 | 删除主故事后，正文、事件、状态、笔记、快照、记忆与向量均无残留；故事/全局记忆查询不返回其内容 |
| 迟到写入 | 删除后尝试写入派生记忆、提交预先准备的行动均被拒绝；另一个故事不受影响；目标库操作未改变源库 |

## 证据边界与后续

本轮直接调用实际服务和仓储，使用真实数据库；没有运行页面或HTTP生成链路。正文、派生记忆和384维非零向量均为受控样本，没有调用模型或嵌入供应商。因此证明的是保存内容的恢复、检索及后续状态提交，不证明模型自动抽取、长程对白质量或持久任务重试可靠性。

删除验证覆盖删除完成后的迟到写入和备份前删除记录，不覆盖所有并发锁顺序与后台任务竞态。尤其，恢复到删除发生之前的旧备份，仍可能带回后来删除的数据；当前没有跨备份保存并重放删除凭据的机制，不能承诺该场景不会复活内容。

EXP-07E继续开放：补用户可携带的完整故事导出/导入、旧备份恢复时的删除约束，以及生成/派生并发删除矩阵。EXP-05B继续补自动记忆持久进度、失败重放与来源追溯。本轮没有变更业务迁移、页面或运行中的3080/3081/5188，也不代表用户最终验收。
