# 分批摘要的保存、校验与续写

2026-10-25最新补充：05A工程收尾已部署3081。事实与摘要复用同一来源/知情复核，单人遗漏已修复；偏好独立取用仍受有界容量约束。既有20批候选/4批注入限制不变，不能将05A工程完成理解成递归全局摘要、无限记忆或人工质量签收。见[收尾结果](../deployment/story-memory-05a-completion.md)。下方未部署/05A未完成描述保留为历史。

日期：2026-10-24。对应 EXP-05A/05B、DEC-07/08、INV-01/03/09，涉及 EX-07/10/12。目标是让被容量裁剪的已确认经历仍有机会进入续写，保持约定与表达连续性。本次交付为源码和隔离验证；不关闭完整记忆验收或 OPEN-01 至 07。

## 玩家可感知的变化

继续较长故事时，如果早期五轮经历已有成功派生且原文校验有效，默认聊天生成可在容量允许时使用这批经历的摘要。当前状态、身份、手记、表达约定、最新完整轮次与置顶原文继续受保护。摘要不修改资产、地图、事件、原文或已确认状态，也不把未发生的承诺确认为结果。

本次没有新增页面按钮。既有记忆区仍展示整理进度和批次原文依据，不展示未经可见性分级的自动摘要正文；“已整理”也不代表该批必定进入每次生成。阅读导出仍不包含这些内部摘要。

## 持久化与来源

沿用 [持久任务](story-memory-durability.md)：每个故事、每位角色累计五次完整确认回应创建一批。一次抽取同时返回事实与摘要，保存在 `story_memory_jobs.extracted` 的版本化 JSON 检查点中：`{ version: 1, facts: [...], summary: { content, sourceMessageIds } }`。摘要最长1600字符，引用须在该批十条输入/回复内。

实际模型抽取要求此对象格式；既有事实数组检查点仍可恢复和完成派生，但不会补造摘要，也不自动重新调用模型。摘要抽取不新增一次模型请求；输出最多2000 token且不超过模型上限，输入先按现有估算检查容量。沿用平台辅助调用计量，不新增玩家正文扣费。

向量失败时检查点保留，但其中摘要尚不参与续写。只有事实/向量提交与任务成功完成后才可读取。来源校验、租约、重试上限、删除竞态和受控重放沿用原任务流程。

读取使用只读、可重复读事务，先检查故事归属与租户，再限定当前回应角色及成功任务。核对五个不同确认事件、同故事输入/回复、角色、请求号、状态版本、非中止输入以及原文SHA-256。来源改变、摘要格式损坏、引用越界、缺少指纹、任务未成功时跳过，不将其作为可信摘要注入。

## 续写选择与预算

1. 仅覆盖内容快照版本1的故事，以及单聊/群聊的默认聊天生成路径。自定义文本模板暂不接入；旧档不推测补写。
2. 先完成正常上下文选择。原文全部容纳时不另加摘要；仅在发生历史裁剪后查询最近20个成功对象检查点候选。
3. 一个候选的全部十条来源都必须存在于本次完整历史中，且均未保留在已选历史里。部分重叠、分支缺少来源的批次不加入。
4. 优先较新批次，最多4批；摘要预算不超过1024估算token或可用输入容量的25%，取较小值。每条说明及消息封装也计入预算。1600字符的合法摘要仍可能因实际容量不足而不使用。
5. 预留摘要容量重新选择原文；遇到固定资料、最新/置顶整轮等容量冲突，先放弃摘要。最终按事件版本恢复摘要顺序，再进行完整请求容量检查。
6. 注入内容标记为可能有误的历史派生资料，注明当前规则、确认状态、手记及原文优先。这是提示层的约束，不是已证明的模型事实裁决或防泄密机制。

上述接入独立于旧的 `buildContextWithSummarization` 方法；该旧方法仍不是WebSocket入口。预算通则见 [上下文容量保护](story-context-budget.md)。数据库读取故障会在正文预扣/生成前传播为请求失败，不承诺任何故障都静默回退；已经接受的用户输入仍按现有规则保存。

## 恢复与验证

不新增表或迁移，依赖0048/beta0008。完整数据库备份包含任务JSON及来源指纹；恢复后可复用新摘要检查点。删除故事级联删除任务和摘要；已删除故事的读取返回不存在。原备份删除保护仍依赖 [可信源库重放](../deployment/story-deletion-replay.md)。

- `npm run check:story-memory`：实际服务、数据库/pgvector、整库备份与异进程恢复；受控抽取验证新检查点恢复、未成功排除、来源变化排除、旧格式兼容、群聊角色隔离和删除。
- `npm run check:story-context`：真实HTTP/WebSocket/浏览器与账本链路；在一次性库中明确植入经来源校验的成功摘要，检查其出现在实际发给受控模型的续写请求中，再使来源指纹失效并验证下一次续写排除。该植入不冒充真实模型抽取。
- 定向单元：解析版本/引用、摘要与原文重叠、容量/置顶保护、时间顺序、抽取供应商边界、已有上下文及生成费用回归。

最终结果及源码/构建摘要见 [独立验证记录](../deployment/evidence/story-summary-lifecycle-verification.json)。历史记忆界面、持久任务和容量报告保留原记录，不用新的数量覆盖旧证据。

实际通过：6文件117项定向单元、42项持久记忆/读取检查、19项恢复行为、14项证据守卫、2项损坏探针，以及7组真实API/浏览器检查。类型、前后端生产构建、脚本语法检查通过，定向lint零错误2条既有警告。所有验证使用合成资料和受控服务；未执行真实供应商长程对话、全量单元或本机候选部署。
