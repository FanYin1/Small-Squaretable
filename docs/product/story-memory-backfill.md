# 已确认故事历史的记忆任务补建

日期：2026-10-24。对应 EXP-05B，关联 EXP-05A、DEC-07/08、INV-01/03/04/09、EX-07/10/12。本次补齐“已有确认事件，但持久记忆任务或未满批进度遗漏”的运维恢复环节，不关闭整个记忆工作包。

## 适用范围与玩家效果

适用于内容快照版本1、具有完整确认事件及输入/回复来源的故事，包括安装0048/beta0008之前已产生确认事件的故事。检查发现遗漏后，可补入待处理批次，后续由正常工作进程生成记忆与摘要；玩家沿用现有记忆区查看处理进度与原文依据。

普通旧聊天没有这种事件依据时明确拒绝，不从聊天文本猜造事件、状态或角色归属。此工具不把故事升级为版本1，不改写正文、事件、资产、地图、手记或已完成的派生内容，也不是纠正/分支操作。

## 检查与应用

入口 `npm run backfill:story-memory`。仅使用操作者显式提供的 `DATABASE_URL`，不自动读取候选环境配置。数据库凭据属于运维权限；这不是面向玩家的HTTP接口。每次必须明确一个故事和其中一个冻结角色。

默认只读检查：

```bash
npm run backfill:story-memory -- --chat <故事UUID> --character <冻结角色UUID>
```

返回确认回复数、已有任务数、当前未满批数量、遗漏回复数、本次计划新增批次数 `jobsToCreate`、后续待补批数 `deferredJobs`、补建后剩余进度，以及 `reviewHash`。默认单次最多100批，可用 `--max-jobs 1` 至 `--max-jobs 100` 调整，检查和应用必须使用相同上限。不输出正文、抽取内容、密钥或完整来源列表。检查使用只读可重复读事务，没有写入和模型调用。

核对具体结果后，以刚返回的指纹应用：

```bash
npm run backfill:story-memory -- --chat <故事UUID> --character <冻结角色UUID> --apply --expected-review <reviewHash>
```

应用只创建待处理任务及调整尚未入批的进度，返回 `createdJobs`。入队不等于整理成功；后续抽取/嵌入仍可能失败并产生既有平台辅助调用成本，不新增玩家正文扣费。工具没有跳过校验的 `--force`；缺指纹、未知参数或已过期的复核结果均拒绝。

## 补建规则

1. 确认故事版本、状态和冻结角色，再读取同故事的确认事件。输入必须为该故事用户消息，回复必须为该故事助手消息；核对角色、请求号、版本、确认标记以及输入未中止。发现损坏来源直接拒绝，不悄悄排除后声称覆盖完整。当前检查会保守核对同故事其他角色的确认来源，损坏也会阻止操作。
2. 已有任务无论等待、运行、重试、失败还是成功，其五条来源均算已覆盖。任务、检查点、失败次数和重放记录原样保留；失败任务仍使用 [原有重放流程](story-memory-durability.md)。
3. 检查任务间、任务与未满批进度间是否存在重复或非法来源。损坏、缺失、跨角色或跨故事引用不通过，不自动删改已有任务来凑齐覆盖。
4. 按确认事件版本，将尚未入任务的历史与原有未满批进度排序，每五条规划一批；本次按上限补建，其余完整批次留给下一次检查，真正不足五条的尾部保存为进度。已有批次不重新分组。后续新回应继续沿用原入队触发器。
5. 复核指纹包含故事/角色、状态版本、原文及事件元数据、已有任务来源与进度。新增轮次、来源变化或另一操作已补建后，旧指纹拒绝；任务自身运行状态变化不会重新计算历史覆盖。
6. 应用事务与正常剧情提交共用故事状态行锁，并保护故事、事件、原文及已有进度。所有新任务和进度一起提交；中途失败全部回滚。并发补建只允许一个复核结果生效，另一请求需重新检查。已删除故事不会复活。

后续扩展：事件和任务按200条分页扫描，数据库计算原文SHA-256，检查进程不再加载整段原文。当前保守限制为整个故事最多10万确认事件，选定角色最多2万个已有任务，一次应用最多100批；锁等待2秒，单SQL语句15秒。超过限制明确失败，没有静默截断或自动全库扫描。未入队批次显式计入 `deferredJobs`；再次检查并应用新复核结果即可继续。旧5000轮/200万字符限制已由该路径替代，原验证报告保留历史记录。

## 验证与部署边界

复现入口：`node --test scripts/story-memory-backfill.test.mjs` 和 `npm run check:story-memory`。后者使用一次性PostgreSQL/pgvector、实际创建/提交/工作进程，以及受控抽取与向量服务；明确删除隔离夹具中的任务/进度模拟历史遗漏，不操作真实故事。

覆盖只读检查、实际CLI参数保护、补建后正常派生、恢复进度后新轮次入队、重复应用、过期复核、并发补建、被占用的提交锁、群聊角色隔离、失败任务保留、第二批写失败整体回滚、中止排除、来源损坏和删除。独立结果见 [验证记录](../deployment/evidence/story-memory-backfill-verification.json)。既有持久任务、摘要与页面证据保留历史记录。

不新增迁移，依赖0048/beta0008。本轮不在真实候选库执行补建，3080/3081/5188不变，也不改玩家界面。补建不突破 [分批摘要](story-summary-lifecycle.md) 的候选数量和容量限制，不保证所有补建内容都进入每次续写。
