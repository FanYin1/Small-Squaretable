# 蔚蓝星域实际体验复盘与导入适配方案

日期：2026-10-26，香港时间。来源：用户要求给凡音点数、模拟实际卡片体验、反思旧市场及对话设计残留，并讨论LangChain/LangGraph适配agent。

## 本轮实际操作及证据边界

- 3081“凡音”到账100点，充值前可用0点、充值后可用100点；按当前10000 token/点换算，追加账本及系统审计记录，使用固定幂等键防重复。没有修改用户角色，也不是购买订单或供应商充值。私有回执在`backups/exploration/azure-trial-20261026/credit-receipt.json`。
- 使用实际07AC候选和已导入卡，检查详情、身份、旧入口、个人角色库，以及该卡已有的空故事。拦截浏览器业务写请求、WebSocket和外部资源；没有创建新故事、修改现有正文、发送模型消息或执行卡内脚本。
- 记录8张入口截图、10个开场在1440/390视口下的20张阅读截图。零浏览器异常/横向溢出不等于体验合格；下表列出实际发现的问题。[机器可读记录](../deployment/evidence/azure-experience-audit-20261026.json)包含私有截图位置。
- 入口检查拦截了旧入口自动创建请求，之后出现的恢复态是检查工具造成，不能当作生产故障。该轮同一浏览器上下文中的手机身份/旧入口截图受其影响，不作为独立正常入口证据。阅读页另起浏览器检查，不受此恢复态影响。
- 本轮模拟的是实际页面、开场切换和阅读，不是生成对话。没有调用付费模型，因此不能声称已经验证该卡的多轮叙事、人物一致性或记忆质量；用户允许模拟不意味着旧45万token预算自动重置。

## 已复现的问题

| ID | 现象、依据 | 对用户的影响 | 处理方向 |
| --- | --- | --- | --- |
| AZ-01 | `MyCharacters.vue`的开始聊天只传`characterId`，新StoryCard快进传`storyEntry: quick`；Chat据此选择不同开局流程 | 同一张卡从不同入口进入，身份准备与恢复界面不一致 | 统一所有入口到同一故事启动契约，补点击路径回归 |
| AZ-02 | 详情`storyText`仅替换姓名并截断，然后用文本插值显示`first_mes`；实际页面暴露`<VariableInsert>`及JSON | 用户先读到程序数据，页面极长；阅读渲染器却另行隐藏这些块，同一内容两套表现 | 共用“可读叙事/内部指令”的展示投影，在截断之前解析；源卡与上下文不因展示清理被改写 |
| AZ-03 | 卡的description和scenario均为空，尽管内嵌书共有122条、278542字符，首页/身份仍显示暂无描述 | 世界丰富但展示空洞，用户不知道玩什么 | 引入有来源的体验介绍字段与缺资料降级；不能直接把秘密设定或模型指令拼成宣传文案 |
| AZ-04 | 私有详情保留评分、两套统计、点赞/分享、评论；截图可见重复统计区域 | 导入个人体验卡仍像旧市场商品页面 | 私有体验页优先开局和继续；公开社区信息按使用场景另行呈现，作者工具收起 |
| AZ-05 | 默认开场实际为作者目录，需要在创建故事后点小箭头从1/10开始寻找9种开场 | 用户先确定身份再选故事身份，目录被当作剧情，缺乏对比信息 | 开局准备中呈现来源可追溯的开场列表、身份/处境/已声明资源；保留原文查看及未知字段，不自动替用户选开场 |
| AZ-06 | 相邻开场预览用删除符号的正则处理，实际显示`content`包装名称 | 看似修饰过仍有技术文本残留 | 与详情及正文复用同一展示投影，避免再写一套简单字符替换 |
| AZ-07 | 手机开场切换截图中，长文显示停在内部滚动区的后段；顶部标题重复折行 | 不容易从新开场起点阅读；标题占据正文空间 | 明确“切换开场回到开头”和“继续历史保持阅读位置”两种滚动规则，补窄屏标题和触屏检查 |
| AZ-08 | 外部变量声明未映射为本平台原生状态规则，概况只能提示本卡未定义数值规则 | 开场有资金、舰船等设定，面板却无法可靠显示或持续更新 | 明确区分静态背景、初始状态候选与可执行规则；建立适配产物及验证，不能只把JSON展示成看似实时的数值 |

10个开场每个均含一个VariableInsert块，原文长度5248至18952字符；另有4条正则规则和作者脚本声明。它是检验“能导入但不能完整体验”的有效样本，而不是理应自动兼容的简单文本卡。

## 为什么发生这种脱节

1. 工程工作把解析、持久化、隔离和页面组件接入分开完成，却缺少“导入一张真实复杂卡后，从资料库进入并选开场”的完整交付门槛。上一轮导入只核对卡、封面、条目与绑定，没有实际走完这个界面；应当在交付入口前完成这一检查。
2. 视觉改造替换了外层布局，保留旧市场的信息顺序和多个旧入口；组件存在或换色不证明用户任务已经迁移。实际3081已有新外观，不应将问题简单归因于用户访问旧端口或缓存。
3. 原生示例有干净的介绍、结构化规则和可用的状态，第三方卡却可能把目录、初始变量、正文和脚本混在同一字段。缺少统一的展示与运行适配层，导致各页面各自清洗、各自截断。
4. 既有“脚本暂不支持”的说明是准确边界，但大量兼容说明挤占了身份页，也不能补偿空简介、错误的信息层级或没有选择开场的体验。工程限制需让用户可理解，不能成为产品设计遗漏的替代交付。
5. 03B的文件导入证据依然有效；本轮问题不应靠重新命名该证据解决。AZ-01至07作为02/07D的具体缺口继续处理，AZ-08的通用框架转换属于需要明确范围的新适配提案。测试数和截图数不能作为体验完成率。

## 是否引入agent

建议引入一个受控的“角色卡适配工作流”，优先试验LangGraph编排；不把自由运行agent直接接到每轮聊天，也不让它静默重写源卡。LangChain可作为模型调用和结构化输出的接入层，是否采用取决于现有供应商协议、预算计量及错误恢复能否继续复用。框架选择不能替代AZ-01至07的确定性前端修复。

依据官方文档，LangGraph侧重状态工作流编排，可结合确定性步骤与模型步骤，也不强制依赖LangChain；持久化文档区分线程检查点和跨线程存储。interrupt可用于暂停等待复核，但恢复会重跑节点，所以写入/收费仍需业务幂等。LangChain结构化输出支持schema校验，但结构符合schema不代表故事事实正确。来源及抓取摘要见[官方资料记录](evidence/import-adapter-official-sources-20261026.json)，2026-10-26直接读取官方Markdown，未据第三方教程或旧版本印象定方案。

建议工作流：

```text
原件归档与哈希
  → 确定性解析、依赖与能力清单
  → 按开场/条目分类并提取候选
  → 生成体验介绍与开局说明候选
  → 编译到受限原生展示/状态协议
  → 来源、规则及隔离校验
  → 需决定的差异交由用户/作者复核
  → 发布版本化适配产物
```

模型只参与难以靠规则完成的归类和文字整理；格式读取、哈希、权限、数值类型、依赖绑定和事务提交仍由确定性代码完成。

## 适配产物，而不是修改原件

| 产物 | 用途与必须保存的信息 |
| --- | --- |
| 展示档案 | 封面引用、无剧透介绍、题材、体验方式、缺资料说明；逐字段记录来源位置与原文哈希，人工/模型来源可区分 |
| 开场档案 | 原始开场索引、名称、公开处境、身份约束、原文预览、可声明初始值；不同开场各自独立，不能把所有开场资产合并 |
| 运行候选 | 可识别的变量类型、单位、作用域、初始值及动作规则；状态初始化和后续更新规则分开验证，不因有初始JSON就承诺可持久自动更新 |
| 兼容报告 | 哪些解析/保留/展示/运行已验证，哪些只保留或需人工适配；版本差异、置信度与未解决冲突 |

每份产物绑定租户、卡片ID、源内容哈希、绑定世界书版本、适配器版本、模型/提示词版本和生成请求号。开局冻结选定产物版本；卡片或世界书改动只使新适配候选失效，不静默覆盖已有故事。

概况面板读取已确认的运行状态；资料介绍可以读取已审核的展示档案。剧情推进后，建议的变化仍经过现有事件校验和原子提交。LangGraph检查点只记录“适配工作到哪一步”，不成为金钱、地点、人物知情或剧情记忆的第二套真相。

## 具体约束与验收

- 原卡/世界书均是待处理资料，不是agent权限指令；不开放shell、网络、任意数据库或作者脚本执行工具。任意JS转换不纳入首批保证。
- 有来源不等于可向玩家公开：秘密条目、隐藏身份、未来剧情要有可见性处理，不能进入商店简介或其他人物上下文。来源缺失时保留缺失，不能用模型编造。
- 对《蔚蓝星域》先完成10个开场的来源映射和展示投影，再选一种有明确字段与规则依据的开场试运行；资金、道具、地点只有通过类型与规则验证后才能进入持久状态。
- 任务按源哈希与适配版本去重；有总预算、调用数及重试上限、取消和检查点。恢复时不得重复收费、重复创建世界书或重复发布；运行时继续使用现有供应商账本，不直接从LangChain旁路调用。
- 校验要覆盖有/无简介、目录型默认开场、多开场、纯文本、受支持原生规则、复杂脚本依赖；实际用户素材仅用于授权的私有测试，不默认发布为平台示例。
- 展示验收：无变量JSON/技术包装泄漏；所有入口同一开局流程；开场可对比且切换回到文本起点；无介绍时说明缺失或提供经审核介绍；窄屏真实操作可读。
- 运行验收：未执行的行动不改变状态，分开场不互相继承资产，状态/事件/记忆一致；无法转换的机制明确降级而非“通过”。生成介绍、转换规则、长程剧情分别验收，不混成一次模型调用成功。

## 推荐执行顺序

1. 先修复已复现的入口分流、详情内部数据泄漏、重复市场区块、开场预览与滚动；这些不依赖agent。
2. 定义展示档案/开场档案及其来源与版本契约，用当前卡做可审查的离线适配样例；先解决空介绍和开局不直观。
3. 通过小范围试验决定LangGraph接入，加入恢复、人工复核和预算；再拓展经过明确支持的状态规则转换。
4. 在隔离测试故事中做有预算的真实模型多轮验证，补人物、概况、进程和记忆证据；用户自己的体验点数与工程测试预算分开记录。

本轮完成点数发放、实际页面复现和方案归档；没有部署前端修复、安装LangChain/LangGraph、生成适配产物或进行模型质量验收。不能把本方案计为EXP-02/06/07D完成。
