## 用户可见变化

沿用故事页面已有导出入口，JSON、TXT和Markdown均通过 `GET /api/v1/chats/:id/export` 下载。此前只导出聊天正文，接口不接受页面已有的Markdown选项；现在三种格式均包含已保存的可读故事内容。TXT/Markdown明确说明文件用于阅读、不能恢复存档，附件只保留引用。

JSON保留 `chat`、`messages`、`messageCount`、`exportedAt`，新增 `format: small-squaretable.story-reading` 和 `version: 1`。它是版本化的玩家阅读格式，`scope.restorable` 明确为 `false`，没有接入导入接口或伪装成可恢复的完整备份。

| 内容 | 当前导出范围 |
|---|---|
| 身份与出场角色 | 开局冻结的身份姓名、描述、来源类型、修订和时间；冻结的角色ID和名称。旧故事没有快照时不按当前来源补造 |
| 正文 | 当前故事所有已保存的玩家/助手消息，按时间及ID排序；保留消息ID、人物ID、附件引用、时间和已有的已确认/中断标记 |
| 状态与地图 | 与现有玩家面板相同的可见字段、未知值、字段事件来源、可用行动和已知地图；不复制隐藏状态值或未发现地图节点 |
| 历程 | 导出全部玩家可见事件，按版本升序；保留已确认/中断状态、行动标签、结果、摘录及输入/回复来源，不受面板12条或接口单页30条限制 |
| 此次笔记 | 当前故事的笔记、风格偏好及未完成事项 |
| 版本依据 | 角色内容与世界书快照的协议版本、修订摘要；不包含原始作者设定和规则正文 |

原始角色卡、世界书条目、隐藏字段及规则、系统消息、消息内部扩展、原始派生记忆和向量、账户/账本不进入玩家阅读文件。派生记忆目前没有足够的玩家可见权限标记，因此不能把全量记忆表直接加入下载；这是导出边界，不能被描述成完整迁移已完成。管理员整库恢复仍见 [非空恢复验证](story-nonempty-restore-verification.md)。

## 一致性与错误处理

- 在同一个只读、可重复读事务中验证用户与租户归属，读取正文、快照、状态、全部事件及笔记。导出过程中提交的新行动不会混进旧版本记录，之后再导出才会包含新内容。
- 身份、角色和世界书从开局快照取得；来源修改不会改变旧故事的导出依据。声明已版本化却缺失快照时返回错误，不静默省略为成功文件。
- 未授权、不同租户或已删除故事不可下载；状态/快照故障保留相应错误状态，未知失败返回导出错误，避免把部分数据作为成功文件发送。
- 下载响应使用 `no-store` 和 `nosniff`，文件名移除控制字符。Markdown正文放入长度足够的代码围栏，保留原文，避免正文中的围栏或HTML变成导出页面结构。
- 一次导出代表该只读事务所见的已保存内容，不包含尚未落库的流式片段。已开始的合法快照读取可以完成；删除不会撤回此前已下载的文件。

## 验证与复现

`npm run check:story-export` 复用两个一次性数据库的非空恢复演练，再在恢复目标库运行额外的导出检查。只使用合成内容，不调用模型，不读取3080/3081业务数据，结束清理临时容器与转储。

本轮20项实际服务/数据库导出检查通过：142条可读正文、71个事件跨分页完整导出，来源引用可解析，停止标记保留，冻结身份和名称、状态与笔记正确；三种格式不含9类秘密标记；不同用户、租户和故事隔离；并发提交后旧导出仍为版本71，新导出完整包含版本72；旧故事不补造状态；缺失快照及已删除故事拒绝导出。

同时通过既有19项恢复行为、13项证据守卫、2项损坏探针，以及40项路由/状态单元测试（含8项新增导出路由检查）。类型检查和服务端构建通过；定向lint零错误，保留聊天路由已有的1条未使用变量警告。机器可读的数据库证据见 [导出验证报告](../deployment/evidence/story-reading-export-verification.json)，其中保留检查列表和源码摘要。

路由测试使用模拟的导出服务，数据库检查直接调用实际服务；两类证据分开，不冒充真实HTTP/浏览器全链路。未改动前端源码，未更新3081，也未完成用户下载交互验收。
