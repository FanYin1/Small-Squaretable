## 1. 本轮进入开发的依据

可以据此推进的方向：

- 四个主要入口为“我的故事 / 发现 / 创作 / 我的”；游玩时突出正文、行动与资料，减少平台导航占用。
- 发现可以快速开始；详情解释玩家身份、参与方式与随卡设定；已有可用身份时调整身份是可选操作。
- 探索页复用同一界面结构，推荐行动与自由输入并存；人物、物品、资源、地图按卡所需呈现。
- “我的故事”展示真实进度与继续入口；创作和账户分别使用真实草稿、权限与余额数据。
- 暖黑/暖纸、克制强调色、封面与阅读层级作为当前视觉参考；迁移时做同尺寸对照。

仍开放的事项：OPEN-01 纠正/回退/分支语义，OPEN-02 推荐点击提交方式，OPEN-04 状态与记忆详细协议，OPEN-05 首批兼容框架，OPEN-06 首发内容，OPEN-07 精确文案与首次使用细节。OPEN-03 的七页总体方向已有推进依据，精确尺寸、真机表现与生产效果仍需验收。未定项不阻塞无依赖的页面工作，也不能被开发者静默关闭。

## 4. 实施顺序与每批交付

### 第一批：EXP-07A，真实进入与继续流程

关联：DEC-03、10、12、13、14 / INV-05、08。本批为下一次实施的明确起点。

- 把示例的色彩语义、文字层级、卡片与页面间距映射到现有设计令牌；先比较普通正文、按钮、边界与焦点，避免新旧样式互相覆盖。
- 改造发现、详情、可选身份与我的故事，复用现有搜索、角色、人设、创建和列表 API。
- 保留旧深链接、搜索条件、身份读取失败、余额读取失败、创建结果未知与恢复路径。
- 真实账户继续使用现有鉴权；不把“本地旅人”“已带入设定”等演示文案无条件复制进生产。
- 已绑定内容尚无可信读取结果时，只显示可证实的信息；“绑定情况未读取”不能伪装成“没有绑定”。

预期触及：上述四页、StoryCard、PersonaSelector、useStoryCreationRecovery、公共导航/令牌及对应测试。是否需要额外接口由实际缺口决定，不为占位效果更改数据库。

本批验收：真实 API 下“发现 → 详情/直接开始 → 必要身份 → 创建一次 → 正文 → 返回列表 → 继续同一存档”；受控响应验证超时、重复点击和迟到响应；390/768/1440px × 明暗主题对照；键盘与输入法不回归。本批不宣称推荐行动、动态状态或长期记忆完成。

### 第二批：EXP-03A 与 EXP-04A，绑定和状态协议

关联：DEC-05 至 08、11、12 / INV-01、02、06 至 09。

- 以现有 chatId 为体验隔离边界，设计内容版本、绑定资料、公开状态字段、事件与来源的类型及持久化方案。
- 先写状态转移与权限测试，再接面板；关键状态的持久化不能仅落在带 TTL 的变量缓存中。
- 卡内背景、知识补充、规则和风格分开表示用途；明确绑定与版本，缺失或歧义可诊断，不从整个资料库猜配。
- 区分原始变量、已确认事实、玩家可见状态与模型推测；不将作者秘密、系统提示或人物未知信息直接显示。
- 在受控测试环境演练迁移、失败恢复与旧存档读取；老存档没有结构化状态时保持正文可读，按“尚未建立/未知”处理。

本批验收：状态可独立恢复，Redis 清理/进程重启不丢关键数据；同卡两档与不同用户隔离；资料绑定可解释；卡或世界书版本变化不静默重写已有存档。

### 第三批：EXP-04B 与 EXP-07B，探索游玩完整闭环

关联：DEC-04 至 07 / INV-02、04、05、06、08。

- 将正文、推荐行动、自由输入与资料窗口接入正式 Chat 页面；窄屏使用可关闭的资料面板，保留焦点与阅读位置。
- 推荐/自由输入共用同一发送、停止、幂等、错误与计费路径；推荐只传行动意图，不让客户端直接提交可信数值变更。
- 推荐绑定生成它的消息与状态版本；切档、旧分支或状态已变化后使其失效，不能用过期选项改写当前状态。
- 地图先验证地点/连接/可见范围；浏览与前往明确分开。无地图的卡不显示空地图面板。
- 流式正文与已确认状态区分展示；结果未知时查验原请求，不能自动重放付费生成。

本批验收：资源地图型与日常关系型两类代表卡均可完成多轮操作；状态由合法来源更新；重复提交、停止、连接中断、抽取失败与重试不造成双重变化或假保存。OPEN-02 的最终交互在接入推荐入口时单独记录，不扩大为所有界面待重新批准。

### 第四批：EXP-05A，连续记忆与约定

关联：DEC-07、08 / INV-01、03、04、09、10。

- 状态事实、经过记录、约定、风格偏好、阶段摘要分别有来源与版本；摘要是派生信息，不能吞掉原始事实依据。
- 审计检索、写入、相似去重、合并、配额清理的存档作用域；不能只给某个检索接口加 chatId。
- 设定冲突与新表达保留时间顺序，不静默改写已发生的约定；过期或失败摘要不得盖过新事件。
- 上下文装配优先保证必要设定、当前事实与未完成事项；模型无法容纳时显式降级，不能声称所有内容始终注入。

本批验收：固定脚本式长程用例检查事实恢复；模型体验用例检查人物表达与风格。覆盖离开/重启、上下文裁剪、同卡两档、用户切换、约定改期和摘要失败。受控模型和真实供应商的结论分别记录；不以一句“我记得”或检索方法存在代替验证。

### 第五批：EXP-03B 与 EXP-07C，创作、账户及代表卡兼容

关联：DEC-02、10 至 14 / INV-05、07、08、09。

- 将创作和账户页面迁移到真实功能；保留导入、草稿、编辑、预览、发布权限、点数与账本。
- 基于兼容研究选择代表卡，分别报告解析、保留、执行、界面呈现与游玩通过情况。
- 未知扩展保留并说明能力缺口；不执行来源不可信的作者脚本来证明“兼容”。处理沙箱与桥接能力后再进行受控脚本验证。
- 首批题材、内容授权与素材来源单列确认，不将两张原创演示卡自动视为首发内容。

本批验收：至少两类机制不同的代表卡完成导入到恢复流程；缺依赖和不支持规则有可理解诊断；真实保存/发布与本地预览的边界清楚。

### 第六批：EXP-07D，本机候选与交付

关联：DEC-14 / INV-08。

- 使用同内容、同尺寸、同主题建立原型/生产对照，每页记录差异及原因；不是只给一张新的首页截图。
- 先在隔离环境验证真实 API 与受控模型，再构建和部署本机候选，记录构建标识、迁移版本和访问入口。
- 保留旧候选的可恢复部署信息；数据库变化采用兼容迁移或恢复方案，不能假设回退镜像就能回退数据。
- 自动化、真实供应商、用户视觉与手机真机分别签收。外部模型额度/域名/邮件缺失只影响相应验收，不阻塞无依赖的前端工作。

用户已经选择先交付本机内测候选；此计划不把公网部署当作准备阶段或页面验收的前置条件。

## 5. 状态与行动接口的准备约束

以下是设计输入，尚未实现、未固定路径、未冻结数据库表名；在 EXP-04A 中形成实际共享类型、迁移与 API 合同。

| 数据 | 至少需要 | 必须避免 |
|---|---|---|
| 体验配置 | chatId、卡/世界书版本、绑定清单、公开能力和状态字段定义 | 用全局卡当前版本静默替换存档配置 |
| 玩家资料快照 | 状态版本、字段值与已知/未知标记、来源事件/消息、玩家可见范围 | 将空值当 0，或把所有 ERA 变量直接渲染给玩家 |
| 推荐行动 | 稳定 ID、显示文案、意图、来源消息、适用状态版本 | 模型返回一段文本就被当作可执行指令或可信奖励 |
| 用户行动 | 请求标识、chatId、推荐引用或自由文本、期望状态版本 | 同一点击走第二套计费或重复保存路径 |
| 单轮结果 | 原请求状态、正文标识、确认后的事件/状态版本、可追溯错误 | 前端收到局部文字即显示所有状态“已保存” |
| 连续记忆 | 存档作用域、来源与版本、经历/约定/摘要/风格的类型 | 以同角色相似度去重合并不同存档的事实 |

建议单轮顺序：验证身份/存档/请求 → 固定本轮输入及版本 → 生成正文和候选变化 → 校验可见性与规则 → 原子确认事件与状态 → 记录终态 → 更新派生记忆。模型网络调用不置于长数据库事务中；结算与上述提交的失败恢复必须另有明确协调方案。现有正文保存和账本流程需按失败矩阵评审后集成，不能照抄原型的一次内存赋值。

至少设计这些失败点：生成前拒绝、模型中途失败、停止、状态抽取失败、状态版本冲突、数据库提交失败、确认响应丢失、记忆派生失败。每项明确正文是否保留、状态是否确认、费用如何查验、用户能否重试、是否需先查询原请求。既有失败/重试语义不能被无意改写。

## 6. 避免再次出现设计与交付脱节

每个工作包的交付说明必须包含：

1. 对应 DEC / INV、原型页面与具体可见行为。
2. 实际文件、接口/数据来源、缺失时的展示；哪些是真实数据，哪些仅为测试替身。
3. 同尺寸的原型与正式页面证据；原型变化时记录理由及受影响页面。
4. 定向测试、浏览器行为与人工查看结果，及尚未验证的真实模型/真机部分。
5. 源码、构建、部署、用户验收分别处于什么状态；禁止把有组件或有截图直接改成任务完成。

具体异常验收包括：加载失败不装作空态、发送失败保留草稿、重复点击不多次建档/扣费、切档和切账号不接收旧回包、只读资料不生成、来源链接指向真实原文、未知状态不伪造、键盘焦点和移动端输入保持可用。
