日期：2026-10-24。活动任务 EXP-05B，关联 DEC-07/08、INV-01/03/09、EX-07/10。本次补齐生成请求的容量保护与可恢复提示；源码和隔离验证不等于3081部署或完整记忆系统验收。

## 玩家可见行为

角色资料、确认状态、表达约定与当前输入必须进入请求时，不能为了发出请求而静默丢弃其中一部分。固定资料或本轮输入超出当前模型容量时停止本次后续生成，显示原因。已保存原文、状态、事件、笔记和来源快照不被删改。

错误提示区提供“取回文字修改”。点击后将本轮文字追加到现有草稿并聚焦输入框，保留用户已经写下的新内容；不会自行发送，也不会重放旧行动或旧状态版本。用户修改后主动发送是一笔新的请求，原输入仍在历史里。切换故事或账号清除该恢复入口，迟到的其他故事错误不能覆盖当前页面。生成中不可取回。

该入口依赖当前页面持有的失败请求信息，刷新后不承诺自动重建错误提示；原文仍可查。恢复文字会受到现有输入长度限制，超出限制仍需修改后发送。本次未定义 OPEN-01 的纠错、回滚或分支交互。

## 请求预算与选择规则

1. 使用模型注册表的上下文窗口和输出上限，预留100 token缓冲。未知模型沿用既有4096窗口/2048输出回退值，不能据此猜测供应商实际能力。
2. 容量估算使用原有文本估算与 UTF-8 字节数除以3的较大值，并计入消息及会话封装。它改善无空格长串被严重低估的问题，仍是启发式估算，不是供应商分词器，也不保证精确边界。原计费估算函数保持不变。
3. 系统材料整体受保护；全部深度插入材料预留容量，包括世界书、作者说明及动态资料。无法容纳时返回 `critical`，不截断设定后继续生成。当前没有对系统材料内的可选片段再做优先级细分，因此可能保守拒绝。
4. 历史按用户输入开启的完整轮次选择；开场白可独立成块。最新一轮及包含置顶消息的整轮必须保留，分别超限时返回 `latest` / `pinned`。群聊本轮已经完成的回复也属于受保护内容。
5. 其余历史优先近期，再按重要度与新近程度选择，最终恢复原始时间顺序。不会单独留下被裁掉输入所对应的助手回答。被省略的仅是本次请求中的历史，数据库原文保留；省略提示自身也计入预算。
6. 深度材料实际插入后再次检查完整消息。文本模板只格式化已有完整消息一次，避免重复系统提示，并按实际格式化文本及2048输出上限检查。末端超限返回 `payload` / `template`。
7. 聊天流式调用显式发送输出上限。点数模式取模型上限与既有默认4096上限的较小值请求预扣，并尊重余额导致的进一步缩减；订阅模式也显式传递模型上限。没有借此提高既有点数输出额度。

`CONTEXT_BUDGET_EXCEEDED` 只返回原因和数值预算，不携带隐藏角色资料、系统提示或历史正文。错误不提供原样直接重试入口；修正输入或容量配置后再主动发送。

## 保存与费用边界

此检查发生在用户输入已接受、保存并计入消息配额之后。因此失败不等于未提交输入，也不等于所有资源用量为零。遭拒的这一角色尚未开始正文流式生成或正文预扣；群聊中此前已完成的其他角色回复和费用保持有效，不整体回滚。情绪分析、语义检索等前置辅助操作仍可能已执行。

确认状态、事件、行动后果不会因为容量拒绝而产生新提交。修改后发送使用现有请求及状态校验流程，不篡改原请求为“成功”。

## 验证方式

`npm run check:story-context` 构建当前服务端与生产前端，在回环55441/55442、一次性PostgreSQL/Redis 55448/55449验证真实 API、WebSocket、浏览器与数据库/账本效果。输入均为合成数据，模型为受控服务；使用既有默认容量小窗口便于确定性触发边界，禁用后台记忆任务消费以隔离正文请求计数，不修改正式环境配置或限流规则。脚本等待正常限流窗口，并拒绝意外429/5xx。

场景包括长输入拒绝后的保存/无正文扣费、追加取回草稿、缩短输入后续写、25轮合成历史与表达约定保留、窄屏作者资料超限。25轮历史由夹具直接写入隔离库，不是25轮真实模型对话，也不替代记忆任务或事件提交事务验收。

定向单元覆盖固定/最新/置顶材料、轮次顺序、深度插入、实际模板、输出上限、群聊部分完成、迟到错误、账号/故事隔离及组件取回交互。机器证据见 [容量验证记录](../deployment/evidence/story-context-budget-verification.json)。桌面1440×1000与移动视口390×844截图仅用于本次错误提示与恢复入口验收，不代表七页视觉或真实手机验收。

本轮实际结果：7个文件171项定向单元、5组真实API/浏览器容量检查、类型检查、前后端生产构建和脚本语法检查通过。隔离运行中的基础邀请注册、幂等创建、生成结算/重放、停止及失败释放检查也通过。定向lint零错误，保留8条既有警告；桌面和窄屏截图已检查，提示与恢复按钮可见。临时容器已清理；未跑全量单元或真实供应商长对话。
