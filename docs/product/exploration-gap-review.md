# 开发前回顾：遗漏、未展开与已知待定项

日期：2026-10-22。依据：用户要求“回顾一下，我们还是有什么没有涉及的或者遗漏的”。

性质：复核结论与补充建议，不自动新增已确认产品需求，不改变 DEC / INV，不关闭 OPEN 项，也不把建议全部设为首发阻塞。工作入口仍为 [活动待办](backlog.md)，正式实施顺序见 [实施计划](exploration-implementation-plan.md)。

后续记录（2026-10-22）：用户要求补齐这些方面，已形成 [体验补全方案](exploration-experience-contract.md)，逐项展开下方 GAP-01 至 09。本文保留当时的缺口判断；新稿只补方案与验收，不代表缺口已在生产中修复。

## 1. 总体判断

当前已覆盖七类页面、角色卡/世界书边界、状态持久化、统一行动、存档隔离、长期记忆方向、生产对照与本机交付。它们是必要基础。

主要不足是：工程和页面交付比较具体，核心体验的运行规则与成败判断还不够具体。完成七页和接口后，仍可能只有外观完整的角色聊天，未达到 DEC-01 的身份体验与 DEC-04 的探索推进。两张预写示例只能验证界面和固定分支，不能证明真实模型会理解自由行动、遵守人物边界或持续推进情境。

本次区分三种情况：真正需要补入的交付物；已经提过但没有可执行规则；已经明确待讨论/待实现的能力。避免把已有邀请码、计费、备份、删除等基础能力重新说成“从未考虑”。

## 3. 核心体验应怎样验收

下列是建议用例，不是用户已批准的固定评分表或通过率：

1. **用户拒绝推荐行动**：选择先休息或谈别的，角色作符合情境的回应；不能自动执行被拒绝的任务，也不必因此对用户无条件赞同。
2. **用户提出自己的行动**：明确复合行动、否定句、只问情况和真正尝试行动的区别。无法判断时保留参与空间，不能靠关键词匹配擅自推进。
3. **同一事件由不同人物回应**：维持各自身份、动机、知情范围与表达方式；不能所有人物都变成一种讨好语气。
4. **用户表达偏好或界限**：后续回应能体现已经明确表达的内容；不由模型擅自发明用户意愿或情感。
5. **不同选择留下不同结果**：正文、可见事实或后续互动至少有可解释的区别，不能只是换一句话后回到同一段落。
6. **行动未成功**：有基于设定的原因和后续参与空间；不随意给成功率，也不为推进剧情替用户选下一步。
7. **暂时没有明确目标**：允许闲谈、观察、等待；需要推进时给情境中的线索，不把所有卡改造成强制任务列表。
8. **离开之后继续**：不仅能读取历史，还能辨认上次处境、未完成事项、重要约定及下一步参与入口；回顾不能泄露隐藏信息。

上述用例将 DEC-01、04、05、08 与 INV-06、10 接到可观察行为。自动化可检查事实与提交约束，人物表现与参与感需要实际游玩评审；两类证据不能互相替代。

## 4. 探索与状态规则还需具体回答什么

### 4.1 谁负责推进

应区分当前场景提供线索、人物回应、环境变化、玩家决定与规则结算。模型不能在一轮里代替玩家完成多个尚未选择的行动。一次输入包含多件事时，何时按顺序处理、何时停在风险点，需按卡规则和明确意图确定，不由界面按钮数量决定。

场景什么时候结束、移动耗时是否有依据、等待是否推进时间、失败是否改变资源，都是玩法语义。此处不要求复刻完整游戏的技能、骰点、战斗或开放世界系统。

### 4.2 哪些信息可以成为事实

例如“他说仓库里有一百枚金币”可以成为“某人作了这一陈述”的记录，不能立即成为玩家背包有一百枚金币。尝试购买也不等于交易完成；计划前往也不等于位置已变。

作者规则、已确认事件、用户表达、模型推断发生冲突时，不能简单设定一个全局优先级解决所有字段。应按字段类型、行为权限和来源裁决；不确定时保留未知或待核对。具体协议仍属于 OPEN-04。

### 4.3 身份怎样影响体验

“称呼”“玩家身份”“能力/背景”“与角色既有关系”不是同一个字段。不同卡允许的自定义范围不同，应在不泄露设定的前提下解释限制。初次使用可以用合理默认值开始，深度调整保持可选；这也不意味着已授权新增繁重的人设编辑流程。

## 5. 已经登记，不能算作新发现的遗漏

- 纠正、重写、回退、分支仍是 OPEN-01 / EXP-06；本次再次确认其重要性，不替用户定案。
- 推荐点击立即提交还是填入草稿仍是 OPEN-02；示例的立即提交不是最终结论。
- 通用状态、单轮提交、长期记忆、存档隔离已有 EXP-04/05；此次补的是裁决、时序与体验验收细节。
- 世界书绑定、缺依赖、兼容分层、脚本隔离和首发内容已有明确入口；它们并非之前完全未涉及。
- 邀请码、真实费用、删除、导出和备份在旧工程或部署文档中已有记录；新增数据和页面仍需回归，不能由旧记录直接宣布覆盖。
- 真机软键盘、焦点、不同浏览器和视觉签收已有未完成声明；本次不把截图检查等同于这些能力已验证。

## 6. 对开发顺序的建议

EXP-07A 的无依赖页面与真实入口工作可以继续。建议在正式大范围接入探索状态前，先完成一个使用真实服务端持久化的最小完整体验：选卡 → 自由行动或推荐 → 人物回应 → 可追溯状态变化 → 离开 → 恢复。以受控模型验证规则与故障，再单列真实模型体验验证。

这个最小体验应包含拒绝推荐、自主行动、未知事实、失败/停止与重开隔离；不只复现预写示例的顺利分支。通过后再扩展剩余页面和卡适配，降低外观完成后才发现交互/数据协议不合适的风险。

建议先补四项具体材料：叙事行为约定、按卡身份与状态裁决表、端到端体验用例、生成耗时与费用时序。它们分别放入现有 EXP-04A/B、07A、05A 的实施说明，不需要另起一个无限扩张的新阶段。

这是一项顺序与验收建议，尚未作为已确认的新需求覆盖原计划。没有据此新增社交社区、语音、图片生成、完整战斗系统或复杂游戏编辑器；这些不是当前核心目标的必要前置条件。
