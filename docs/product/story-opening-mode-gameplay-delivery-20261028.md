# sans开局模式：真实游玩与叙事边界修复

2026-10-28。对应EXP-ADAPT/AD-5，DEC-05/06/08/18/20/23、INV-02/04/08/09。范围是已审核原卡的首次互斥模式选择，不包括战斗、生命值、EXP、后续升级或地图。AD-3/AD-5父任务保持开放，群聊暂停。

## 实际变化

原卡内强制追加生命值和Lv/EXP面板的指令，与平台仅支持开局记录的边界冲突。本轮在已冻结、校验通过的sans开局规则范围内，对发送给模型的作者提示建立派生投影：移除精确对应的旧数值面板模板、强制追加面板、自动经验升级和冲突的提示优先级声明，保留人物、世界、语气和其他作者内容。未改写原卡、绑定世界书、冻结快照或原始指纹，不对其他角色卡套用这些替换。

单人故事已保存的连续性和本轮批准结果改为最后的深度零系统消息，位于作者深度零提示之后，仍通过现有上下文预算及最终容量检查。开局规则另明确要求：未选择时条件式解释，确认后只叙述批准的开局结果，不输出未经适配的当前生命值、经验或等级面板。页面概况继续将开局Lv标为不随经验更新的记录。

用户声明的模型能力仍为1,000,000上下文、64,000最大输出。本轮发现原2,048请求输出不足以容纳供应商思考与可见回复，将实际请求上限调整为4,096；能力上限不等于实际请求用量。没有新增额外的理解模型调用，也没有隐藏生成结果中的数值以通过验收。历史消息和旧档不自动重写。

这说明仅修改提示顺序不能解决输入中强制面板模板的冲突。随后增加范围受限的作者提示投影，离线检查六份实际供应商请求，确认旧面板和优先级冲突已移除，人物与场景保留；没有付费调用。首次投影测试因未覆盖原始宏而失败，补齐原始宏、展开后人物名及不同玩家名后通过。

第四批进一步暴露了协议用词歧义：`execute`是可用行动的待确认标识，并非让模型立即执行；“等我确认”不应将已明确选择降为描述等待的`explore`。补清协议并增加仅使用当前可用ID的候选示例，仍要求原输入逐字证据，候选正文仍由服务端替换为核对提示。没有强制把任意自由文本转换成模式选择，也没有放宽引用、版本或确认校验。
