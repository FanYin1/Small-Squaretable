# 工作包 3：单轮输出可靠性

日期：2026-11-05。依据：用户在工作包 2 交付后指示“继续下一个包”。对应 DEC-30/31/32/34、INV-02/04/05/08；前置记录见[工作包 2](prompt-trace-work-package-20261105.md)。

## 固定范围与已实现行为

本包收口单次生成的接收、控制块解析、状态提交和前端收尾。沿用一次模型调用、正文流式预览、服务端校验与事务确认；不新增行动审批，不自动重试，不新增模型修复调用。未引入双模型或正文/控制两次生成。

对照本仓库实际链路发现：仅有 `finish_reason`、没有 `[DONE]` 或 HTTP EOF 时仍等待读流；通用情绪处理仍处于版本化故事的前台生成锁内；DONE 后等待终态期间，前端退回输入中提示；JSON.parse 对重复字段采用最后值。以下修正围绕这些缺口，不扩大到工作包 4。

### 结束、取消与错误边界

- 明确 finish 帧之后最多继续等 1000ms，用于接收独立 usage 帧；这是**模型已经声明结束后的收尾等待**，不是模型生成超时、正文长度限制或输出 token 上限。
- `[DONE]` / 原生 `done` 仍立即释放；没有 EOF 的兼容网关不再无限等待。usage 迟于该窗口可能无法取得，沿用已有用量估算，不伪造 provider usage。
- 收尾 deadline 从首次 finish 开始计算，后续 usage/心跳不能延长。窗口结束时存在未完成事件则记为传输不完整；结束后新正文、冲突结束原因、错误 choice index、坏帧仍拒绝确认。坏帧后不继续无限等待连接关闭。
- 用户取消可打断挂起的 reader.read，即使源不再返回数据也进入片段保存/结算路径。timer 与 AbortSignal 监听清理，读取器取消并释放锁。
- `stop` 是成功候选；`length` 保持截断；`content_filter`、`tool_calls`、未知结束原因不能把可见片段认定成完整剧情。
- `commitStoryTurn` 自身也校验提供的结束原因；调用方漏传 interrupted 时，已知非 stop 结果仍不提交资产/规则/事实/推荐变化。没有提供 generation 元数据的原有内部调用保持兼容。

### 控制块格式规范化与歧义拒绝

新增加的唯一规范化类型：在**完整控制标签和完整 JSON 结构**内，移除字符串外、非空对象/数组最后一项后的尾逗号。规范化必须让整段 JSON.parse 成功，之后继续完整 schema、证据归属、行动 ID、规则条件及事务版本校验。

- 字符串中的逗号、引号、反斜杠和证据内容不改动；不添加字段/值/引号/括号，不猜测缺失标签，不提取嵌套对象替代根对象。
- 同一块不组合尾逗号规范化与原有“一个多余结尾符号”处理；连续逗号、缺分隔符、多对象、注释、错位括号和未闭合字符串仍失败。
- 此项明确扩展过去“所有尾逗号都拒绝”的表现格式边界，依据 DEC-32 的表现格式规范化授权；旧行为记录保留。新诊断 warning 为 `trailing_commas_removed`，不会静默把模型行为变为无行动表达。
- 对所有嵌套对象检查**解码后的重复属性名**，包括 Unicode 转义后重名和相同值重复；不同对象中的同名字段合法。重复字段返回 `invalid_json / duplicate_key`，不采用 JSON.parse 的最后值，不输出原始字段名或内容到诊断。
- 系统协议继续要求模型生成标准 JSON，并明确禁止重复属性名。模型生成要求不因运行时兼容而放松。
- 畸形/未完成 `<story-intent` 开头从流式及最终可见正文中隐藏，仍判协议失败；若先出现畸形块、后出现合法块，不跳过前者采用后者。
- 保留原有 16000 字符控制块上限、可选推荐/引导的独立容错；本包不新增整体输出硬限制。

### 保存回执与附加工作

- 助手消息事务保存、结算后即发送权威 DONE，先于未读数与附加处理。正文/推荐只使用数据库返回的结果，失败预览不能冒充已确认内容。
- 未读数更新失败只记录固定类别告警，不把已保存剧情报成生成失败。计费仍等待且按原账本策略执行，未转入易丢失的后台任务；输入用量计量也放入结算保护范围。
- 版本化故事的**通用情绪计算**移入有界进程内队列：最多 4 个不同故事并行、32 个任务，同故事串行。队列满或失败记录固定类别告警，不阻塞生成结束；进程退出可能丢失这类可选任务，不声称持久化或保证完成。
- 版本化故事提示词原本就不读取通用情绪（`isolateKnowledge`）；本次不改变该策略。真实故事记忆仍由已确认 story_events 的数据库触发器/记忆工作队列处理，未迁入此进程队列。未确认轮次不新增通用情绪/成长处理。
- 旧式非快照聊天的记忆提取、情绪更新顺序保留。群聊功能继续暂停；共享流读取器的保护适用于原有调用方，不新增群聊机制。

### 前端收尾

收到已保存的 DONE 后，如 `generation_finished` 尚未到达，显示“回复已接收 · 正在结束本轮”，不退回“角色正在输入”。输入与模型切换继续等待服务端终态解锁，避免前台提前发送撞上生成锁。

同一单人 requestId 的 DONE 后迟到片段不再重新打开流式显示；新 requestId、旧式无正文 DONE 协议及原有群聊角色接续保持兼容。停止、失败、切换会话和终态事件按原恢复流程清理临时状态。
