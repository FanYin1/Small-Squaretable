## 已修改的行为

| 场景 | 本轮行为 | 证据范围 |
|---|---|---|
| 单聊或群聊生成中停止，已有部分正文 | 保留片段和中断标记；不从该片段执行ERA插入/编辑/删除，不据其更新人物成长、情绪或立即抽取记忆；已接收的用户输入仍可用于原有情绪处理 | 服务端路由回归，保留已产生费用的结算检查 |
| 有内容快照的新故事，正文携带ERA指令 | 不向旧变量存储写入；原生资源继续由故事状态协议确认 | 原生/版本化故事与旧故事的对照回归；未删除原始卡扩展 |
| 旧故事正常完成 | 保留原有ERA变量支持 | 单聊与群聊插入/编辑/删除回归 |
| 后续批次再次读取中断片段 | 记忆抽取入口过滤带中断标记的消息；只剩中断片段时不调用抽取模型 | 独立记忆服务回归，覆盖延后抽取 |
| 旧版本、失效行动或不满足前提 | 校验失败不接受请求、不预扣，不提供携带原版本的直接重试；前端保留未确认草稿，移除尚未被接收的临时消息，提示查看状态并重新确认 | 服务端拒绝检查、客户端消息/草稿确认回归、状态刷新组合函数检查 |
| 生成已接收，提交阶段才遇到冲突 | 保留已接收的用户消息，不误删历史；不提供不安全重试 | 客户端回归；不代表提交回包丢失全链路验收完成 |
| 正文已提交后才收到停止 | 使用保存时确定的中断状态，不把已确认结果重新解释为未完成 | 提交边界的路由回归 |
| 群聊保存后派生记忆失败 | 记录失败，已保存结果仍有效，继续处理后续人物 | 路由故障注入；没有实现持久重试 |

行动冲突后，通过既有请求结束通知触发状态刷新。用户核对后重新选择或调整行动，以新请求提交；不会自动把旧行动改成新的付费请求。本轮不改变OPEN-02的推荐默认方式，也不引入OPEN-01的回退/改写机制。
