# AD-3：规则文本线索与来源定位

本包承接 DEC-18/27、EXP-ADAPT AD-3/5 的输入检查。它解决第三方卡只得到“未找到平台规则声明”、无法看清待核对机制的问题。**这是确定性语法线索扫描，不是完整依赖解析、agent语义理解或规则转换，更不会自动维护数值。**

## 用户可见行为

个人卡详情执行已有的“检查这张卡”，完成后可展开“规则线索与依赖核对”。默认折叠，不让技术信息占据剧情入口；手机与桌面共用同一组折叠卡片。

按五类展示命中次数、核对要求及最多三份不同来源定位：

| 线索 | 为什么不能仅凭命中启用 |
|---|---|
| 带数字的消耗、增减、赋值 | 还缺资产归属、条件和完整效果，不能只取扣款 |
| 随机、概率、掷骰 | 需要范围、分布和修正项，不能私自换成固定值 |
| 每日、每月、每轮等 | 需要时钟、触发点、重置及重复结算规则 |
| 条件、阈值、重置等 | 需要确认与其他状态之间的依赖 |
| 外部变量标记或更新命令 | 识别不等于获得执行权限，也不等于结果可信 |

来源显示角色字段、开场编号、绑定书UUID前缀/条目序号或扩展键，以及行号、字符范围和原文SHA256前缀。绑定书可打开原资料，再按条目序号核对；并非编辑器精确行跳转。API不返回命中原句、作者秘密或整本书。

## 范围与限制

- 检查当前单卡的description/personality/scenario/mes_example/system_prompt/post_history_instructions、promptTemplate、默认/备用开场，以及明确绑定且启用的世界书条目。
- 指定扩展regex_scripts/scripts/tavern_helper/TavernHelper_scripts/depth_prompt作为JSON序列化的**静态文本**检查，包括其中停用脚本。它们的出现或命中不表示启用/执行。其他未知扩展不在扫描范围。
- 不扫原始归档副本、旧data包装、creator_notes、未绑定书、全局书或停用书条目；没有将未扫描部分当作已核验。
- 上限2,000份非空文本、2,000,000个UTF-16代码单元。超过任一上限时不展示局部线索结论，明确范围超限。每类统计当前定义范围内全部命中，但只保留前三份不同来源的首个位置。
- 行号从1起；内部start/end是JavaScript UTF-16的左闭右开偏移，页面显示为1起的区间。扩展定位针对JSON序列化文本，不是原PNG文件的字节偏移。
- 否定句、例子、脚本字符串、叙述都可能命中。次数不是“规则数量”“完成率”或完整依赖图；未命中也不等于没有机制或已兼容。

## 数据与权限

复用原作者/租户限定的GET adaptations接口，只为最新、ready且资料修订仍匹配的记录即时附加inspection。整个查询处于同一只读repeatable-read事务。

inspection包含扫描器版本1、当前sourceRevision、范围覆盖及来源摘要。它不进入数据库artifact、不进入故事快照或运行规则；不修改旧检查结论。源卡或绑定资料变化后不再显示旧线索；读取失败或重新检查期间隐藏旧线索，不能把无法复核的结果继续当作当前。

无新数据库迁移、无模型调用、无自动重跑历史任务、无点数变动。公开访问或非作者无法通过该接口读取线索。源码规则编译、状态提交与分支回放行为未改变。

## 固定验证

- 单元：五类匹配、精确摘要/偏移、停用/全局/其他卡排除、原始索引保留、归档不重复扫描、范围超限、例子数量限制、UTF-16与CRLF、输入不变及无规则产物。
- 界面：默认折叠、来源定位/链接、旧修订/不匹配结果隐藏、读取失败隐藏旧线索；不得出现“分析通过所以可运行”。
- 隔离集成：四个原始PNG真实导入并检查；API分类与桌面/手机展示，原卡与数据库artifact不变；仍明确unsupported、没有新增可运行行动。
- 实际候选：单独合成私有卡执行检查、展示、重启，再删除清理并比对既有业务表；不能将这项合成测试说成真实卡玩法验收。

## 后续原要求

AD-3还需要把有来源的完整条件/效果转换成受支持的可执行结构，并在事务、重复请求、失败、刷新和分支中验证。线索扫描只提供定位依据，不能自动裁决作者冲突、推导隐藏规则或替代上述要求。AD-5仍需要逐卡真实玩法与质量验证，父项不关闭。
