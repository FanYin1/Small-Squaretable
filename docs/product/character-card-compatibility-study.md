## 2. 兼容的定义

必须逐层报告，禁止用“能上传”代替“完整可玩”：

1. 文件解析：读出原始数据，区分人物、世界书、预设、插件和普通图片。
2. 内容保留：人物、开场、示例对话、世界书、未知扩展可追溯，不静默丢字段。
3. 行为语义：世界书触发、宏、正则位置和执行时机符合已声明的支持范围。
4. 状态连续：变量变化可验证、持久化，并按用户/存档/分支隔离。
5. 界面交互：面板、选项、地图与状态一致；不只是显示一段 HTML。
6. 游玩验证：进入、行动、刷新、重启、纠正和长程恢复通过。

第三方脚本 API 不存在时必须返回明确的不支持结果，不应通过空数组或空成功响应制造假兼容。文件中包含设定，不代表模型每轮都能正确执行它。

## 3. 源码核对发现

### 3.1 有可复用基础

- `src/client/utils/sillytavern.ts` 已有 V2/V3 结构识别、标准化及扩展字段保留。
- `src/server/routes/characters.ts` 的单卡创建流程可从内嵌世界书建立数据库记录。
- `src/server/routes/worldbooks.ts` 有独立世界书与条目导入路径。
- `src/server/services/worldinfo-engine.service.ts` 已有关键词、递归扫描、插入位置、概率等处理。
- 项目已有前后端正则处理、ERA 变量桥接和脚本运行组件。

以上是代码存在性检查，不表示行为与来源平台完全一致。

### 3.2 应先解决的缺口

| 问题 | 源码依据 | 影响 |
|---|---|---|
| 批量与单卡创建不走同一世界书关联步骤 | `characters.ts` 的 `/import/batch` 直接调用 `characterService.create`，未调用单卡路径的 `createCharacterWorldBook`；服务 create 仅创建角色记录 | 原始世界书可能保留在卡数据中，但没有生成相同的运行关联 |
| 图片解析分支不完整 | 批量 PNG 路径只识别 `chara`；对 `iTXt` 使用与普通文本相同的偏移 | 需要统一处理数据块、版本与异常，不能宣称任意 PNG/V3 完整支持；不代表本目录所有 V3 当前都会失败 |
| JSON 缺少先分类再导入的边界 | 批量 JSON 路径直接将对象当人物，使用 `parsed.data || parsed` | 世界书、预设或特殊旧卡可能被错误创建为角色 |
| 不同世界书入口字段映射不一致 | 内嵌与独立导入对 `extensions`、深度、概率等取值路径不同 | 同一条目通过不同入口可能改变行为；需逐字段及触发对照测试 |
| 世界书默认范围过宽 | 独立导入创建 `scope: global`；引擎合并用户启用的全局书和角色书 | 不应把素材库所有世界书同时导入并启用，可能造成不同世界串设定 |
| 脚本扩展覆盖不完整 | `ChatWindow.vue` 只读取 `tavern_helper` 的特定元组结构；素材还有 `TavernHelper_scripts` 等字段 | 扩展名称和结构都需要识别，不能只做一个字段别名就宣称完成 |
| 部分 API 只是占位 | `sillytavern-shim.ts` 中世界书相关 API 返回空数组/空成功；`EraScriptRunner.vue` 的聊天消息接口返回空数组 | 依赖这些接口的脚本可能不报错但无法完成工作 |
| 桥接更新不等于完整存档 | `era-bridge.ts` 的 merge/delete 修改内存并广播，函数本身没有服务端写入 | 不能依据状态栏变化认定该路径已持久保存；须检查整个写入链路 |
| 第三方脚本隔离边界需先处理 | `EraScriptRunner.vue` 使用 `srcdoc` 与 `allow-scripts allow-same-origin` | 不应将来源角色卡脚本视为可信代码；在大规模运行测试前修正隔离及可调用能力边界。此次未执行利用测试 |

特别注意：世界书存储字段不等于引擎真正执行所有语义。需要对深度、角色、预算、递归、概率、冷却、黏着、分组、正则关键词等分别标注“保留 / 执行 / 已验证”。

## 4. 建议架构

原始文件 → 分类与依赖扫描 → 可追溯的统一内容结构 → 兼容适配 → 存档状态与事件 → 原生界面。

### 4.1 原始内容与转换结果分开

保留原始文件或原始数据、内容哈希、来源相对路径、作者和版本字段。标准化结果单独保存并记录转换器版本。未知扩展原样保留，不自动执行；遇到冲突保留诊断，不猜测作者意图。

同名文件不等于同一卡，相同角色的新版本不等于重复垃圾。已有存档固定卡、世界书和适配器版本；更新内容不应静默改变正在进行的剧情。

### 4.2 世界书按体验绑定

解析卡内嵌书、命名引用、独立书和可选补充书之间的关系。引用同一内嵌书时去除重复绑定；找不到或同名多份时明确提示，不任取一份。

每个存档保存启用的书及版本。世界设定、表达风格和玩法规则分别组织。禁止把所有已导入世界书默认注入所有卡。

关键词触发语义先忠实实现；额外语义检索作为明确可配置能力，不能悄悄取代原规则。作者设定也不能覆盖平台鉴权、工具权限与真实计费。

### 4.3 状态与记忆分开

世界书定义规则；存档记录规则作用之后的当前事实。统一状态接口保存类型、路径、来源事件、可见范围和版本。

不同卡可以保留自己的字段，例如金币、信用点、灵石、船体完整度、门派声望。平台不强行把它们改成同一种经济或关系系统，而是提供数值、物品、人物、目标、地点和节点地图等通用组件。

原生字段直接映射；已知变量协议通过版本化适配器转换。仅以正文描述数值的旧卡，可以生成待确认映射，但未经验证不得把推断数值当作权威存档。无法解释的字段保留原文或只读数据，不虚构可操作面板。

所有适配器通过同一服务端状态提交入口：校验路径、类型、权限、事件 ID 和预期版本。模型或旧脚本提出变化，不能直接改平台账户和计费数据。刷新恢复、重复提交、回退和分支都必须在此基础上实现。

### 4.4 原生界面与作者自定义内容

首选原生组件，保持统一的导航、输入、推荐行动、状态面板和存档操作；允许主题、封面和情境表达变化。

任意 HTML/JavaScript 不能自动转换成地图或可靠的状态系统。必须保留的自定义面板需要独立隔离环境和有限接口；暂不支持的交互应明确停用或提示。若影响核心玩法，不可仅标成“外观差异”后加入快速开始。

### 4.5 保护作者玩法与产品探索体验

不是所有旧卡都适合自动添加任务和地图。产品的推荐行动可基于当前情境提供，但不能改写作者的身份限制、世界规则或关键分支。原卡已有操作菜单时先识别和适配，避免重复出现两套推进机制。

第一版的实例卡使用同一套正式能力，并经过完整验证；庞大素材库用于兼容性回归，不直接变成未经审核的首页推荐库。

## 5. 用户看到什么

导入完成前给出可理解的结果：

- 可开始：设定和必要依赖已就绪，并说明验证范围。
- 可进行基础对话：部分辅助面板未适配，列出具体影响。
- 需要补充或适配：缺世界书或核心玩法依赖，提供处理入口。
- 未识别：保留文件，不创建空白角色冒充导入成功。

“已完成解析”和“已经验证可玩”在内部状态和对外文案中分开。玩家默认看到简短说明；作者可展开字段映射、世界书触发记录和不支持 API 清单。

## 6. 实施与验收顺序

1. 统一文件分类、单卡/批量解析与原始数据保留；先修复静默失败和脚本隔离问题。
2. 用本目录建立静态回归样本，覆盖旧式/V2/V3、不同元数据块、嵌入/独立世界书、重复版本、伪装扩展名和畸形输入。全量分类不等于全量模型实测。
3. 统一世界书绑定、版本冻结和触发语义；提供可检查的注入结果与原因。
4. 建立服务端状态与事件记录，先完成声明式字段和有限的已知变量适配，再逐步扩大框架支持。
5. 接入通用面板、开局选择与探索式推荐行动；选择少量不同题材的实例做完整体验。
6. 验证多轮推进、刷新与重启、同卡多存档、纠正/回退、重复事件和原文/状态/记忆一致性。

每种适配器独立记录测试版本、支持字段、缺失能力与验证结果。不承诺所有历史脚本在未知环境下完全等价运行，也不以目录名称“7500+”作为兼容率分母。

调研时点仅完成方案整理；后续已完成的有限实现见本文补充记录。R5 本机服务未因这些隔离验证升级，剩余兼容改造仍由EXP-03B跟踪。
