## 03C R2：没有平台声明时的产品行为

| 场景 | 可验证行为 | 验证层 |
|---|---|---|
| 正文规定玩家职业、关系或共同经历，没有固定称呼协议 | 原字段被保留并随故事冻结；用户看到未自动核对的边界，不能显示身份验证通过 | 导入、详情/开局、持久快照 |
| 所选人设简介与作者正文可能冲突 | 实际发送上下文包含应保留的作者设定和所选人设；不静默删掉一方；记录当前优先级和冲突处置缺口 | 生产上下文装配及受控请求捕获 |
| 书含常识/背景/风格/规则，但无用途声明 | 显示用途未知，不强制重新选世界；绑定及关键词/常驻语义不因诊断改变 | 页面、触发与实际请求 |
| 未绑定的同名资料或另一角色私有书 | 不因名称或用途猜测而注入；诊断不泄露隐藏正文 | API权限、请求捕获 |
| 开始后修改源卡、书或人设并重启 | 旧档保持原快照，新故事读取新版本；详情当前诊断与旧档历史诊断分别有依据 | 数据库、API重启、浏览器恢复 |

仅检查字符串同时存在不等于身份冲突已解决。发现默认人设实际覆盖作者固定背景等问题时，先复现并记录具体冲突，沿既有身份约束修复；若必须新增改编/固定身份选择交互，标明与已确认行为的差异，不自行代签。没有字段定义的旧卡不承诺自动推断所有可改项，也不强制新增全套语义识别系统。

实施入口：`src/server/services/chat.service.ts`、`chat-creation.service.ts`、`story-content.service.ts`、`story-worldbooks.service.ts`、诊断组件及现有集成工具。受控检查证明资料传递和保存；真实人物回应遵循设定属于另一层证据，不能混写。

## 验证与03C关闭条件

1. 对照R1/R2逐项标记已有证据、缺检查、缺实现或需产品决定；不以新测试总数计算完成率。

3. 代码变更完成后运行类型、构建及针对性lint；涉及持久化、快照或权限的变更必须有对应行为检查。
4. 有新候选变更时复用已验证的备份/迁移演练/升级流程，再检查实际3081入口、旧新故事和受影响页面。仅覆盖核对而无代码变化时不为制造交付次数重复部署。
5. 关闭时按原任务分别说明代表性、用途、缺依赖和身份边界；每个通过结论有对应证据，每个未支持结论有原范围依据和用户可见降级。仍有原范围缺陷则保持开放，不能更改分母使其完成。

最终交付必须含“本次开发后的实际效果”：用户做什么、看到什么、部署版本、复现入口、真实/受控模型边界及仍未实现行为。人工签收、真机和完整产品验收继续独立标记。
