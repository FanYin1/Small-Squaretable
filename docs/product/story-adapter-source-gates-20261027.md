# AD-3：规则来源触发条件与旧回执防绕过

对应DEC-18/19/27、INV-02/07/09。该修复属于适配规则的正确性，不是新一种第三方规则转换，也不替代AD-3原有的条件、赋值、一次性奖励、交易样本与AD-5真实玩法要求。

## 已定位缺陷

旧有限编译器提取启用条目中的`squaretable-rules-v1`后直接编译，未验证该条目的关键词、概率、时序与人物过滤条件。因此一个只有50%概率启用的来源，其数值与行动可能被当作常驻规则；来源内容摘要本身不能防止这一错误。

新增10个反例在修复前全部失败，旧编译器返回supported，属于可重复定位的适配缺陷，与之前偶发加载问题无关。

## 固定边界

| 编号 | 要求 |
| --- | --- |
| SG-01 | 显式声明所在条目必须明确constant=true；概率为100（缺省100），delay/cooldown/sticky为0（缺省0） |
| SG-02 | 人物过滤为空或明确包含当前单角色；不兼容或类型不正确时返回review/conditional-source，无规则与行动 |
| SG-03 | 同修订的旧supported回执在新故事采用前按现行编译器复验，不能仅凭旧supported状态绕过；只读检查不改写原回执 |
| SG-04 | 作者检查页不把过期supported结果继续显示为可运行；说明需重新检查、已有故事保留冻结规则，不劝作者删掉限制过检 |
| SG-05 | 已有故事按冻结规则续玩；重启后继续、重复回执不重复结算；修复来源后的新检查与新故事可正常采用 |

常驻条目的关键词本就不参与激活限制，不因保留keys/secondary keys误拒绝。人物过滤包含当前角色时仍可使用。没有实现概率采样、延迟、冷却或关键词状态机，不将这些条件静默丢弃，也不擅自把50%变成100%。

仅检查声明所在条目的可转换性；其他来源的复杂自然语言依赖仍不能据此认定已解决。原生作者规则保持原入口，已审查咔咔精确指纹机制保持原冻结语义。无全库扫描、原件改写、旧存档回填、批量重检查或付费模型调用。

## 回执与存档

读取作者的ready记录和新开局采用supported回执时重编译比较。结果不再一致则current=false且不附加到新开局，作者必须显式重新检查。资料本身没改、只是检查要求收紧时，同样给出准确提示，不伪造“原卡已修改”。尚未支持的回执不因复验自动变成supported。

旧存档继续只读冻结产物，不用当前卡片重新编译，不重新计算或删除已有数值；读取并验证旧结构仍兼容。新增conditional-source原因会进入新检查回执与可能的新故事资料，旧镜像不能保证认识它；回退需要兼容读取版本或应用/数据配套恢复，不能仅因没有SQL迁移就假定可任意降级。
